# ABOP мини-бенч моделей — APE как гейт под одну 32ГБ карту

**Зачем:** выбрать MoE-движок для локального рантайма ABOP (одна карта 32 ГБ), не доверяя чужим
лидербордам, а проверив кандидатов на том, что реально делает движок под governance. Проверка идёт
**до аренды бокса** — арендуем уже под победителя, чтобы оживить фронт.

**Принцип:** APE = гейт. Грейдеры совпадают с боевыми гейтами `cli/ape.py` (`_json_first`, cite/анти-галлюцинация,
структура DoD). Портируемо: любой OpenAI-совместимый `/chat/completions` (наш MCP-шлюз, RouteAI, OpenRouter,
локальный vLLM) — один код-путь.

---

## Шортлист кандидатов (32 ГБ, MoE)

Задача движка — оркестрация под governance (route/judge/DoD/synthesis) + русский + строгий tool/JSON.
Приоритет — instruction-following + tool-calling + reasoning, не creative writing.

| # | Модель | Total/Active | Вес Int4/MXFP4 | Роль-гипотеза | Почему |
|---|---|---|---|---|---|
| **A** ⭐ | Qwen3-30B-A3B-Instruct-2507 | 30B/3B | ~16–17 ГБ | оркестратор + специалисты | сильнейший мультиязычный (RU), tool/JSON, active 3B дёшев на волнах |
| **A′** | Qwen3-30B-A3B-Thinking-2507 | 30B/3B | ~16–17 ГБ | судья/план (DoD) | reasoning-режим для аудита/плана, тот же вес |
| **B** | GPT-OSS-20B | ~21B/~3.6B | ~13 ГБ | контраст-эффективность | Apache-2.0, быстрый, огромный запас KV; RU слабее — бенч рассудит |
| **C** | Moonlight-16B-A3B *(или DeepSeek-V2-Lite)* | 16B/~2.4B | ~9–10 ГБ | дешёвый роутинг/floor | тонкий, высокий concurrency; держит ли гейт малый MoE |

Вотчлист: Qwen3-Coder-30B-A3B (если код/структура доминируют), Ling-lite-1.5, Phi-3.5-MoE (~24ГБ Int4, впритык).

**VRAM 32 ГБ:** A ~17ГБ вес → ~13ГБ KV/prefix (контекст 16–32k, APC вкл); B ~13ГБ вес → щедрый KV; C ~9ГБ → очень щедрый.

> Точные цифры лидербордов (2507, GPT-OSS) перепроверить — знания до янв-2026. Гейт ниже доверяет поведению под APE, а не чужим числам.

## Что меряем (5 измерений, APE-гейты)

| Измерение | Что проверяет | Грейдер | Гейт |
|---|---|---|---|
| **json_tool** | строгий ReAct: `{"tool":...,"args":{...}}` / `{"final":...}` + верный инструмент | `_json_first` + ключи/tool | ≥ 90% |
| **cite** | анти-галлюцинация: цитата при наличии, `«Недостаточно данных»` при отсутствии, **без выдумки** | наличие цитаты / fallback + отсутствие ловушки | **≥ 90% (HARD)** |
| **route** | выбор семьи-исполнителя одним словом | точное совпадение метки | ≥ 75% |
| **dod** | вывод Definition of Done (JSON) + корректный вердикт | структура + вердикт | ≥ 70% |
| **ru** | следование инструкции на русском (формат/краткость/отказ) | contains/format | ≥ 70% |

**Гейт прохождения:** ВСЕ измерения ≥ порога И `cite` (HARD-constraint из `CLAUDE.md`: любая выдумка числа/факта = провал).
Латентность (p50/p95), токены и оценка ₽ — информационно, для расчёта concurrency/окна KV на боксе.

## Запуск

```bash
pip install httpx
cd bench

# один кандидат (пример — OpenRouter)
python run_minibench.py minibench_ru.jsonl \
  --base-url https://openrouter.ai/api/v1 \
  --model qwen/qwen3-30b-a3b-instruct \
  --api-key "$OPENROUTER_KEY" \
  --price-in 12 --price-out 40 \
  --out report_qwen.json

# через наш MCP-шлюз (OpenAI-совместимый) — модель по имени в каскаде
python run_minibench.py minibench_ru.jsonl \
  --base-url "$GATEWAY_OPENAI_URL" --model local/qwen3-30b-a3b --api-key "$GATEWAY_KEY" \
  --out report_local.json

# локальный vLLM (после аренды бокса)
python run_minibench.py minibench_ru.jsonl \
  --base-url http://BOX:8000/v1 --model Qwen3-30B-A3B-Instruct-2507 --out report_box.json
```

Прогнать по каждому кандидату → сравнить `report_*.json` (поле `passed_gate`, `per_dim`, `latency`).
Exit-code 0 = гейт пройден.

**Температура фикс. 0.1** (CLAUDE.md, не повышать). Датасет — `minibench_ru.jsonl` (20 кейсов, RU), расширяется дозаписью строк.

## Как читать вывод

- `per_dim` — % прохождения по измерению.
- `gate` — сверка с порогом; `cite` провал = модель отклоняется независимо от остального.
- `latency.p95` + `tokens` — вход для VRAM/concurrency-бюджета на 32 ГБ.
- `est_cost_rub` — если заданы `--price-in/--price-out` (для сравнения дешёвого прогона до бокса).

## Порядок этапов

1. **Сейчас:** прогнать шортлист A/B/C через доступный endpoint (OpenRouter/наш шлюз) → выбрать проходящего с лучшими латентностью/RU.
2. **Далее:** арендовать дешёвый бокс (32 ГБ), поднять vLLM с победителем (Int4/MXFP4, APC вкл), перепрогнать бенч на боксе (латентность реальная).
3. **Затем:** подключить инфру (`_mcp_call`→локальный `infer()`), направить фронт-прототип на живой endpoint — оживить Канву/Пульт.
