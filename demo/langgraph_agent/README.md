# Чужой агент внутри процесса: LangGraph + ABOP по MCP

Рабочая демонстрация ADR-028/048/049: агент, которого ABOP **не создавал и не исполняет**,
получает место в карте процессов, читает данные под правами своего пользователя и отчитывается
о работе на участке.

Граф исполняет LangGraph. ABOP о нём ничего не знает — связь только по MCP, тем же Bearer-токеном,
что и у человека.

## Что агент делает

«Досье подрядчика»: читает `contractor_report` из Data Plane, считает по каждому подрядчику число
пунктов, просрочки и перерасход часов, ранжирует по риску. **Все числа считает код** агента;
модель в этом графе не участвует вовсе — выдумывать нечего.

```
карта ──▶ данные ──▶ досье ──▶ отчёт
  │         │          │         └── report_run: «со слов агента»
  │         │          └── считает код, не модель
  │         └── data_query под правами пользователя
  └── process_coverage: агент видит своё место в процессе, а не задачу в вакууме
```

## Запуск

```bash
pip install langgraph mcp httpx

TOKEN=$(curl -s -X POST http://<abop>/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"<логин>","password":"<пароль>"}' | python -c 'import json,sys;print(json.load(sys.stdin)["access_token"])')

# 1. заявиться в реестр ABOP (конверт при этом ОБЪЯВЛЕН, а не проверен)
python demo/langgraph_agent/agent.py --base http://<abop> --token "$TOKEN" --register

# 2. посадить агента на операцию — обычной редакцией карты, из интерфейса или по API;
#    это решение организации, а не самого агента

# 3. прогон с отчётом по своему участку
python demo/langgraph_agent/agent.py --base http://<abop> --token "$TOKEN" \
  --audit-id ext-langgraph --report o112
```

## Две честности, которые здесь видно

**Конверт объявлен, а не проверен.** Границы своего агента ABOP выводит осмотром его графа. У
чужого графа нет — его исполняет LangGraph. Поэтому `verification.ok = null`, вид `external`, и
под «проверено» такой агент не попадает ни при каких условиях.

**Прогон — это отчёт.** ABOP не видел работы: агент сам о ней сообщил. Такое подтверждение везде
помечено «со слов агента» и считается ОТДЕЛЬНО от собственного журнала прогонов — для этого в
сводке и стоит `confirmed_reported_only`.

Отчитаться агент может **только** по операциям, на которые его посадили: иначе покрытие любого
участка накручивалось бы одним запросом.

## Что эта демонстрация попутно нашла

Два дефекта, оба про одно и то же — молчаливую подмену «данных нет» вместо «что-то пошло не так»:

1. инструменты карты в MCP звали имена, уехавшие при расщеплении монолита, и падали с
   `module 'server.web_api' has no attribute 'process_coverage'`;
2. `data_query` резал JSON по символам на 4000 знаках — ответ обрывался посреди записи, агент не
   мог его разобрать и показывал «записей нет», хотя записей было 24.

Оба закрыты тестами (`tests/test_mcp_tools_call.py`, `tests/test_tool_output_cap.py`). Второй — и
есть причина, по которой агент в шаге «данные» просит только нужные поля: сужать выборку —
работа агента, а не среды.
