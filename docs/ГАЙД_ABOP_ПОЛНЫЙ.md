# ABOP — полный гайд по всем функциям

Справочник по всем экранам и функциям платформы: что делает, как настраивать, что настроить **на стороне сервисов-источников** (1С/Redmine/BookStack/Twenty/MinIO/почта).

Связанные документы: `КАК_СОБРАТЬ_АГЕНТА.md` (быстрый старт для новичка), `ABOP_ADR.md` (архитектурные решения, особенно ADR-032 про Data Plane).

---

## 0. Что такое ABOP (в двух абзацах)

ABOP — среда сборки, запуска и эксплуатации ИИ-агентов в **управляемом периметре безопасности**. Агент = роль семьи + навыки, работает на **реальных данных** через Data Plane и под **конвертом** (что можно/нельзя, автономия ≤ контракт LUDA).

Ключевая цепочка (ADR-032): **Коннектор → Рецепт → Сущность (canonical) → Навык (data-need) → Агент (роль+навыки) → Узел процесса → Конверт**.

---

## 1. Запуск платформы (dev)

```bash
# из корня репозитория
uvicorn server.web_api:app --host 127.0.0.1 --port 8091
# → http://127.0.0.1:8091
```

`.env` (ключевое):
- `ROUTEAI_API_KEY` — ключ RouteAI (LLM-движок). Без него прогон агента не выполнит LLM-анализ.
- `POSTGRES_DSN` — пусто = хранилище в памяти (dev). Заполнить для persist.
- `KEYCLOAK_*` — пусто = dev-режим (без токена). Заполнить для прод-авторизации.
- `ABOP_RUN_LLM_CONCURRENCY` — сколько навыков анализируются одновременно (дефолт 2, под единую RouteAI-карту).
- `ABOP_RUN_LLM_TRUNCATE` — 1 (dev, режет промпты для скорости), **на проде 0** (полные промпты).

> После правок фронта — **Ctrl+F5** в браузере (бандл кешируется).

## 3. Данные (Data Plane)

Три вкладки: **Коннекторы**, **Рецепты**, **Карта**.

### 3.1. Коннекторы — «розетки» к источникам

Коннектор = именованное подключение к системе-источнику.

**Как настроить:**
1. Данные → Коннекторы → **＋ подключить**.
2. **Адаптер** (тип источника): CSV, Excel (xlsx), JSON-файл, Текст (txt/md), PDF, REST API (http), SQLite, PostgreSQL, Векторная БД (Qdrant/knowledge), Вычислимое (derive).
3. **Путь / URL** — файл или адрес API.
4. **Токен авторизации** (для REST/API) — заголовок. Форматы:
   - `Token id:secret` или `Bearer eyJ...` → уходит в заголовок `Authorization`;
   - `X-Redmine-API-Key: ключ` → уходит как свой заголовок `Name: value`.
5. **root** — ключ массива в ответе (если API отдаёт `{data:[...]}` → `data`; Twenty → `data.opportunities`).
6. **Тест-прогон** — читает несколько строк с **этим токеном** и показывает реальные поля (или честную ошибку 401, если токен неверный).

> Бейдж на плитке — «не проверен», пока не нажмёшь тест (не врёт «ок» без проверки).

### 3.2. Рецепты — «источник → чистая сущность»

Рецепт превращает сырой источник в типизированную каноническую сущность.

**Как настроить:**
1. Данные → Рецепты → **＋ рецепт** (или открой существующий — форма подгрузит все поля, токен и root).
2. **Источник (адаптер)** + путь/URL (+ токен/root, если API).
3. **🔎 Показать поля источника** — покажет реальные колонки; **клик по колонке добавит строку в map**.
4. **map** — «поле → спека», редактируется inline: `col:колонка · cast:тип` (`money/decimal/int/lower/upper/date`), `lookup:сущность.поле`, `const:значение`.
5. **rules** — редактируются inline: `assert поле > 0` (фильтр), `pii_mask(поле)` (маска ПДн).
6. **emit** — сущность (`transaction/customer/document/issue/email/meeting`) + ttl.
7. **Проверить** — dry-run: покажет канонические записи + счётчики (записано/отброшено/невалидно), ничего не сохраняя.
8. **Сохранить рецепт** → в canonical store (`/data query` для агентов).

> Рецепт делается **на сущность, не на навык** (общий склад). Много навыков читают одну сущность.
> JSON Schema-контракт: в `emit.json_schema` можно задать строгую схему записи — невалидные отсеются.

### 3.3. Карта — весь Data Plane целиком

Данные → **Карта**: по каждой сущности видно цепочку **рецепты (наполняют) → навыки (потребляют) → роли/агенты**, плюс список подключённых коннекторов. Инструмент понимания: «откуда данные и кто их берёт».

## 4. Навыки

Навыки → клик по навыку → **drawer**:
- **Тело**: Когда применять / Метод (по шагам) / Definition of Done / Анти-паттерны / Безопасность / Интеграция.
- **Конверт безопасности**: mode (read/write/action), egress (internal/external), cite (числа только из источника).
- **Источники данных (data-need)** — **редактируется**: селект сущности + поля (через запятую) + рядом резолвнутый рецепт. **＋ сущность** / удалить / **Сохранить источники**. Так оператор задаёт, какие сущности/поля берёт навык.

## 5. Агенты

### 5.1. Сборка на канве (Граф)
Граф → палитра слева → группа **«Роли (семьи)»** (реальные роли из 9 семей) → перетащи роль на холст → **узел-агент** (с правильными family/role). Клик по узлу-роли → **drawer агента**. Подключи источники и «Вывод», соедини стрелками.

### 5.2. Портфель (экран Агенты)
- Переключатель **В работе / Лимб**.
- Клик по карточке → **детали агента**: роль/семья/автономия, миссия, конверт, навыки, источники данных (data-scope), переходы `become`.
- Кнопки: **В Лимб** (архив, выведен из эксплуатации — обратимо), **Восстановить**, **Удалить** (насовсем).

### 5.3. Жизненный цикл (ADR-024)
`draft → tested → deployed(vN) → retired (Лимб)`. Лимб = архив выведенных, не удаление.

## 6. Запуск агента (прогон)

Запусти агента (кнопка на канве или через API `/api/runs`). Что происходит:
1. Governance-каркас: граф → волны, проверка автономии ≤ конверт, точки HITL.
2. **LLM-прогон**: каждый навык с data-need **читает реальные данные** из store (`data_query`) и прогоняет через RouteAI (агентский движок) → **находки** на доску.
3. Точки HITL — агент ждёт подтверждения человека (внешние действия — только dry-run + approve).
4. Агент-аудитор сверяет с Definition of Done.

**Настройки прогона (env):**
- `ABOP_RUN_LLM_CONCURRENCY=2` — батч одновременных LLM-вызовов (rate-limit к RouteAI). Поднять при своей карте с vLLM/paged-attention.
- `ABOP_RUN_LLM_TRUNCATE=0` на проде — полные промпты (1 = обрезка для dev-скорости).

> Анти-галлюцинация: агент опирается только на данные. Нет данных (напр. нет плана) → честно скажет «невозможно», не выдумает.

## 7. Настройка на стороне СЕРВИСОВ-источников

Чтобы ABOP брал данные, на самих сервисах нужно завести доступ. Реквизиты demo-стенда — сервер `5.129.192.63`.

### 7.1. MinIO (S3) — файлы, мок-данные 1С
- Консоль: `http://5.129.192.63:9001` (веб), S3 API: `:9000`.
- **Данные**: загрузить объекты в бакет (`mc cp file.json loc/bucket/key` или через консоль).
- **Публичный доступ** (чтобы ABOP-http-адаптер читал по URL без подписи): `mc anonymous set download loc/<bucket>`.
- В ABOP: коннектор **REST API**, URL = `http://5.129.192.63:9000/<bucket>/<key>.json`.

### 7.2. Redmine (аналог Jira) — задачи
- UI: `http://5.129.192.63:3000`.
- **Включить REST API**: Администрирование → Настройки → API → «Включить REST-веб-сервис».
- **API-ключ**: Моя учётная запись (`/my/account`) → справа «Ключ API» → показать/сгенерировать.
- В ABOP: коннектор REST API, URL `http://5.129.192.63:3000/issues.json?limit=50`, токен = `X-Redmine-API-Key: <ключ>`, root = `issues`. Сущность → `issue`.

### 7.3. BookStack (аналог Confluence) — документы/договоры
- UI: `http://5.129.192.63:6875`.
- **API-токен**: профиль пользователя → Edit Profile → **API Tokens** → Create Token → скопировать **Token ID** и **Token Secret**.
- В ABOP: URL `http://5.129.192.63:6875/api/pages`, токен = `Token <id>:<secret>` (уйдёт в `Authorization`), root = `data`. Сущность → `document`.

### 7.4. Twenty (CRM) — компании/сделки/контакты
- UI: `http://5.129.192.63:3002`.
- **API-ключ**: Settings → **APIs & Webhooks** (Developers) → Generate API key → скопировать JWT.
- В ABOP: URL `http://5.129.192.63:3002/rest/opportunities?limit=50` (или `/rest/people`, `/rest/companies`), токен = `Bearer <JWT>`, root = `data.opportunities` (или `data.people`). Сущность → `customer`.
- Особенности полей Twenty: суммы во вложенном `amount.amountMicros`, имя в `name.firstName`/`name.lastName`, почта в `emails.primaryEmail` — в map используй dotted-path (`col:amount.amountMicros`).

### 7.5. Mailpit (почта) — письма
- UI/API: `http://5.129.192.63:8025`, SMTP приём: `:1025` (без auth — тестовый).
- **Отправить письма** (наполнить): любой SMTP-клиент на `5.129.192.63:1025`.
- В ABOP: коннектор REST API, URL `http://5.129.192.63:8025/api/v1/messages?limit=50`, root = `messages`, без токена. Сущность → `email`. Поля вложенные: `From.Name`, `Subject`, `Snippet`.

### 7.6. NocoDB (no-code таблицы, «база 1С»)
- UI: `http://5.129.192.63:8090`. REST API таблиц (нужен токен из UI: Account → Tokens).
- В ABOP: REST API, root по структуре ответа NocoDB (`list`).

### 7.7. PostgreSQL (боевая БД)
- Коннектор **PostgreSQL**: DSN `postgresql://ro_user:pass@host:5432/db` (read-only-пользователь!) + SQL-запрос. Открывается в режиме read-only.

## 8. Загрузка из LUDA 2 (контракты)

Экран «Загрузка из LUDA 2» принимает бандл контрактов (CapabilityRequest + DeploymentContract + BaselineMeasurement + EvidencePack). Из контракта собирается `AgentVersion` с потолком автономии = `DeploymentContract` (ADR-013/029). Прод-развёртывание без валидного контракта запрещено (только песочница A0).

## 9. Безопасность (конверт)

- **Автономия** A0–A4 ≤ контракт LUDA. Превышение → блок запуска/деплоя (красный баннер).
- **HITL** — внешние действия (письмо/тикет/платёж) только через dry-run + подтверждение оператора.
- **egress** наружу — через контролируемый прокси (анти-SSRF); ПДн маскируются.
- **cite** — числа/факты только из источника.

## 10. Траблшутинг

| Симптом | Причина | Решение |
|---|---|---|
| «Error unpacking … Bad escaped character» | битый JSON-escape в бандле | не вставлять `\s\d\w` в код компонента; проверить `json.loads` template |
| Рецепт: «Сбой адаптера … HTTP 401» | нет/неверный токен | указать токен в коннекторе/рецепте (раздел 7) |
| Рецепт: «0 записей», данные есть | не указан `root` | указать ключ массива (`data`/`items`/`data.opportunities`) |
| Прогон висит/таймаут | много навыков × LLM | снизить `ABOP_RUN_LLM_CONCURRENCY` или дождаться; проверить RouteAI |
| Тест коннектора «ок», а внутри 401 | коннектор без токена | добавить токен в коннектор (тест теперь честный) |
| Пустой экран/кнопки не реагируют | кэш бандла | **Ctrl+F5** |
| Агент случайно выведен | он в Лимбе | Агенты → Лимб → Восстановить |

## 11. Шпаргалка потока

1. **Коннектор** (розетка + токен) → тест-прогон.
2. **Рецепт** (discovery полей → map → rules → Проверить → Сохранить).
3. **Навык** → настрой data-need (сущности+поля).
4. **Граф** → перетащи роль → узел-агент → подключи источники.
5. **Агенты** → проверь портфель, конверт.
6. **Запусти** → смотри находки, отвечай на HITL, забери результат.
7. **Карта** (Данные → Карта) — свериться, что вся цепочка связана.
