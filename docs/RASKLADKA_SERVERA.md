# Раскладка серверного пакета: расщепление монолита и шов зависимостей

> Актуально на 08.10.2026. Решение — [ADR-052](ABOP_ADR.md). Сторожат
> `tests/test_routes_inventory.py` и `tests/test_routes_modules.py`.

## 1. Зачем это вообще

`server/web_api.py` вырос до 8 648 строк и почти двух сотен ручек в одном `@app`, без единого
`APIRouter`. Пока файл один, сервис нельзя ни шардировать по домену, ни читать по частям: любая
правка в карте процессов открывает тот же файл, что правка биллинга.

Но расщепление — именно тот вид работы, где легко потерять ручку и не заметить. Тесты проверяют
поведение известных эндпоинтов; эндпоинт, который молча исчез, никто не спросит. Поэтому переезд
идёт под тремя страховками, и они важнее самого переезда.

## 2. Три страховки

### 2.1 Снимок маршрутов — `tests/fixtures/routes.json`

Закреплены все **206** пар (метод, путь). Переезд ручки между модулями снимок **не меняет** — он
описывает внешнюю поверхность, а не раскладку файлов. Пропажа ручки ломает тест.

Если ручка добавлена осознанно — снимок обновляется тем же коммитом, и это видно в ревью отдельной
строкой. Так добавление API перестаёт быть незаметным.

> Тонкость FastAPI: `app.include_router(...)` не раскладывает маршруты роутера в `app.routes`
> плоским списком — они остаются внутри `original_router`. Инвентаризация обязана спускаться
> рекурсивно, иначе она «не видит» ровно те ручки, которые уже вынесены.

### 2.2 Шов зависимостей — `server/deps.py`

Единственное место, откуда модули маршрутов берут «кто пользователь и что ему можно»:

| Что | Для чего |
|---|---|
| `user(request)` | разбор `Bearer`: multi-issuer JWKS, кэш проверенных токенов, fail-closed |
| `require_level(u, "manager")` | шкала уровней `analyst → manager → support → admin` |
| `can_see_family(u, family)` | ABAC по отделу |
| `_sub(u)`, `_identity(u)` | кто именно (для авторства и журналов) |
| `_uid_of(u)` | под каким именем человека знают внешние системы (сквозной ID) |

Здесь намеренно **нет ни одного маршрута и ни одного стора**. Импортировать `web_api` из модуля
маршрутов нельзя: первый же такой импорт втянул бы приложение целиком, и расщепление свелось бы к
перестановке строк между файлами. Запрет проверяется тестом.

### 2.3 Статическая проверка имён — `tests/test_routes_modules.py`

При переносе ломается не поведение, а **имена**: функция уехала в модуль, а звавший её код остался
в монолите (или наоборот). Python обнаруживает это только на живом запросе — то есть у заказчика.

Тест разбирает AST каждого модуля и ищет имена, которые читаются, но нигде не объявлены и не
импортированы. Первым же запуском он нашёл ссылку на `execute_agent_run`, переданную **как
значение**, а не вызовом: замена по шаблону вызова её не задела, и обработчик событий шины упал бы
при первом же событии.

## 4. Что осталось в монолите

109 ручек. По убыванию размера домена:

| Домен | Ручек | Что держит его в монолите |
|---|---|---|
| `runs` | 24 | `execute_agent_run` — общая зависимость с `agents` и с обработчиком событий шины; переезжать им придётся вместе |
| `agents` | 20 | то же + авторство, версии, триггеры, подбор |
| `report-templates` / `schema-templates` | 12 | предпросмотр шаблона зовёт слой сборки отчёта (`_report_context` и пять html-помощников, ~400 строк). Сначала этот слой должен уехать в `server/report_compose.py` — иначе домен шаблонов потянет его за собой в чужой модуль |
| `skills` / `catalog` | 8 | `_skill_*`-помощники общие с подбором и агентами |
| `plan` | 6 | зовёт планировщик, оркестратор и `execute_agent_run` |
| `pipelines` | 5 | то же плюс `_rerank_chain` и `_result_to_context` |
| `hitl` / `findings` / `out-channels` | 5 | `_resume_job_after_hitl` и `_send_channel` — доставка живёт рядом с прогонами |
| `board` | 3 | `_run_visible` общий с домеными прогонов |
| `triggers` | 3 | `execute_agent_run` |
| `contracts` | 3 | чистый, едет следующим |
| остальное (`nlu`, `auth`, `canvas`, `fleet`, `billing`, служебные) | 15 | по одной-две ручки; часть останется в приложении осознанно (health, metrics, middleware) |

**Порядок переезда** определяется не размером, а связностью: сначала домены, в которые никто не
заглядывает, последними — `runs` и `agents`.

Два домена ждут не переезда, а **предварительной правки**: шаблоны — выноса слоя сборки отчёта в
`report_compose`, навыки — разбора `_skill_*`-помощников, часть которых принадлежит подбору, а не
каталогу. Везти домен вместе с чужими помощниками значило бы сделать второй монолит поменьше.

## 5. Признанный долг: один поздний импорт

В `server/routes/bus.py` есть единственное исключение из запрета на `web_api`:

```python
def _из_монолита(имя: str):
    from .. import web_api
    return getattr(web_api, имя)
```

Переигровка задания из DLQ зовёт прогон, который из монолита ещё не выехал. Импорт отложен до
вызова, поэтому цикла на старте нет. Тест падает, если таких мест станет **больше одного**: это
записанный долг, а не привычка. Он уйдёт вместе с доменом `runs`.

## 6. Как перенести домен

1. Создать `server/routes/<домен>.py`: `router = APIRouter()`, аутентификация и гейты — из
   `..deps`, сторы — напрямую.
2. Перенести ручки, заменив `@app.<verb>` на `@router.<verb>`. Путь и метод **не менять** — иначе
   поедет снимок, и переезд перестанет быть переездом.
3. Подключить: `app.include_router(_routes_<домен>.router)` в `web_api.py`.
4. Перекрёстные ссылки восстановить **по имени у роутера**, а не копией функции:
   `_seat_ops = _routes_process._seat_ops`. Копия со временем разойдётся с оригиналом.
4а. Если помощник нужен обеим сторонам и ни одной не принадлежит — он не перекрёстная ссылка, а
   **шов**: `_uid_of` (под каким именем человека знают внешние системы) уехал в `server/deps.py`
   именно так. Признак шва: его зовут и ручки, и прогоны, и фоновые задачи.
5. Прогнать `pytest tests/test_routes_inventory.py tests/test_routes_modules.py` — первая проверка
   ловит пропажу ручки, вторая — оборванное имя. Затем полный прогон.

## 7. Чего делать нельзя

* **Импортировать `web_api` сверху модуля.** Это возвращает монолит через чёрный ход; тест
  запрещает.
* **Менять путь или метод «попутно».** Переезд и правка контракта — два разных коммита, иначе по
  изменившемуся снимку невозможно понять, что именно произошло.
* **Копировать помощника в новый модуль.** Две копии одной проверки прав — это ровно тот способ,
  которым дыры в доступе и появляются.
* **Дублировать гейты в слое MCP.** Уровни проверяются внутри вызываемых функций; MCP-сервер
  (ADR-048) — обёртка над тем же HTTP-слоем, а не второй путь к данным.
