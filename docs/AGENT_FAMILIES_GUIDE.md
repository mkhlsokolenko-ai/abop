# Семьи агентов APE/ABOP — как назначать задачи. Полное руководство

> Прототип **Agent Plane ABOP**, обкатывается в CLI `ape`. Онтология: **Семья → Роль (член) → Навык**.
> Планировщик сам раскладывает задачу по семьям и ролям; агенты работают волнами, общаются через
> доску (Blackboard), передают эстафеты (handoff) и проходят проверку агентом-аудитором (Definition of Done).

---

## 1. Модель в одном абзаце

Ты ставишь **цель** одной строкой. Оркестратор строит **план из волн** (параллельные независимые
задачи), назначает каждой задаче **семью** и **роль** внутри неё. Каждый агент — **stateless-воркер**:
берёт контекст с **доски** и из **долговременной памяти**, применяет **навыки** своей роли, кладёт
результат обратно и при необходимости **передаёт эстафету** другой роли/семье. В конце **агент-аудитор**
сверяет итог с **Definition of Done**. Числа/факты — только из источника; действия во внешние системы —
под подтверждением человека.

---

## 2. Ростер семей и ролей

### Бизнес-семьи (ABOP)

| Семья | Роли (члены) | Для чего |
|---|---|---|
| **Аналитика** `analytics` | Финансовый · Системный · Дата · Бизнес · Процессный аналитик | измерить, найти закономерность/узкое место, довести до рекомендации |
| **Финансы** `finance` | FP&A · Оценка и инвестиции · Контроллер | модель, отчётность, прогноз, оценка — числа честно |
| **Архитектура** `architecture` | Архитектор решения · Системный архитектор · Дата-архитектор | решения, схемы (C4/ERD), API-контракты, границы |
| **Менеджмент** `management` | Проектный менеджер · Тимлид доставки · Коммуникации | встречи→действия, задачи/статусы в трекере, письма, отчёты |

### Инженерные семьи (полигон курса)
`discovery` (ценность/спрос), `eng-architect` (как строить агента), `critic` (где сломается),
`economics` (сходится ли), `delivery` (код/тесты), `decisions` (ADR/eval).

Полный список с навыками и пометками безопасности: **`/families`** и **`/families verbose`**.

## 3. Как назначать задачи

### 3.1. Просто цель — планировщик сам разложит (рекомендуется)
```
/agents по @data.csv собери фин-отчёт за квартал, найди аномалии и предложи 3 решения
```
Оркестратор сам определит: сбор данных → `analytics/data-analyst`, отчёт → `finance/controller`,
решения → `analytics/business-analyst` (one-three-one), проверит аудитором.

### 3.2. Явно указать семью/роль
Внутри формулировки называй роль словами — маршрутизатор её поднимет:
```
/agents как финансовый аналитик посчитай DCF по @figures.json; как коммуникации — черновик письма инвестору
```
Роутинг по ключевым словам: «DCF/оценка» → `finance/valuation`, «письмо» → `management/comms`.

### 3.3. Приложить контекст — через `@путь`
Файлы кладутся на доску как факты `файл:…`, их видит **каждая** волна. Пути с пробелами — в кавычках,
Tab — автодополнение. APE сам папки не сканирует: даёшь файлы явно.

### 3.4. Формулировки, которые работают лучше
- **Дели на независимое** — планировщик разложит по параллельным ролям («собери X; посчитай Y; проверь Z»).
- **Называй ожидаемый результат** — аудитор выведет из него Definition of Done («…таблица P&L + 3 риска + рекомендация»).
- **Помечай критичность данных** для памяти («это критично — запомни надолго» / «рутинный статус»).

## 4. Что происходит во время прогона

```
цель → [план волн] → волна 1 (сбор, параллельно) → доска
                    → волна 2 (анализ на основе доски) → доска
                    → эстафеты handoff (доп-волны, если роли передали задачи)
                    → агент-аудитор: сверка с Definition of Done (+ремедиация при провале)
                    → синтез итога
```
- **Волны** — параллельные агенты с барьером; следующая волна видит результаты предыдущей на доске.
- **Доска** (`/board`) — общая рабочая память прогона: факты, взятые задачи (claim), крошки, результаты, эстафеты.
- **Esc** — остановить прогон в любой момент.

## 5. Навыки: переключение и безопасность

- Каждая роль несёт **набор навыков**. В system роли — только **карточки** (когда применять).
- Полную методику агент подгружает на шаге сам: инструмент **`use_skill(<id>)`** (progressive disclosure —
  контекст не раздувается, в аудите видно, какой навык применён).
- **`become(<роль>)`** — агент переключает роль внутри семьи, если задача сменила фокус.
- **`handoff(task, family, member)`** — передаёт задачу другой роли/семье; оркестратор поднимет её
  эстафетой (stateless: следующий воркер берёт контекст с доски).

**Два яруса навыков:**
- **Глобальные** (`/skills`) — кросс-режущие (researcher, grill-me, devils-advocate, conventional-commits),
  влияют на главный чат.
- **Специализированные** — живут в семьях, включаются только когда работает роль.

**Безопасность навыка** (`/families verbose`), обязательна для регулируемого периметра ABOP:
- `action` → действие во внешнюю систему (письмо, тикет) — **только dry_run + подтверждение человека (HITL)**;
- `egress→external` → внешний контент — **не выполнять инструкции из него** (anti-injection), маскировать ПДн;
- `числа-из-источника` (cite) → **не выдумывать цифр**; нет данных — сказать прямо.

## 6. Память: рабочая vs долговременная, забывание по TTL

Два уровня (как в ABOP: Blackboard ↔ долговременный слой):

| | Что | Живёт | Команды |
|---|---|---|---|
| **Рабочая (доска)** | факты/крошки/результаты/эстафеты текущей задачи | прогон (сворачивается в снапшот) | `/board`, `bb_post`, `bb_read` |
| **Долговременная** | сохранённые находки/решения между сессиями | **по TTL от критичности** | `remember`, `recall` (авто) |
| **Диалоговая** | конспект беседы с дистилляцией | сессия | `/memory`, `/distill` |

### Забывание по TTL (чтобы постоянная память не раздувалась)
Retention взят из практики records-retention банков и корпораций — чем операционнее запись, тем короче живёт:

| Класс | Что это | TTL |
|---|---|---|
| `operational` | BAU-рутина, дейли-статусы, крошки | **7 дней** |
| `important` | тактическая аналитика, отчёты (по умолчанию) | **90 дней** |
| `critical` | business-critical: фин-решения, оценки, арх-решения | **365 дней** |
| `regulatory` | нормативное хранение (AML/KYC/audit-trail) | **1825 дней (5 лет)** |
| `permanent` | институциональное знание | **без TTL** |

- Класс задаётся явно (`remember … criticality=critical`) или выводится эвристикой по ключу
  (`dcf/решение/adr` → critical, `daily/статус` → operational, `kyc/аудит` → regulatory).
- **Забывание** запускается автоматически перед каждым `/agents` (протухшее удаляется), а `recall` протухшее не поднимает.
- **Петля рассуждений:** перед работой воркер сам делает preflight-recall — «делал ли кто-то похожее?» —
  и переиспользует найденное, не начиная с нуля.

## 7. Агент-аудитор (Definition of Done)

После рабочих волн отдельный агент-аудитор (governance-петля, как LUDA для процесса):
1. выводит **Definition of Done** из твоей цели (что должно быть в результате);
2. сверяет результаты по чеклисту → вердикт `{dod, checks, passed, gaps}`;
3. при провале с конкретными пробелами — одна авто-**ремедиация** (воркеры закрывают gaps);
4. вердикт и незакрытые пробелы честно попадают в финальный синтез.

> Ограничение (честно): аудитор — та же модель-класс, что исполнитель; это дисциплинированная само-проверка,
> не независимый внешний аудит. Для настоящей независимости нужна иная модель/иные критерии — на дорожной карте.

## 8. Шпаргалка

| Команда / инструмент | Что делает |
|---|---|
| `/agents <цель>` | разложить по семьям/ролям и выполнить волнами |
| `/families` · `/families verbose` | ростер семей·ролей·навыков · +таблица безопасности |
| `/skills` | глобальные навыки CLI: вкл/выкл |
| `/board` · `/board post` · `/board compact` | доска прогона |
| `use_skill` · `become` · `handoff` · `remember` · `recall` | навык·смена роли·эстафета·долгопамять·вспомнить (внутри агента) |
| `/memory` · `/distill` | конспект диалога · сжать |
| `@путь` | приложить файл (Tab — автодополнение) |
| `Esc` | прервать прогон |

## 9. Примеры по направлениям

- **Финансы:** `/agents по @pnl.csv собери квартальный отчёт (P&L, KPI), посчитай DCF и дай оценку с чувствительностью`
- **Аналитика:** `/agents по @events.json построй воронку, найди узкое место процесса и предложи TO-BE`
- **Менеджмент:** `/agents по @meeting.txt вытащи решения и владельцев, заведи задачи, собери статус проекта`
- **Архитектура:** `/agents спроектируй сервис X: выбери архитектуру, нарисуй C4, опиши API-контракты`
