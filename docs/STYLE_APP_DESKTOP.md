# STYLE_APP_DESKTOP — эталон дизайна десктопа ABOP

> Один файл, одна страница смысла. Метафора, масштаб, лестница, сигнатуры, каркас.
> Решения приняты на дизайн-допросе 21.11.2026 (grill-me, режим design, 8 веток —
> владелец утвердил каждую). Дисциплину держат тесты: `tests/test_desktop_style_app.py`
> (этот файл) + `test_desktop_contrast.py` (AA считает по подложкам) +
> `test_desktop_design_language.py` (карточки собираются токенами).
> Эталон веба — `docs/STYLE_APP.md` (верстак); грамматика кнопок общая.

## §0. Метафора: диспетчерская отдела

Интерфейс = пульт управления потоком работы, не админ-панель. Всё выводится оттуда:
mono-капсы — гравировка на приборах; полоса значимости — главный жест; живые числа —
табличный моно-шрифт; **ни одного декоративного элемента**. Что-то мигает только тогда,
когда реально работает. Что-то крупно только тогда, когда это главная цель экрана.

## §1. Масштаб (числа охраняются тестом)

| элемент | рецепт |
|---|---|
| тело | 13px / 1.5, `font-variant-numeric: tabular-nums` на всём |
| заголовок экрана | 15px / 800 (один `h1` на экран) |
| заголовок карточки | 12.5px / 600 |
| капса секции `.lbl` | 500 9.5px mono, uppercase, .13em |
| кнопка `.btn` | 700 11.5px / 8×12 / r8 |
| кнопка `.sm` | 700 11px / 7×10 |
| кнопка чата (отправка) | 44×44 — **единственная** крупная цель приложения |
| чип `.chip` | 500 10px mono / 5×8 / r6 (`--r-2xs`) |
| тег `.tag` / `.tagbtn` | 500 9.5px mono / 3×7 / r5 |
| строка списка | 28px (`--row-h`) |
| радиусы | 6/8/9/11/14/18 |

Кнопка — инструмент пульта, не витрина: одинаковый вес со строкой данных.

## §2. Палитра и сигнатуры

Фон `#060a12` · панели `#101726`/`#16203a` · рамки `#22304e`/`#31415f` · поле `#0d1526`.
Акцент фиолетовый `#8b5cf6` — один на все продукты платформы (латунь — только в бумаге).
Mesh = «дыхание» 0.02, не ноль. Шрифты: Manrope (вариативный, ось 200–800) + IBM Plex
Mono, оба в бандле; Inter/JetBrains Mono — фолбэк.

**Обязательные словари (сквозные, на каждой поверхности):**
- **Полоса значимости** `.sevbar h/m/l` — на всём, что «требует слова»: находка,
  группа, фирма с «ждёт N», NCR, эскалация, входящее ЭДО, строка прогона с ошибкой.
  Увидел полосу — понял: здесь нужен человек. Цветной полосы вне словаря быть не может.
- **ИКА-светофор** — одна шкала: ≥90 зелёный / 70–90 жёлтый / ниже красный (ADR-085).
- **Числа** — tabular mono. Пропорциональные цифры в счётчиках запрещены.
- **Капсы** — один рецепт `.lbl`; второй словаря подписей нет (`.ape-label` — синоним).

**Запрещено:** hover-lift (взлёт карточек — только рамка/фон), sheen вне `.load`,
постоянный пульс статусов (ровно горит; `.dot.run` — маячок реально исполняющегося),
градиентные плитки состояний, свои цветные полосы/кружки вне словаря темы.

## §3. Лестница ответственности — грамматика кнопок

Кнопка классифицируется по цене решения ДО нажатия. Словарь классов общий с верстаком
(`b-do/b-out/b-irr/b-calc`); ступень обязана стоять в разметке:

| ступень | класс | вид | примеры |
|---|---|---|---|
| расчёт | `.b-calc` | станочная двойная рамка, прозрачная | Пересчитать, Только вычитать, Исправлено — проверить |
| внутри | `.b-do` | плоская кнопка по умолчанию | Признать, Норма, Отдать отделу, Отчёт |
| наружу | `.b-out` | рамка ярче; **адресат стоит на подписи** | (egress-действия, письма) |
| необратимое | `.b-irr` | штриховка + красная рамка; всегда с подтверждением «что уйдёт — целиком» | Провести в 1С |
| ждёт человека | — не кнопка | место для подписи (HITL) | карточка решения |

`primary` — не ступень, а **флаг главной цели экрана**: одна на экран, ставится рядом
со ступенью (`class="btn sm primary b-do"`), никогда вместо неё.

Правила: на карточке/строке — одно главное действие, остальные тише или в меню;
рутинный разбор не должен превращаться в «можелклики» — массовые операции через
подтверждение пакетом. Сторож: «Провести в 1С» без `.b-irr` падает тестом.

## §4. Каркас экрана

- **Шапка экрана**: модули зовут `head()` ядра — `h1.scr-title` 15px/800 + строка
  происхождения (11px) + действия экрана. Три роли текста: `.scr-title` (заголовок
  экрана) / `.lbl` (капса секции, одно имя — синоним `.ape-label` выведен) /
  `.grp-title` (заголовок группы/карточки 12.5px/600). Если текст не одна из трёх
  ролей — это тело, и заголовком делать вид не должен.
- **Рейл = кольцо работы** (волна 3): первый класс — **Пульт отдела · Чат · Решения ·
  Прогоны · Клиенты · Кабинет**; под капсой «сервис» — Вертикали · Граф · Контроль ·
  Наблюдение (видит тот, кому ABAC разрешает). Представление (вертикаль) меняется
  из шапки (`vertBtn`), палитра Ctrl+K знает все разделы. Критерии: расчётчик до
  действия ≤1 клик; админ до сервиса ≤2.
- Карточка собирается токенами (`--panel-grad`/`--edge`/`--shadow-1`), не инлайнами.
- Состояния (пустое/загрузка/ошибка) — первоклассный контент со словами, не пустота.

## §5. Дисциплина

1. Новые экраны — классами из темы, не инлайнами. Инлайновый бюджет модулей —
   потолок, падающий при каждом касании файла (сторож считает `style="`).
2. Кнопка без ступени лестницы не проходит ревью; необратимое — всегда с `.b-irr`
   и модалкой полного перечня.
3. Контраст — не «на глаз»: `test_desktop_contrast` считает AA по подложкам.
4. Изменение любого числа из §1 — через тест и с пометкой решения в комментарии.
5. Ссылки на этот файл в комментариях кода — формат `STYLE_APP_DESKTOP §N`.
