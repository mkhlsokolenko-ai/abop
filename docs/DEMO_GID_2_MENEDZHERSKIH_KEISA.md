# Демо-гайд: 2 менеджерских сценария (что и как показывать заказчику)

Гайд-сценарий выступления. Идея, которую продаём: **ABOP — инженерная платформа для сборки и
управления агентами, а десктоп-чат — рабочая среда пользователя**, откуда он этими агентами
пользуется. Инженер собирает агента в вебе ABOP (навыки → конверт → HITL → Data Plane), а менеджер
запускает его прямо из чата и получает находки, задачи в трекере и письма — под своим подтверждением.

Всё на **реальных** системах и данных (не слайды): менеджер видит входящие письма и данные в живых
сервисах, запускает агента из чата, результат прилетает обратно **в те же системы** — но только
после подтверждения (HITL прилетает в чат всплывающим окном «подтвердить действие»).

> Точка входа для показа — **ABOP Desktop** (маскот-иконка на рабочем столе).
> Модуль **«Чат»** — это и есть среда управления: тред → шторка «Агенты» → запуск реального ABOP-агента.

| **Redmine** (трекер задач) | `http://5.129.192.63:3000` | сюда агент создаёт задачи |
| **BookStack** (вики/Confluence) | `http://5.129.192.63:6875` | документ БФТ для анализа |
| **Twenty CRM** | `http://5.129.192.63:3002` | контекст по клиенту (при желании) |
| **ABOP Desktop** | приложение (иконка-маскот) | рабочее место менеджера |

Прогрев кэша (чтобы на демо прогон возвращался за 1–2 сек, а не 25–40):

```bash

curl -s -X POST http://5.129.192.63:8091/api/demo/prepare -d '{"scenario":"bft"}'      -H "Content-Type: application/json"
```

## Сценарий 1. «Утро менеджера»: триаж почты → дневной план → задачи в трекер

Объединяем то, что раньше было тремя шагами (триаж входящих + формирование плана дня + назначение
задач в Jira/Redmine) в один сквозной прогон агента **«Дайджест задач»** (mailtasks).

**Боль заказчика:** менеджер утром тонет в почте — часть писем это задачи, часть срочное, часть
мусор. Руками разбирать 30–60 минут, план дня собирается «на коленке», задачи теряются.

### Шаги показа

1. **Показать проблему — открыть почту.**
   Вкладка **Mailpit** `http://5.129.192.63:8025`. Входящие (17 писем) вперемешку: «Смените пароль»
   от службы безопасности, счёт №СК-778, задача от директора, лид, спам.
   *Реплика: «Вот утро менеджера. Здесь срочное, задачи и мусор — всё в куче.»*

2. **Открыть ABOP Desktop → модуль «Чат» → создать тред.**
   *Реплика: «Чат — рабочее место. Отсюда менеджер и пользуется агентами, которых мы собрали в ABOP.»*

3. **Запустить агента из чата.**
   В композере — иконка **🕸 (Агенты)** → шторка → вкладка **«Агенты»** → выбрать **«Дайджест задач»**
   → **▶ Запустить агента в тред**.
   *Реплика: «Агент читает те же письма, что и менеджер, под его правами (RBAC/ABAC).»*

4. **Показать результат — карточка прогона прямо в треде:**
   - 🔴 *Письмо службы безопасности «Смените пароль» — срочность высокая, требует немедленного действия.*
   - 🟡 *Письмо от Игоря Пряхина — договорённость/задача, нужен ответ.*
   - … + план дня по приоритетам, спам отсеян.
   Внизу карточки — блок **доставка**: `redmine` и `email` со статусом «ожидает подтверждения (HITL)».
   *Реплика: «За ~30 секунд разобрано то, на что уходит час. Каждая находка — со ссылкой на письмо.»*

5. **HITL — всплывающее окно «подтвердить действие».**
   Сразу после прогона выскакивает окно: *«🛡 Подтвердите действие агента: redmine → создать задачу,
   email → ответ клиенту»*. Кнопки **Подтвердить действие / Отклонить**.
   *Реплика: «Агент ничего не отправляет и не меняет сам. Всё наружу — только по клику менеджера.
   Это управляемая автономия: агент работает в рамках конверта, который задал инженер в ABOP.»*

6. **Нажать «Подтвердить» → показать результат в системах.**
   - **Redmine** `http://5.129.192.63:3000` → появилась задача (с описанием и ссылкой на письмо).
   - **Mailpit** `http://5.129.192.63:8025` → появилось письмо-ответ.
   *Реплика: «Результат вернулся в ваши же системы. Менеджер не переключался между окнами.»*

**Ценность:** *«Разбор входящих и план дня — из часа в 30 секунд; задачи сами лежат в трекере; отправка под контролем.»*

## Сценарий 2. «Письмо со ссылкой на БФТ»: анализ документа из Confluence по запросу

**Ситуация:** менеджеру пришло письмо со ссылкой на страницу в Confluence/BookStack — там БФТ
(бизнес-функциональные требования). Он просит агента разобрать документ: структура, пробелы, риски,
что уточнить у автора. Агент **«Аналитик БФТ»** (bft) читает страницу из BookStack и даёт разбор.

### Шаги показа

1. **Показать письмо со ссылкой.**
   **Mailpit** `http://5.129.192.63:8025` → письмо с задачей «Подготовить/проверить вики-отчёт»
   и ссылкой на **BookStack** `http://5.129.192.63:6875` (страница БФТ).
   *Реплика: «Классика: прислали ссылку на требования, надо быстро понять, что там и чего не хватает.»*

2. **(Опционально) показать сам документ** в BookStack — чтобы заказчик видел исходник.

3. **Из чата попросить агента разобрать.**
   Способ А (быстрый): выделить ссылку/фрагмент письма → **Ctrl+Shift+A** (глобальный хоткей) —
   ABOP Desktop открывается, текст уже в чате.
   Способ Б: в треде — шторка **🕸 Агенты** → **«Аналитик БФТ»** → в поле контекста вставить ссылку
   на страницу → **▶ Запустить агента в тред**.
   *Реплика: «Менеджер не пишет промптов — он берёт готового агента, собранного инженером под эту задачу.»*

4. **Показать результат — карточка разбора БФТ:**
   - структура документа и ключевые пункты,
   - пробелы/неоднозначности («что уточнить у автора»),
   - предложение по оформлению вики-отчёта.
   Внизу — **доставка**: `bookstack` (черновик отчёта) и `email` автору — оба «ожидает подтверждения».

5. **HITL-окно → подтвердить → результат в системах.**
   - **BookStack** `http://5.129.192.63:6875` → появился/обновился вики-отчёт.
   - **Mailpit** `http://5.129.192.63:8025` → письмо автору с замечаниями.
   *Реплика: «Разбор требований и ответ автору — в ваших же инструментах, за минуту.»*

**Ценность:** *«Любой документ по ссылке из письма — разобран агентом с готовым ответом, без ручного вычитывания.»*

## Ответ на главный продуктовый вопрос (проговорить заказчику)

**«ABOP — инженерная платформа, чат — среда управления».**
- В **вебе ABOP** инженер/аналитик собирает агента: выбирает навыки, задаёт конверт автономии,
  точки HITL, подключает источники (Data Plane). Это «завод агентов».
- В **десктоп-чате** менеджер этими агентами пользуется: запускает из треда, видит находки, жмёт
  «подтвердить». Ему не нужно знать промпты и внутренности — он работает в привычном чате.
- Одни и те же агенты/навыки/данные: чат ходит в тот же рантайм ABOP, что и веб. Собрали в вебе —
  сразу доступно в чате пользователю (по его роли).

## Что подчеркнуть в обоих кейсах
1. **Один рантайм, свои данные.** Агент под правами конкретного менеджера (RBAC/ABAC). Модель на
   self-host (свой сервер) — данные не уходят наружу.
2. **Управляемая автономия (HITL).** Всё, что меняет системы/уходит наружу — только после
   подтверждения. HITL прилетает в чат окном; конверт задал инженер в ABOP.
3. **Аудируемость.** Каждая находка — со ссылкой на источник и трассой прогона (модель, токены,
   откуда данные). Показать вкладку логов/трассы.
4. **Результат в системы.** Не «ещё один отчёт», а задача в трекере / письмо / вики-страница.
