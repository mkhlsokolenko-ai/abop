# ABOP — Рабочее задание дизайнеру (Design Brief)

**Задача:** перерисовать концепт фронта ABOP до **production-grade product concept** — закрыть провал понимания (пройти 2-мин тест ≥7/10), добавить слой Операций/Флот, закрыть пробелы (Безопасность, слайдер прав, light-тема), применить доработки ревью (D1–D6). Работать **строго по докам** (`ABOP_DESIGN_HANDOFF.md` — навигатор; данные/сущности/исполнение — там же в матрице). Ничего не придумывать: нет источника → фиксируем как вопрос.
**Отправная точка:** прототип v2 (собран, но проваливает 2-мин тест 4/10) + дизайн-система/брендкит ABOP (dark-first индиго, маскот Эйп, «язык ожидания» — сохранить).
**Формат сдачи:** Figma — библиотека компонентов + экраны по спринтам + кликабельный прототип (связи), **2 темы (dark+light)**, **все 4 состояния** каждого экрана.
**Статус:** v1.0.

---

## 0. Правила (жёстко, «не придумывать»)
- **⚠️ Корневая модель — канва-центричная (ADR-030).** Не 8 вкладок-ровней, а **один граф в центре** + линзы (Строю/Запускаю/Эксплуатирую/Конверт) + палитра-источники + конверт-рамка + инспектор. Всё задание читать через эту модель; «экран» = линза/панель над графом (см. T0.2, `SCREENS §0`).
- Данные/поля экрана — из `ABOP_API.md` (матрица `HANDOFF §3`). Нет эндпоинта → не рисуем цифру.
- Сущности и их имена — из `ABOP_TDR.md` (`Deployment/Instance/AgentVersion/Recipe`).
- Тексты/термины/tooltip — из `ABOP_UX_FIXES.md` (готовые, человеческий язык). Новый текст — согласовать.
- Элементы/цвета/маскот/спиннеры — только `ABOP_DESIGN_KIT.md` + `docs/brand/`. Ни одного нового визуального языка.
- Состояния (пусто/загрузка/ошибка/наполнено) — рисовать ВСЕ четыре (`SCREENS §10`).
- Каждый экран проходит чек-лист приёмки (§6 ниже).

## СПРИНТ 0 — Фундамент (блокирует всё; сделать первым)

**T0.1 · Токены** — `tokens` (dark+light). Вынести палитру брендкита в переменные: bg/surface(glass+flat)/brand(индиго-градиент)/семафор(ok/warn/crit)/text. Источник: `DESIGN_KIT §6.1`. **NB (доработка D6):** ввести ДВА уровня поверхностей — `--surface-glass` (dashboard/hero) и `--surface-flat` (workflow/таблицы). Приёмка: обе темы, WCAG AA на стекле.

**T0.2 · Shell / КАНВА-ЦЕНТРИЧНЫЙ каркас (ADR-030)** — НЕ sidebar из 8 вкладок-ровней, а **канва в центре + линзы + палитра + конверт-рамка + инспектор**. Источник: `SCREENS §0`, `ADR-030`, `PRD §7`. Собрать:
- **Конверт-рамка** (сверху/вокруг канвы, всегда видима): автономия ≤ контракт · egress · N точек HITL · семафор здоровья. Клик → Паспорт-оверлей. **Не прячется в узлы** (value prop).
- **Палитра** (слева): группы-источники `Агенты · Навыки · Данные · Коннекторы` для drag-and-drop В граф + `🔍`-фильтр; внизу маскот Эйп + @user·роль.
- **Переключатель линз** (topbar): `[Строю] [Запускаю] [Эксплуатирую] [Конверт]` — один граф, разные режимы. Активная линза — индиго-подсветка.
- **Инспектор** (справа, по клику): настройки узла (агент/навыки/автономия-слайдер/mode·egress·cite/cost) или связи (data-контракт/handoff).
- **Вызываемые поверхности** (не линзы): Безопасность/RBAC (клик на узел→разобрать участок), Настройки среды, Билинг/аудит — контекстные панели.
- **Обзор** = отдельный вход-портфель графов (нулевая линза), не равноправная вкладка.
Приёмка: активная линза читается; конверт-рамка видна во всех линзах; drag-and-drop из палитры → узел на канве; focus-ring; обе темы.

**T0.3 · Атомы форм** — input/select/textarea/checkbox/**слайдер прав**/поиск-фильтр. Источник: `DESIGN_KIT §6.4`, `GAPS` (слайдер прав). Слайдер прав `read→write→action` с мгновенным семафор-фидбеком; макс-крит залочен (≤ контракт). Приёмка: раздельные hint/error, aria-invalid.

**T0.4 · Семафор-чип безопасности навыка** (`mode/egress/cite`) — read-only компонент + раскрытие «почему». Источник: `DESIGN_KIT §6.8`, `GAPS #4`.

**T0.5 · Маскот Эйп — 5 состояний** как компонент-иконка статуса (idle/думает/HITL/стоп/DoD✓). Источник: брендкит §02, `DESIGN_KIT §6.7`.

**T0.6 · Библиотека спиннеров/прогресса** («язык ожидания»: Кольцо/Волны/Эстафета/Сканирование/Скелетон + прогресс волн + AutonomyEnvelope). Источник: брендкит §03–04, `DESIGN_KIT §6.5–6.6`.

## СПРИНТ 1 — MVP-экраны + фиксы понимания (2-мин тест)

> Цель спринта: **пройти 2-мин тест ≥7/10** (`ABOP_2MIN_TEST.md`). Фиксы обязательны.

**T1.1 · Обзор (decision interface)** — Источник: `SCREENS §2` + доработка **D1** (`UX_REFINEMENT`).
- Outcome-подача прогонов (крупно бизнес-задача, бейдж готовности, техника мелко).
- Полоса «в проде сейчас: N агентов · M экземпляров · HITL · ошибки» → §8а.
- **Фикс 2-мин теста #3:** строка «что это» под логотипом (готовый текст `UX_FIXES`).
- **Фикс #2:** приветственное/пустое состояние-онбординг (3 шага + быстрый старт) — когда 0 прогонов.
- Состояния: пусто(онбординг)/загрузка(скелетоны)/ошибка/наполнено. Приёмка: понятно новичку без жаргона.

**T1.2 · Пульт прогона (★ главный)** — Источник: `SCREENS §3` + доработки **D2/D3/D4/D5**.
- **D2:** граф-центр (canvas волн доминирует) + **Execution Inspector** справа (узел: agent/input/skills/autonomy/cost/latency/risk).
- **D3:** визуализация волн WAVE 01–04 (раскладка DAG, «Волны»-лоадер на активных).
- **D4:** explainable-валидация как шаг (объяснение + «как починить», гейт запуска).
- **D5:** AutonomyEnvelope L0–[L2]–L3 + policy ceiling + tooltip.
- Доска, вердикт аудитора DoD, HITL-полоса (dry_run→approve+undo).
- **Фикс #1:** inline-tooltip на термины (волна/HITL/конверт/автономия — тексты `UX_FIXES`).
- Данные: `/api/runs/{id}/stream` (SSE — предварительно). Состояния: нет прогона/стрим/ошибка/завершён.

**T1.3 · Навыки (каталог)** — Источник: `SCREENS §4`.
- Грид карточек + семафор-чипы безопасности (permission-scoping видимо); drawer с телом (progressive disclosure).
- **Фикс #5:** микро-легенда чипов (`🔵 читает · 🟣 создаёт · 🟠 действует наружу · ✓ из источника`).
- Данные: `/api/skills`, `/api/skills/{id}`. Состояния: фильтр-пусто/загрузка(скелетоны)/наполнено.

**T1.4 · Данные (рецепты + коннекторы)** — Источник: `SCREENS §5`.
- Редактор рецепта (адаптер csv/http/sqlite/computed → map/rules → emit) + **preview-pane** на выборке.
- Коннекторы (реестр адаптеров, у http — «egress→анти-SSRF», sqlite — «read-only»).
- Данные: `/api/data/*`. Состояния: пустой рецепт/preview-загрузка(«Сканирование»)/ошибка-источника/наполнено.

## СПРИНТ 2 — Слой Операций / Флот (новое, центральное)

> Главный экран — **карта процессов с агентами** (`ABOP_OPERATIONS_MAP.md`), НЕ таблица.

**T2.1 · Карта Операций (semantic zoom)** — Источник: `ABOP_OPERATIONS_MAP.md` (полная спека).
- Full-screen карта (движок как Канва, read-only): плитки-узлы процессов, связи value chain.
- **4 уровня зума:** L0 Value Chain (звенья + «🐵 N агентов» + агрегат-индикаторы) → L1 Процесс → L2 Подпроцесс → L3 Операция (карточки живых экземпляров с маскот-Эйп).
- **Декомпозиция индикаторов** по уровню (агрегат→детализация; всё сходится).
- Крошки-уровни (Организация▸Процесс▸…) + тумблер **AS-IS | LIVE** + контекст-панель справа.
- Эйп = «пульс карты» (состояние узла); «язык ожидания» на работающих операциях; AutonomyEnvelope на участке.
- Переходы: клик экземпляра→Пульт(§3), операции→Канва(пересмотр), пустой участок→«развернуть».
- Данные: `/api/deployments`, `/api/instances`, `/api/fleet/health`. Состояния: пусто(«в проде никого»)/загрузка/ошибка/живой-поток/дрейф.

**T2.2 · Эксплуатация — списки** (дополняют карту) — Источник: `SCREENS §8а`.
- таб **Развёртывания** (реестр + ЖЦ: пауза/отзыв/пересмотр-в-Канве/вывод-type-to-confirm).
- таб **Живые** (таблица экземпляров, клик→Пульт).
- таб **Здоровье** (KPI флота + алерты + ссылка на ре-аттестацию).

**T2.3 · Модалка «Развернуть агента»** — Источник: `SCREENS §9.5`. Версия+участок+триггер+автономия≤LUDA+лимит параллелизма. + type-to-confirm для retire/rollback.

## СПРИНТ 3 — Авторинг, Governance, Настройки

**T3.1 · Канва сборки** — Источник: `SCREENS §6`. Палитра(семьи/роли/навыки/источники)·drag-drop·холст(узлы+рёбра+LLM-узлы)·инспектор(роль/модель/**слайдер прав**)·LLM-черновик·автосейв-чип. Действие «пересмотреть развёрнутого» (из §8а). **D6:** плоский control-plane внутри (меньше glass).

**T3.2 · Паспорт агента** — Источник: `SCREENS §7`. Конверт(автономия≤контракт·роли·HITL·резидентность)·flow-схема·аудит-след·прод-статус/версии/инстансы·PDF·кнопка «Развернуть».

**T3.3 · Вкладка Безопасность (ИБ)** — Источник: `GAPS §7` (вернуть из LUDA 1). Admin-gated. 5 секций: RBAC(роль→права+YAML)·Периметр(scope⊆creator)·Модель эскалации·Ре-аттестация(объект=развёртывания)·Аудит-лог(хэш-цепочка).

**T3.4 · Настройки** — Источник: `SCREENS §8`. Табы Модели/Подключения/Авторизация/Арендаторы/Биллинг.

**T3.5 · Модалки** — Источник: `SCREENS §9`. Запуск прогона(§9.1)·HITL-подтверждение(§9.2, dry_run+предпросмотр+undo)·⌘K(§9.3)·подключение адаптера(§9.4).

## 4. Сквозные доработки (применить во ВСЕХ экранах)

- **Product clarity (2-мин тест):** термины объяснять in-place tooltip (`UX_FIXES`), outcome-язык вместо узлового, ни одного голого жаргона на видном месте.
- **Ревью D1–D6** (`UX_REFINEMENT`): outcome-хедер · граф-центр+inspector · волны · explainable-валидация · autonomy-envelope · меньше glass в workflow.
- **«Язык ожидания»** (брендкит): «волна 3/5», не «Загрузка…»; тайминги <300мс/спиннер/>3с-прогресс/>20с-скан; одна анимация на экран; `prefers-reduced-motion`.
- **Governance видимо:** конверт/автономия/HITL — не в настройках, а на поверхности (Пульт/Паспорт/Карта).

---

## 5. Золотые пути для кликабельного прототипа (обязательно связать)

1. **Сборка→результат:** Обзор → Навыки → Данные(рецепт+preview) → Канва(собрать) → Запустить → Пульт(волны/аудитор) → HITL(approve) → Паспорт(конверт закрыт).
2. **Эксплуатация:** Паспорт → Развернуть → Карта Операций(L0 value chain) → zoom до операции(L3, живые Эйп) → клик экземпляр → Пульт → Здоровье(алерт дрейфа) → Пересмотреть в Канве → Развернуть(новый vN).

---

## 6. Критерий приёмки (каждый экран + весь концепт)

**Per-screen:** 2 темы · все 4 состояния · данные с реальными полями (API) · термины in-place · один primary · focus-ring · WCAG AA на стекле · `prefers-reduced-motion` · маскот в корректном состоянии · семафор из токенов · кликабельность=переходы из SCREENS/OPERATIONS_MAP · сверено с DESIGN_KIT.

**Весь концепт (gate):** прогнать **2-мин тест** (`ABOP_2MIN_TEST.md`) — новичок без знания LUDA/Wave/Blackboard/DeploymentContract понимает, что делать, за 2 минуты. Цель **≥7/10**. Пока не пройдено — концепт не принят.

---

## 7. Вне скоупа (не делать сейчас)
- Мульти-каналы (Telegram/WhatsApp), голос, self-improving навыки — не берём (ломают конверт, `DESIGN_KIT §4`).
- Реальная интеграция с бэком — часть `/api/*` предварительна (RUN/STREAM/Fleet реализуются); рисуем по контракту, финальные поля синхронизируем перед hi-fi.
- Мобильная версия — не приоритет (десктоп-среда разработки).
