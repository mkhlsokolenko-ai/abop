# UI/UX разбор мокапа v5 — что работает, что нет, что поменять

> Разбор по методологии проверки проектных решений: понять намерение → проверить
> достижение → назвать конкретное действие. Не критика ради критики — каждое
> замечание ведёт к исправлению.

## Что работает (не трогать)

1. **Рейл отделов с ИКА-бейджами** — человек видит, какой отдел «болен», не открывая его.
   Цветовая шкала (зелёный/жёлтый/красный) читается за долю секунды.

2. **Очередь только своего отдела** — самая сильная UX-находка: расчётчик не тратит
   внимание на чужое. ABAC режет автоматически, человек не думает «чьё это».

3. **Полоса здоровья отдела** — ИКА + слагаемые с барами на одном экране. Руководитель
   видит «что сломано» без открытия отдельных дашбордов.

4. **Хот-карточка** — самая важная находка раскрыта: доказательство, способ, кнопка действия.
   Остальные свёрнуты в компактные строки. Прогрессивное раскрытие.

5. **HITL-карточка «что уйдёт — целиком»** — тело письма/документа перед подтверждением.
   Снимает страх «система сама что-то отправила».

## Что не работает (поменять)

### 1. Фирмы в правой колонке — слишком мелкие

Карточка фирмы занимает ~80px высоты, на ней 6 строк текста (название, статус, схема,
период, граница, доступ). На ноутбуке 1366×768 в правой колонке 316px ширины карточки
 firms выглядят тесно. Рекомендация: сократить до 2 строк (название + статус + «ждёт N»)
и раскрыть по клику, а не показывать всё сразу.

### 2. Нет «пустых состояний» для очереди

Если очереди нет — что видит бухгалтер? Сейчас просто пустое место. Нужно: «Очередь
пуста — все находки разобраны. Последнее решение: B1, вчера, 14:32» + кнопка «История
решений». Пустота — это тоже контент.

### 3. Фирма без ссылки на полную карточку

Клик по фирме в рейле должен открывать её карточку (клиент, схема, последний скан,
пересчитать). Сейчас фирмы в очереди «неразличимы» — одна строка, нет ощущения объекта.

### 4. Слишком много чисел в полосе здоровья

4 слагаемых ИКА + NCR + расход — руководство видит 7 чисел одновременно. Для расчётчика
достаточно 3: ИКА (главное), формата (его работа), и «ждёт подтверждения N» (его очередь).
Остальное — по клику.

### 5. Разрезы по фирмам — где переключатель?

В «Решениях» есть чип «мой отдел», но разрез по конкретной фирме не очевиден. Нужно:
чипы над очередью (все / МАЙ ДЕНТАЛ / Жигулёва) — клик фильтрует. Или использовать
выделение фирмы из правой колонки (уже реализовано) — тогда чип не нужен.

## Рекомендации по приоритетам

| # | что | усилие | эффект |
|---|---|---|---|
| 1 | Пустое состояние очереди | 15 мин | «система жива» вместо пустоты |
| 2 | Компактные фирмы (2 строки) + раскрытие | 30 мин | меньше шума на главном |
| 3 | 3 числа вместо 7 в полосе здоровья | 10 мин | внимание на главном |
| 4 | Разрез по фирме из очереди | 20 мин | выбор контекста без ухода |
| 5 | Иконки отделов в рейле | 15 мин | сканирование без чтения |

## User flow: кольцо отделов

Текущий флоу (v5) — **одно кольцо, без навигации**:

```
Утро → открываю отдел → вижу очередь (только моя) → разбираю карточки
  → каждое решение = один клик (доказательство на карточке)
  → нашёл новое? «Пересчитать» — скан в чате
  → вечером вижу ИКА: «сколько я исправил»
```

Чего не хватает: **уведомления** — «появилась новая находка в очереди» без открытия
десктопа. Telegram-бот уже привязан, но не отправляет уведомления о новых находках
отдела. Это следующая фаза: событие «находка добавлена» → бот уведомляет отдел.

## CJM: полный путь заказчика (аутсорсинг)

Этап 1: Боль → Подключение → Первый скан → Разбор → Решение → Исправлено → Масштаб.

Каждый этап = конкретное действие на конкретном экране. Переходы между этапами =
события, которые видны (новая задача, новый скан, новое решение). Пустых экранов нет:
каждый показывает «что происходит сейчас» или «что нужно сделать».
