* `exe → /memfd:4npbq4x3wxwynoh (deleted)` — бинарь запущен **из памяти** (fileless): на диске его нет, обычным поиском по файлам не найти;

* в Gitea оказалось **18 владельцев репозиториев** с именами вида `poc7c4666b4`, `pocvbkk2x`, `testpoc11204`, `testpoc25804` — характерный след автоматизированного эксплойта;
* профиль нагрузки (ровные ~300 % CPU сутками + одно постоянное TLS-соединение) соответствует криптомайнеру.

## 2. Как это стало возможно

Три условия совпали:

1. **Gitea был открыт всему интернету** — порт `3001` публиковался на `0.0.0.0`.
2. **Регистрация была включена** — `DISABLE_REGISTRATION` не задан, анонимный просмотр разрешён. Любой мог завести учётку и репозиторий.
3. **Сервис не обновлялся и не наблюдался** — сканирование шло девять дней, майнер работал трое суток, и заметили это по нагрузке, а не по тревоге.

Точный технический вектор (какая именно операция Gitea привела к запуску кода) по логам не восстанавливается: Gitea не пишет тела запросов, а действия через API выглядят в логе обычными строками. Поэтому утверждать про конкретную CVE оснований нет — достоверно известны открытая регистрация, следы `poc*`-учёток и запуск из каталога загрузки.

Контейнер Gitea делил сеть `svod-targets_default` с Redmine, BookStack и их базами — то есть **возможность** обратиться к соседям была, но следов обращения нет. Данные заказчика (план Пр2930 с фамилиями) лежат в другом контуре — контейнер `abop-webapi` и Postgres, вне этой сети; обращений к ним с адреса нарушителя также не зафиксировано.

* Контейнер остановлен, майнер прекращён; улики сохранены в `/root/incident-2026-10-19/` (карточка процесса, полный лог Gitea на 15 104 строки, список учёток).
* Gitea **пересоздан с нуля**: заражённый том удалён, репозиториев 0; `DISABLE_REGISTRATION=true`, `REQUIRE_SIGNIN_VIEW=true`, запрет git-хуков, порт опубликован только на `127.0.0.1:3001`. Правка внесена в `/root/docker-compose.yml`, чтобы следующий запуск не поднял сервис открытым.

Снаружи остались SSH, ABOP API (со своей авторизацией) и `red-team.tech` на 80/443.

## 7. Что сделать, чтобы не повторилось

1. Демо-сервисы не публиковать на `0.0.0.0` — только петля плюс доступ по списку адресов (сделано для 14 портов).
2. Любой сервис с регистрацией заводить сразу с `DISABLE_REGISTRATION` и обязательным входом.
3. Поставить тревогу на аномальную загрузку CPU контейнера — сегодня о майнере узнали случайно, при разборе «почему стенд тормозит».
