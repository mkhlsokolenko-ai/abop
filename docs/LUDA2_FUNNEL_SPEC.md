# LUDA 2 — доработка под воронку бизнес-заказчика (спека)

**Основание:** ADR-031 (бизнес-вход = LUDA 2) + `ABOP_LUDA_ROLE_SPLIT.md` + «Product & UX Brief v0.1» (экраны 01–09).
**Ключевой инсайт:** движок воронки в LUDA 2 **уже есть** — эндпоинты аудита закрывают шаги брифа. Доработка = **бизнес-UI поверх существующего движка** + пара новых экранов + редизайн под ABOP DS. Не стройка с нуля.
**Репозиторий:** `luda-v2` (отдельный). **Статус:** v0.1, к реализации.

---

## 1. Что УЖЕ есть в LUDA (движок воронки)

Из `src/luda/api` и `contracts/`:

| Возможность | Эндпоинт / модуль | Закрывает шаг брифа |
|---|---|---|
| Загрузка документов процесса | `POST /api/upload` | 02 Описание (доки) |
| Запуск аудита | `POST /api/audits/run` | 04 Анализ |
| Карта процесса | `POST /api/audits/diagram` | 03 Карта процесса |
| Где сажать агента | `/api/audits/placement` | 05 Что AI может (участки) |
| Экономика/ROI | `/api/audits/roi` | 07 Экономика |
| TO-BE процесс | `/api/audits/to_be` | 08 Вариант автоматизации |
| Пояснение вывода | `/api/audits/explain` | Level 2 «почему» |
| Evidence | `/api/evidence/{sha}` | Level 3 доказательство |
| Автономия A0–A4 + 3 контракта | `contracts/emitter.py` | 06 Безопасность, 09 Решение (эмит) |
| PDF-отчёт | `POST /api/report` | выгрузка руководству |

**Вывод:** ~70% воронки — переупаковка этих вызовов в бизнес-CJM. Диагноз, карта, ROI, TO-BE, контракты, автономия — всё считается движком LUDA (доказательно, не LLM-догадка).

## 2. Аллокация экранов брифа → LUDA (reuse / new)

| Экран | CJM | Данные (LUDA) | Работа |
|---|---|---|---|
| 01 Мои процессы | вход | `GET /api/audits` (список) | **new UI** — портфель процессов (не список аудитов) |
| 02 Новый процесс | описание | `POST /api/upload` + **new** текст-intake | доработать: приём описанием словами, не только файлом |
| 03 Карта процесса | понимание | `/api/audits/diagram` | **reuse** — обернуть в «да, это мой процесс» + правка |
| 04 Анализ | discovery | `/api/audits/run` + `placement` | **reuse** — подсветка ✓/⚠/○/🔒 по участкам |
| 05 Что AI может | capability | `CapabilityRequest` + `placement` | **new UI** — таблица этап×AI/человек бизнес-языком |
| 06 Безопасность | safety | `DeploymentContract` (autonomy/HITL/residency) | **new UI** — границы ответственности (не security dashboard) |
| 07 Экономика | economics | `/api/audits/roi` + `BaselineMeasurement` | **reuse** — baseline→эффект→окупаемость |
| 08 Вариант (Blueprint) | design | `/api/audits/to_be` | **reuse (read-only превью)**; правка → канва ABOP |

Итого нового UI-слоя: экраны 01/05/06/09 + текст-intake в 02. Остальное — обёртка существующих вызовов в бизнес-подачу.

## 3. Что дописать (фичи, сверх reuse)

1. **Текст-intake (02):** приём процесса описанием словами (не только файл) → в тот же аудит-пайплайн. Малое расширение `/api/upload` или новый `POST /api/process/describe`.
2. **Бизнес-слой поверх аудита (04–07):** перевод LUDA-артефактов в человеческие экраны. Таблица `user-facing ↔ technical` — §4. Чисто UI + маппинг, движок не трогаем.
3. **Autonomy UX (06):** «Самостоятельность AI: средняя» вместо `A2/L2`, раскрытие «почему» (обратимость/наблюдаемость/критичность) из `explain`.
4. **Decision-карточка (09):** сводка (что берёт AI · автономия · безопасность · экономия · ограничения) + CTA «Запустить пилот» → `emit_contracts` → бандл в ABOP (Contract Ingress, SDD §4).
5. **Экран результата (11, замыкание):** baseline vs факт — факт из ABOP через **обратную петлю** (`abop.run_metrics/1.0`, SDD §4-bis). Новый экран + приём RunMetrics.
6. **Progressive disclosure L1/L2/L3:** техартефакты (контракты/Evidence/LUDA internals) за «Подробнее».
7. **Редизайн под ABOP DS:** токены/бренд Эйп/glass/семафор (общая родословная MIRA v3 — унификация, не переверстка). SSO Keycloak уже общий.

## 5. Гардрейлы (критично)

- **Цифры экономики/автономии — из движка, не из LLM.** «68% / 4 из 6 / 47ч» рождаются из `roi` + `BaselineMeasurement` + `placement` (доказательно, аудируемо). LLM только формулирует, не считает. Соблюдает «не строить магический автоподбор» + анти-галлюцинацию.
- **Карта процесса (03) — точка доверия.** Показывать как гипотезу с правкой владельцем («да, это мой процесс» / «поправить»), не «AI всё понял».
- **Доказательность для эксперта.** Любой бизнес-вывод раскрывается до контракта/Evidence (Level 3) — просто для владельца, защищаемо перед CISO/CFO.

## 6. Порядок реализации

**Волна 1 — переупаковка (дёшево, движок есть):** 01 портфель · 03 карта-обёртка · 04 анализ-подсветка · 07 экономика-обёртка · 08 Blueprint-превью. Прогонять существующие эндпоинты в бизнес-подаче.
**Волна 2 — новый UI-слой:** 05 «Что AI может» · 06 Безопасность + Autonomy UX · 09 Decision-карточка + эмит контрактов.
**Волна 3 — intake + замыкание:** текст-intake (02) · экран результата (11) + приём RunMetrics (обратная петля).
**Волна 4 — полировка:** редизайн под ABOP DS · progressive disclosure L1/L2/L3 · 2-мин тест воронки (порог ≥7/10).

## 7. Открытые вопросы
1. Текущий UI LUDA (React/vanilla?) — переиспользовать компоненты или новый shell под ABOP DS.
2. Текст-intake: LLM строит карту процесса из описания — насколько доказуемо vs из документа (гардрейл: гипотеза+правка).
3. Портфель «Мои процессы» — новая сущность Process над аудитами, или аудит = процесс.
4. Приём RunMetrics в LUDA — новый эндпоинт + валидация схемы `abop.run_metrics/1.0`.
