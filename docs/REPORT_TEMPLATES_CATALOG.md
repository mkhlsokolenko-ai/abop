# Шаблоны навыков и отчёты ABOP: что есть сейчас и на чём проектировать новое

> **Что это.** Справочник по тому, из чего собирается документ ABOP: что навык умеет отдать (это и
> есть материал вёрстки), какие блоки документа существуют, какими токенами оформление
> располагает и в каких технических рамках живёт PDF. Разделы 5–6 описывают систему оформления,
> переписанную 06.10.2026, и что именно в ней было не так до этого. Раздел 9 — каталог всех 55
> шаблонов навыков; он пересобирается скриптом `ops/gen_report_catalog.py`.
>
> Составлено 06.10.2026 по исходникам: `skills/*/template.json`, `reports/*.html`, `reports/index.json`,
> `reports/base.css`, `server/report_form.py`, `server/report_compose.py`, `server/report_store.py`.

---

## 1. Путь от задачи до документа

```
задача словами
   ↓  планировщик по контрактам
навык 1 → навык 2 → … → report-editor
   ↓  у каждого навыка template.json: instruction + json_schema
result.skill_outputs[].structured        ← СТРОГО типизированные поля, слой 1
   ↓  web_api._report_context
контекст отчёта: {{title}} {{findings}} {{charts}} {{skills}} …    ← слой 2
   ↓  выбор формы: названная человеком / раскладка report-editor /
      сшивка бланков вертикалей / форма по виду результата
раскладка документа: head, stamp, attrs, verdict, kpi, prose, …    ← слой 3
   ↓  server/report_form.render → HTML + reports/base.css           ← слой 4
HTML  →  Gotenberg (Chromium)  →  PDF
```

Четыре слоя стоит держать в голове раздельно: **материал** (слой 1) система уже даёт качественный и
типизированный; **раскладка** (слой 3) описана декларативно и правится без кода; плохо выглядит
именно **слой 4** — одежда. Это хорошая новость для редизайна: менять придётся в основном CSS и
набор блоков, а не добывать данные.

## 2. Слой 1 — шаблон навыка (`skills/<id>/template.json`)

Пять ключей, из которых вёрстку интересуют два последних:

| ключ | что задаёт | кто читает |
|---|---|---|
| `name` | как навык называется в отчёте и в интерфейсе | заголовки разделов |
| `instruction` | что именно модель обязана сделать и чего не выдумывать | прогон |
| `json_schema` | **строгая схема результата**: поля, типы, наборы значений, обязательность | прогон (structured output) и вёрстка |
| `inputs` | откуда берётся материал: `data` (сущность Data Plane), `skill` (выход предыдущего навыка), `context` (текст задачи) | планировщик и прогон |
| `produces` | что навык отдаёт в цепочку: путь, ключ, тип связи | планировщик (сцепка по контрактам) |
| `max_tokens` | потолок ответа (у 47 из 55; от 900 до 7000) | прогон |
| `delivery` | куда результат уходит наружу (у 6 навыков) | HITL и коннектор |

**Главное для дизайнера:** `json_schema` — это и есть доступные поля документа. Там уже есть
ранги (`критично/существенно/умеренно/формально`), вердикты, суммы, ссылки на документы,
хронологии, таблицы. Выдумать значение вёрстка не может: блок, сославшийся на несуществующее поле,
рендерится пустым (а графа реквизитов — со словом «не указано»).

## 3. Слой 2 — контекст отчёта (плейсхолдеры)

Готовит `web_api._report_context`. Доступны в любом HTML-шаблоне формы:

| плейсхолдер | что внутри | где используется |
|---|---|---|
| `{{title}}`, `{{agent}}`, `{{date}}` | шапка: вид документа, агент, дата | 24 формы |
| `{{verdict}}` | вердикт прогона строкой | default, audit1c |
| `{{findings}}`, `{{findings_total}}`, `{{by_class}}` | находки, их число, разбивка по классам A/B/C/D | default, audit1c |
| `{{investigations}}`, `{{investigations_total}}` | расследования от симптома | invest |
| `{{charts}}` | графики — **готовый инлайновый SVG** (`server/charts.py`: bar, line, pie) | 4 формы |
| `{{skills}}` | структурированные ответы ВСЕХ навыков таблицами и списками | 3 формы |
| `{{skill_<sid>}}` | ответ конкретного навыка (дефисы → подчёркивания: `{{skill_audit1c_rank}}`) | audit1c, invest |
| `{{sources}}` | на чём стоял прогон: сущности, документы по ссылке, вложения | letter, audit1c |
| `{{requisites}}` | служебные реквизиты прогона | 4 формы |
| `{{deliveries}}` | что ушло наружу и по чьему подтверждению | 25 форм |
| `{{tool_usage}}`, `{{schema_notes}}` | вызовы инструментов, замечания по схемам | 25 форм |
| `{{blank}}` | **весь документ, собранный раскладкой** | 21 форма |
| `{{css}}`, `{{footer}}`, `{{service}}` | стиль, подвал, служебная таблица | 25 форм |
| `{{разметка}}`, `{{разметка_сводка}}` | экспертная разметка находок пилота (точность, «вручную бы не нашли») | audit1c |

Пустой плейсхолдер рендерится пустотой — раздела в документе просто не будет.

## 4. Слой 3 — раскладка документа (блоки)

Форма вертикали — это одна строка HTML (`{{blank}}`) плюс служебные блоки, а весь документ задан
**раскладкой**: массив блоков в `index.json` → колонка `layout JSONB` в таблице `report_templates`.
Правится в вебе без кода. Рендерер — `server/report_form.py`.

| блок | что даёт | поля блока | CSS-класс |
|---|---|---|---|
| `head` | шапка: вид документа, происхождение, объём работы, метод | `title`, `sub`, `meta[[подпись, ссылка]]`, `ctx[ключи]`, `note` | `.ahd`, `.req` |
| `part` | разделитель части сшитого документа | `title`, `sub` | `.part` |
| `stamp` | угловой штамп письма (кому, тема, цель) | `rows[[подпись, ссылка]]` | `.stamp` |
| `attrs` | таблица реквизитов; пустая графа остаётся со словом «не указано» | `title`, `rows` | `.at` |
| `verdict` | решение документа: бейдж, значение, основание, условия | `src`, `badge`, `badge_label`, `why`, `meta` | `.vb` (+`.ok/.warn/.no`) |
| `kpi` | показатели плашками | `title`, `rows` | `.kpis`, `.kpi` |
| `prose` | раздел связным текстом, абзацы сохраняются | `title`, `src` | `.prose` |
| `list` | перечень | `title`, `src`, `field` | `.lst` |
| `cards` | пункты карточками с подписанными графами | `src`, `head`, `badge`, `badge_label`, `code`, `group`, `graphs[[подпись, графа]]`, `filter` | `.ac`, `.ac-h`, `.ac-f` |
| `register` | реестр: объявленные колонки в объявленном порядке (до 60 строк, остальное счётчиком) | `src`, `cols[[подпись, графа]]`, `note` | `.tbl` |
| `pre` | исходник как есть: код схемы, фрагмент OpenAPI, диаграмма как код | `title`, `src` | `pre.code` |
| `sign` | подписи: кто подготовил, кто проверил, кто утверждает | `rows[подписи]` | `.sign` |
| `note` | оговорка: чего документ НЕ заменяет | `text` | `.meth` |
| `ctx` | готовая врезка из контекста (`charts`, `skills`, `sources`) | `key` | — |

**Ссылки на поля** (`src`, `badge`, `why`, графы в `cols`/`graphs`):

* `заявка.запрошенная_сумма` — путь в структуре; берётся у первого навыка, который поле заполнил;
* `limit_policy_enforcement:вердикт` — только у названного навыка;
* `критичность|ценность|срочность` — альтернативы: одну графу документа разные навыки группы
  называют по-своему;
* в `cols`/`graphs`/`head`/`badge`/`code` указывается **графа элемента массива**, а не путь в корне.

**Как выбирается форма прогона** (`web_api._template_for_run`), по убыванию приоритета:

1. форма, названную человеком или OUT-узлом (`report_template_id`);
2. раскладка, собранная навыком `report-editor` в этом прогоне, — если прошла проверку (негодную
   отбрасывают и говорят об этом в замечаниях, а не собирают документ наугад);
3. раскладка из кэша для того же набора навыков (модель не вызывается повторно);
4. бланк вертикали, если все навыки прогона из одной;
5. **сшивка**: раздел каждого навыка из его бланка, в порядке выполнения, — когда навыки из разных
   вертикалей;
6. форма по виду результата: `invest` → `audit1c` → `digest` → `default`.

## 5. Слой 4 — оформление: система токенов

Переписано 06.10.2026. Источник правды — `reports/base.css`; запасной вариант в
`server/report_store.py` короткий и намеренно не копия (копия через месяц разошлась бы и начала
красить отчёты по-своему).

### Токены

| группа | токены | значения |
|---|---|---|
| **Гарнитуры** | `--font`, `--mono` | `Noto Sans` → Segoe UI → Liberation Sans → Arial; `DejaVu Sans Mono` → Consolas |
| **Поверхности** | `--paper`, `--fill`, `--fill-2` | `#fff` лист · `#f6f7fa` шапка таблицы · `#fafbfc` чётная строка |
| **Текст** | `--ink`, `--ink-2`, `--ink-3` | `#16191f` основной · `#454b58` пояснения · `#737a89` подписи граф |
| **Линии** | `--line`, `--line-2`, `--rule` | `#d7dbe3` рамка · `#eceef3` тонкий разделитель · `--rule` = `var(--ink)` |
| **Акцент** | `--accent`, `--accent-soft` | `#2f4b7c` · `#eef1f7` — один на весь документ |
| **Состояния** | `--bad`, `--warn`, `--mid`, `--info`, `--ok` | `#b3261e` критично/класс A/отказ · `#a2590b` существенно/B/с условиями · `#8a6d1f` умеренно/C · `#1f5f8b` формально/D/справочно · `#1a7f4b` пройдено |
| **Кегли** | `--t-cap` … `--t-2xl` | 10.5 · 12 · 13.5 · 16 · 19 · 23 px — шесть ступеней, больше нет |
| **Отступы** | `--s-1` … `--s-6` | 4 · 8 · 12 · 16 · 24 · 32 px |
| **Прочее** | `--lh`, `--lh-tight`, `--tracking` | 1.55 · 1.3 · .055em (разрядка прописных подписей) |

Три правила, вынесенные в тест `tests/test_report_css_tokens.py`, чтобы их нельзя было нарушить
незаметно: **цвет только через токен** (литералов в правилах нет), **селектор объявляется один раз**,
**кегль берётся из шкалы**. Там же проверяется, что первая гарнитура в стопке физически есть в
рендерере PDF и что правила печати на месте.

### Решения оформления и причины

* **Прямые углы.** Это служебный документ, а не карточка приложения: его подшивают и подписывают.
  Радиусы остались только у бейджей — и те нулевые.
* **Цвет несёт смысл или не появляется.** Акцент — на правилах и ссылках; четыре состояния — на
  существенности находок и виде решения. Один смысл — один токен: класс A в бейдже, «критично» в
  карточке, столбец A на графике и левая кромка строки находки красятся одним `--bad`.
* **Подпись графы — один приём на весь документ:** прописные, разрядка `--tracking`, третий тон.
  Так выглядят графы реквизитов, штампа письма, плашек показателей и бейджей — глазу не нужно
  заново учиться читать каждый блок.
* **Цифры моноширинные** (`font-variant-numeric: tabular-nums`) во всех таблицах, плашках и
  значениях решения: колонка сумм — то, по чему документ просматривают.
* **Реквизиты шапки — сеткой**, подпись над значением. Строкой через точку длинные значения рвались
  посреди слова, и шапка читалась как случайный абзац.

### Что доступно в PDF

Проверено 06.10 на рендерере прода: пробный документ с двенадцатью семействами, в PDF вернулись пять —
`Liberation Sans`, `Liberation Serif`, `DejaVu Sans`, `DejaVu Sans Mono`, `Noto Sans`. Поэтому в
`--font` первым стоит Noto Sans: веб-превью и PDF теперь показывают одно и то же. Если понадобится
своя гарнитура — только встраиванием `@font-face` с base64: внешние ресурсы рендерер не загружает.

## 6. Что было не так — и что с этим сделано

| было | почему это портило документ | стало |
|---|---|---|
| 35 хексов на 60 строк, две палитры рядом | карточка находки индиго, таблица реквизитов серая — на одной странице | один набор токенов, тест запрещает литералы |
| 16 кеглей, разница в 0.5 px | заголовок раздела почти равен тексту абзаца, страница читается сплошняком | шесть ступеней, тест ограничивает шкалу |
| `body`, `.tbl`, `.kv`, `.sev` объявлены по 2–3 раза | побеждало правило, стоящее ниже в файле, а не замысел | один селектор — одно правило, проверяется тестом |
| три набора статусных цветов | «критично» и «отказ» — разные красные | четыре токена состояния на весь документ |
| `Segoe UI` в вёрстке | в PDF подменялся Liberation Sans: превью и PDF расходились | гарнитура из списка доступных в рендерере |
| `printBackground` выключен | заливки шапок и бейджи в PDF **не печатались**: белый текст бейджа на белом листе | включён явно |
| поля листа брал рендерер | `@page` при печати через CDP не применяется — документ шёл под обрез | поля заданы явно: 18 мм сверху, 16 по бокам, 15 снизу |
| нумерации страниц не было | отчёт на 17 страниц нечем обсуждать по телефону | колонтитул Gotenberg: имя документа слева, «стр. N из M» справа |
| шапка таблицы не повторялась | вторая половина реестра — колонки без названий | `thead` + `display:table-header-group` |
| реестр чисел печатался карточками | три периода P&L по 11 граф → три карточки по 11 строк, периоды не сравнить | оценка по графам: графа-абзац → карточки, числа → таблица |
| широкий реестр уезжал за край | последняя колонка просто не попадала в PDF | отдельный вид для таблиц от семи граф, отрезанные графы названы вслух |
| графики жили своей жизнью | насыщенный индиго и алый, скруглённые столбцы в пол-страницы, заголовок крупнее заголовка раздела | те же токены, та же гарнитура, холст по пропорции полосы |
| график из одного столбца | число, которому нарисовали прямоугольник на пол-страницы | не рисуется |
| «Находок 0 · Расследований 0» | два огромных нуля говорят противоположное тому, что было в прогоне | печатаются только непустые счётчики |
| в форме аудита две шапки подряд | реквизиты сверху + собственный заголовок документа | одна шапка, служебная отметка внизу |
| документ без заголовка и подписей | раскладка редактора ссылалась на выдуманные поля: 11 блоков из 19 пустые → запасной путь без рамки | раскладка проверяется на разрешимость ссылок (и из кэша тоже), запасной путь сохраняет рамку |

Проверено на живом прогоне «сводка по подрядчикам» (7 навыков): **22 страницы → 17**, появились
заголовок, строка источника данных, подписи и нумерация, реестры стали таблицами.

## 7. Рамки, в которых живёт оформление

| ограничение | что это значит для вёрстки |
|---|---|
| **Рендерер — Gotenberg (Chromium), HTML одним файлом** | современный CSS можно (grid, flex, `break-inside`), внешние ресурсы — нельзя: шрифты и картинки только инлайном/base64 |
| **Пять доступных гарнитур** | работаем в них либо встраиваем свою base64 |
| **Поля и колонтитул задаёт рендерер**, а не `@page` | правятся в `cli/ape.py` (`_PDF_FIELDS`, `_PDF_FOOTER`), а не в CSS |
| **Один CSS на все 25 форм** | новый вид вводится токеном и компонентом, а не стилем «под эту форму» |
| **Раскладка правится в вебе, HTML формы — нет** | новый смысловой блок вводится типом блока в `report_form._BLOCKS`, иначе его нельзя будет поставить в документ |
| **Реестр показывает максимум 60 строк и 12 граф** | обрезанное называется вслух счётчиком, а не прячется |
| **Значения берутся только из `json_schema` навыков** | графа, которой нет в схеме, останется пустой навсегда; вместе с макетом правится схема навыка |
| **Документ подписывает человек** | блок подписей и оговорка «чего документ не заменяет» обязательны в бланках вертикалей |

### Как посмотреть результат

```bash
python ops/render_report_samples.py --png          # все 25 форм: HTML + картинки
python ops/render_report_samples.py --only credit,audit1c,letter
```

Образцы собираются по `json_schema` навыков формы — данные стенда не нужны, и видно именно
устройство документа. Картинки кладутся рядом в `build/report_samples/`.

## 8. Что осталось

* **Бланки под оставшиеся вертикали.** 21 форма из 25 имеет раскладку; `default`, `digest`,
  `audit1c` и `invest` — формы старого типа, где разделы свёрстаны плейсхолдерами в HTML. Для
  `audit1c` это осознанно (форма согласована с заказчиком), для `default` и `digest` — долг.
* **Прогоны без бланка.** Когда ни у одного навыка прогона нет вертикальной формы, документ
  собирается перечислением разделов навыков. Рамка у него теперь есть, но порядок разделов —
  порядок исполнения, а не логика чтения.
* **Качество раскладок редактора.** Проверка разрешимости отсекает выдуманные поля, но сам редактор
  пока часто их выдумывает — это задача к промпту навыка `report-editor`, а не к оформлению.
* **Своя гарнитура.** Noto Sans — лучшее из доступного, но не выбор дизайнера. Встраивание
  base64-шрифта даст полную свободу ценой ~200 КБ на документ.

## 9. Каталог шаблонов навыков
