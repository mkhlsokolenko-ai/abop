# Демо-прогон: первый агент «Сверщик оплат» (кейс 1С-сверка) — step by step

Пошаговая сборка и запуск первого агента на реальных данных, с фиксацией результата каждого шага.
Кейс: заказчик **ООО «Ветер»**, договор **ДОГ-2026-042**; менеджер не откатил скидку → расхождения оплат.
Этот сценарий — эталон и **основа интерактивного онбординга** (создание первого агента по шагам).

Данные-источники: MinIO S3 (`abop-demo/1c/`) + BookStack (договор) + Mailpit + Twenty. Сервер ABOP :8091.

---

## Шаг 1 — Коннектор к источнику (база оплат 1С в MinIO S3)

**Действие:** Данные → Коннекторы → ＋ подключить → адаптер `REST API`, URL `http://5.129.192.63:9000/abop-demo/1c/payments.json` → Тест-прогон.

**Результат (факт):**
```
Коннектор создан: adapter=http
Тест: доступно=True · строк=5 · поля=[id, invoice_id, amount, date]
```
✓ Розетка работает, discovery увидел реальные поля источника.

---

## Шаг 2 — Рецепты (сырьё → канонические сущности)

**Действие:** Данные → Рецепты → для каждого источника: адаптер+URL → Проверить → Сохранить → (публикация = run в canonical store).

**Результат (факт):**
```
рецепт payments      preview: записано=5 отброшено=0 | run → transaction: 5 записей
рецепт payment_docs  preview: записано=3 отброшено=0 | run → document: 3 записей
рецепт invoices      preview: записано=5 отброшено=0 | run → transaction: 5 записей
```
✓ В canonical store: `transaction` = 10 (оплаты+счета), `document` = 3 (документы об оплате). Каждая запись с provenance/ttl.

---

## Шаг 3 — Навык-сверщик и его источники (data-need)

**Действие:** Навыки → «Ledger Reconciliation» → блок «Источники данных».

**Результат (факт):**
```
навык «Ledger Reconciliation»: источники = [(transaction → рецепт invoices), (document → рецепт contracts)]
```
✓ Навык привязан к сущностям `transaction`+`document`; оператор может править data-need (сущности/поля) прямо в drawer.

---

## Шаг 4 — Сборка агента (роль семьи + навыки)

**Действие:** Граф → палитра «Роли (семьи)» → перетащить «Бухгалтерия / закрытие» (семья Финансы) на холст. (Через API: `POST /api/agents/author {family:finance, member:accounting}`.)

**Результат (факт):**
```
агент собран: id=authored.v1 · роль=accounting
навыки=[ledger_reconciliation, period_close_orchestration, variance_explanation]
автономия=A2
```
✓ Агент = роль «Бухгалтерия/закрытие» + 3 навыка. Появляется в экране Агенты (В работе).

---

## Шаг 5 — Паспорт / конверт безопасности

**Действие:** экран Агенты → клик по карточке агента → drawer (или линза «Конверт»).

**Результат (факт):**
```
конверт: mode=write · egress=internal · cite=True · автономия=A2
data-scope: [(transaction → invoices), (document → contracts)]
переходы become (роли той же семьи): [fp-and-a, valuation, controller]
```
✓ Агент читает/пишет в периметре (наружу не ходит), числа только из источника; автономия A2; может «переобуться» в смежные роли Финансов.

---

## Шаг 6 — Запуск (LLM-прогон на реальных данных → находки)

**Действие:** [Запустить] (линза «Запускаю») или `POST /api/runs {agent_id}`.

**Результат (факт):**
```
прогон OK · run_id=run-authored.v1-001 · волн=1 · вердикт=✓ · автономия A2 ≤ конверт · HITL-гейтов=0
```

**Находки агента (реальный анализ данных навыком period_close_orchestration):**
> **Расхождение: PAY-1003 vs INV-003** — платёж 200 000 ₽ меньше счёта-фактуры 250 000 ₽ на **50 000 ₽** (недоплата).

Навык `variance_explanation` — план-факт анализ по инвойсам/платежам.
Навык `ledger_reconciliation` — при недоступности LLM (каскад RouteAI) честно помечает «LLM недоступен» и **не выдумывает** цифр (анти-галлюцинация ADR-016).

✓ Агент прочитал canonical store через `data_query`, применил методику навыка через LLM (qwen3-30b) и **нашёл реальное расхождение** с привязкой к id и суммам.

---

## Итог цепочки (что с чем связано)

```
MinIO S3 (payments/docs/invoices)
   → КОННЕКТОР (http) → РЕЦЕПТ → СУЩНОСТЬ transaction/document (canonical store)
   → НАВЫК ledger_reconciliation (data_query по transaction+document)
   → АГЕНТ «Сверщик оплат» (роль Бухгалтерия + навыки, конверт A2/write/cite)
   → ПРОГОН волнами → аудитор (DoD ✓) → НАХОДКИ (недоплата PAY-1003 −50 000 ₽)
```

## Настройки прогона (env)
- `ABOP_RUN_LLM_CONCURRENCY=2` — батч одновременных LLM-вызовов (rate-limit к RouteAI).
- `ABOP_RUN_LLM_TRUNCATE=1` (dev, обрезка промптов; max_tokens=1600) → **на проде 0** (полные).

## Этот сценарий → онбординг
Шаги 1–6 = сценарий интерактивного онбординга «Создай первого агента»: при первом входе пользователь проходит их по очереди с подсказками, получая рабочего агента и первую находку.
