# ABOP — Дизайн-исследование и UI/UX kit

**Назначение:** передать дизайнеру полную базу для отрисовки среды ABOP — что берём у конкурентов, что переиспользуем из готовой дизайн-системы LUDA (MIRA v3), какой у ABOP собственный бренд (маскот Эйп), и полный набор элементов (палитра, типографика, кнопки, бары, спиннеры, состояния).
**Артефакты:** брендкит — `docs/brand/ABOP_Brand_Kit.dc.html` (логотип, маскот Эйп, мотив-кит ожидания). Продукт — `ABOP_PRD.md` (v1.1, среда разработки). Дизайн-система-источник — LUDA MIRA v3.
**Статус:** v1.0, к работе дизайнера.

---

## 0. Главный вывод за 30 секунд

- **У ABOP уже есть собственный бренд** (брендкит: dark-first, индиго→фиолет градиент, маскот Эйп, богатый «язык ожидания»). Это НЕ палитра LUDA (navy/teal) — у ABOP своя идентичность.
- **Структуру, компоненты и дисциплину — берём из LUDA MIRA v3** (сетка, Card/Badge/Button, вкладки-маршрут, канва, пульт, паспорт, WCAG-дисциплина, buildless-стек). Перекрашиваем в бренд ABOP.
- **У конкурентов заимствуем 4 паттерна** (по убыванию ценности): permission-scoping видимо в UI (DeepSeek), real-time canvas прогона (OpenClaw), side-by-side preview + streaming (Hermes), HITL-oversight экран (Magentic-UI).
- **Наша слабость** — у нас пока НЕТ ни одного экрана среды (только CLI); сильная сторона — governance/безопасность/аудит уже в ядре, конкуренты это только начинают.

## 1. Что сильно у конкурентов, а у нас слабо (честные пробелы)

| Конкурент | Их сила | Наш пробел |
|---|---|---|
| **Hermes** (Nous Research) | Зрелые клиенты: React/Ink TUI + Electron desktop; **streaming tool output**, **side-by-side preview pane**, file browser, slash-autocomplete, interrupt/redirect | У нас только CLI-REPL с ANSI-рендером; нет desktop/веб-клиента, нет живого стрима вывода инструмента в UI |
| **OpenClaw** | **Real-time canvas** для динамической визуализации; полная 7-компонентная схема (gateway/runtime/skill/memory/nodes) как продукт с UI; мульти-канальность | У нас архитектура та же, но **нет визуального канваса прогона**; всё в тексте терминала |
| **DeepSeek Harness** | **Permission-scoping прямо в settings-UI** (read-only → full), per-task model swap, plugins toggle — управление безопасностью и составом наглядно | У нас безопасность навыка (`mode/egress/cite`) есть в ядре, но **не показана в UI** — оператор её не видит и не крутит |
| **Magentic-UI / OrchVis** | HITL как **первоклассный экран** с иерархическим oversight мультиагентов | У нас HITL есть в логике (dry_run), но **нет пульта оператора** как экрана |

**Вывод:** наш пробел — не архитектура (она сильнее многих), а **отсутствие визуального слоя**. Конкуренты обогнали нас в UI-зрелости, но у них слабее governance/аудит/конверт — а это наш ров.

Источники: [Hermes docs](https://hermes-agent.nousresearch.com/docs/), [Hermes ui-tui](https://github.com/NousResearch/hermes-agent/tree/main/ui-tui), [OpenClaw / Open WebUI](https://docs.openwebui.com/getting-started/quick-start/connect-an-agent/openclaw/), [DeepSeek Harness](https://www.mindstudio.ai/blog/deepseek-harness-agentic-coding), [Magentic-UI](https://arxiv.org/pdf/2507.22358), [OrchVis](https://arxiv.org/pdf/2510.24937).

## 2. Что сильно в дизайне LUDA vs конкуренты (наши козыри)

LUDA MIRA v3 (боевая дизайн-система, трек R0→R10 задеплоен, аудит 5.4→фикс) даёт то, чего у конкурентов НЕТ:

1. **Дисциплина токенов и семафора.** Один семантический семафор `--st-*` (не россыпь vivid-hex), WCAG AA ≥4.5:1 на обеих темах. У конкурентов (особенно чат-ориентированных) — вольный визуал.
2. **Внятный маршрут вместо чата.** Вкладки-маршрут (Обзор→Аудит→Сборка→Канва→Пульт→Агенты→Коннекторы), крошки, `⌘K`-палитра. Конкуренты живут в чат-ленте (Open WebUI) — а среде разработки нужен маршрут.
3. **Готовые сложные экраны:** канва сборки (drag-and-drop, палитра-каталог, LLM-черновик потока), паспорт агента (verified envelope), Пульт HITL (оптимистичные Разрешить/Отклонить + undo). Это ровно то, что конкуренты только нащупывают.
4. **Governance наглядно** (конверт, гейт детерминирован). Ни у кого из троих нет «конверта безопасности» как видимой сущности.
5. **Buildless-стек** (React UMD + Babel, вендоренные файлы) — работает в закрытом периметре без сборки/CDN. Критично для ФСТЭК/ДСП.

**Итого:** по governance-UI, дисциплине и готовым экранам LUDA впереди. Отстаём только в «живости» (стрим/canvas) — это и заимствуем.

## 3. Подходы всех 3 конкурентов: UI/UX и user-flow

| | Hermes | OpenClaw | DeepSeek Harness |
|---|---|---|---|
| **Форм-фактор** | TUI + Electron desktop + мессенджеры | Runtime + Open WebUI (чат) + мульти-канал | Плагин-харнесс поверх редактора/агентов |
| **Основной UX** | Терминал-first, стрим tool-вывода, preview-pane | Чат-first + real-time canvas | Settings-first: тумблеры плагинов, скоуп прав, свап моделей |
| **User-flow** | пиши → агент стримит шаги → preview → правь | сообщение → агент рендерит canvas → канал | сконфигурь права/плагины → делегируй под-агентам → композиция |
| **Сила** | живость, интеррапты, preview | визуализация, каналы | наглядное управление безопасностью/составом |
| **Слабость для нас** | чат-центричность, нет governance | нет конверта/аудита | нет ролей-семей, нет памяти-конверта |

**Общий паттерн троих:** все ушли от «чёрного ящика» к **наблюдаемому исполнению** (стрим шагов, canvas, permission-видимость). Это ровно то, что просит governance-периметр — и это мы усиливаем конвертом.

## 4. Ранжирование находок по ценности для пользователя

От самой ценной (внедрять первой) до бесполезной для нас:

| # | Находка | Откуда | Ценность | Почему |
|---|---|---|---|---|
| **1** | **Permission-scoping видимо в UI** (mode/egress/cite на навыке, слайдер прав) | DeepSeek + наша канва СВОД | 🟢🟢🟢 максимум | Прямо усиливает наш ров (конверт); оператор видит и крутит безопасность — это продающая наглядность |
| **2** | **Real-time canvas прогона** (волны/доска/эстафеты живьём) | OpenClaw + брендкит (мотив-волны) | 🟢🟢🟢 | Снимает «чёрный ящик»; брендкит УЖЕ рисует волны/эстафету/скан как язык ожидания |
| **3** | **HITL-пульт как экран** (dry_run→approve, очередь) | Magentic-UI + LUDA Пульт | 🟢🟢🟢 | Точка контроля = точка ценности в регулируемом периметре; у нас логика есть, нужен экран |
| **4** | **Streaming tool output + side-by-side preview** | Hermes | 🟢🟢 | Живость исполнения; preview-pane для рецептов данных/артефактов |
| **5** | **Slash-autocomplete / ⌘K-палитра** | Hermes + LUDA | 🟢🟢 | Скорость для power-user; у LUDA уже есть `⌘K` |
| **6** | **Per-task model swap** (модель на узел/задачу) | DeepSeek | 🟢 | У нас есть per-node модель в ядре — просто показать в канве |
| **7** | **Мульти-канальность** (Telegram/WhatsApp/Discord) | Hermes/OpenClaw | 🔴 не берём | ABOP — среда разработки в периметре, не мессенджер-бот; egress наружу под запретом |
| **8** | **Voice input/output** | Hermes/OpenClaw | 🔴 не берём | Нерелевантно для аудируемой среды; голос неаудируем |
| **9** | **Self-improving / agent-created skills на лету** | Hermes | 🔴 осторожно | Конфликтует с нашим «навык декларативен + аудит»; авто-генерация навыков ломает конверт |

**Правило отбора:** берём то, что усиливает наблюдаемость и конверт (#1–5); отбрасываем то, что открывает периметр или ломает аудируемость (#7–9).

## 5. Сравнение дизайн-подходов и UX (свод)

- **Визуальный тон:** конкуренты — либо аскетичный терминал (Hermes), либо яркий чат (Open WebUI). LUDA — строгий internal-audit-grade. **ABOP-бренд** — dark-first «командный центр» с индиго-фиолет градиентом и glassmorphism-панелями: серьёзнее чата, теплее голого терминала. Это верный тон для «оператор среды следит за прогонами».
- **Модель внимания:** брендкит формулирует прямо — «одно внимание за раз» (у маскота один визор). Это анти-паттерн к перегруженным мультиагентным дашбордам конкурентов. **Берём:** фокус на одном активном прогоне, остальное — свёрнуто.
- **Ожидание как язык:** уникальная сила брендкита ABOP — семантические лоадеры (волны=прогон, эстафета=handoff, скан=аудитор). У конкурентов ожидание — обычный спиннер. **Это наш дифференциатор UX.**
- **Governance-видимость:** только у нас конверт/аудитор/DoD — визуализируемая сущность. Дизайн обязан сделать её центральной, а не спрятать в настройки.

## 6. UI/UX kit — спецификация для дизайнера

> Источник бренда — `docs/brand/ABOP_Brand_Kit.dc.html`. Источник структуры/компонентов — LUDA MIRA v3. Ниже — сведённые токены и элементы.

### 6.1. Палитра (бренд ABOP, dark-first)

```
/* Фон и поверхности (dark-first) */
--bg:            #0F172A;   /* slate-900, основной фон */
--bg-grad:       radial-gradient(60% 50% at 12% 0%, rgba(99,102,241,.18), transparent 70%),
                 radial-gradient(50% 45% at 92% 8%, rgba(139,92,246,.16), transparent 70%);
--surface:       rgba(255,255,255,.05);   /* стекло: панель */
--surface-line:  rgba(255,255,255,.10);   /* граница стекла */
--surface-blur:  16px;                     /* backdrop-filter */

/* Бренд-акцент (primary) — индиго → фиолет */
--brand-grad:    linear-gradient(135deg, #6366F1, #8B5CF6);
--brand:         #6366F1;   /* indigo-500, solid primary */
--brand-hover:   #4F46E5;   /* indigo-600 */
--brand-press:   #4338CA;   /* indigo-700 */
--brand-100:     #C7D2FE;   --brand-300: #A5B4FC;   --brand-400: #818CF8;  /* светлые/ссылки */
--brand-deep:    #1E1B4B;   /* indigo-950, глубокие плашки */

/* Семафор статусов (в бренд-оттенках; та же семантика, что --st-* LUDA) */
--ok:   #34D399;  --ok-strong: #10B981;  --ok-deep: #065F46;  --ok-bg: #ECFDF5;
--warn: #FBBF24;  --warn-strong:#F59E0B;  --warn-deep:#B45309;  --warn-bg:#FFFBEB;  /* HITL/ожидание */
--crit: #EF4444;  --crit-strong:#DC2626;  --crit-deep:#991B1B;  --crit-bg:#FEF2F2;  /* вне конверта */

/* Текст на dark */
--text:   #FFFFFF;
--text-2: rgba(255,255,255,.55);
--text-3: rgba(255,255,255,.40);
--text-mute: rgba(255,255,255,.35);
```

**Дисциплина (наследие LUDA):** статусы — ТОЛЬКО из семафор-токенов (`--ok/--warn/--crit`), не произвольный hex. Контраст текста на стекле проверять на WCAG AA ≥4.5:1 (glassmorphism на dark — зона риска, тестировать каждую пару).

### 6.2. Типографика

```
--font-sans: 'Inter', system-ui, sans-serif;    /* 400 / 500 / 600 / 700 / 800 */
--font-mono: 'JetBrains Mono', monospace;        /* 400 / 500 / 600 / 700 */
```
- **Inter** — весь интерфейс. H1 800/-1.6px, заголовки секций 600, тело 400–500.
- **JetBrains Mono** — «tech»-регистр: wordmark, метрики (`волна 3/5`), id/провенанс, номера секций, безопасность-пометки. Моно = «машиночитаемое/аудит».
- Микро-лейблы секций: mono 11px, uppercase, letter-spacing 1.2px, `--text-3`.

### 6.3. Радиусы, тени, стекло

```
--r-chip: 9999px;   --r-md: 12px;   --r-lg: 16px;   --r-logo: 22.5%;  /* конверт */
--panel: background var(--surface); border 1px var(--surface-line); backdrop-filter blur(16px);
```
Панели — стеклянные (glass) на фоне градиента. Карточки 16px, чипы/пилюли/кнопки-пилюли 9999px, кнопки 12px.

### 6.4. Кнопки

| Вариант | Стиль | Применение |
|---|---|---|
| **Primary** | фон `--brand-grad`, текст #fff, Inter 600 14px, padding 12×20, radius 12; при загрузке — Кольцо-спиннер слева + «Запускаю прогон» | главное действие экрана (запустить прогон, собрать) |
| **Secondary** | стекло `--surface` + border `--surface-line`, текст #fff | вторичные действия |
| **Ghost** | прозрачный, текст `--text-2` | третичные |
| **Danger** | текст/бордер `--crit`, фон `--crit-bg`-alpha | «Стоп», отклонить, вывести из конверта |
| **Пилюля-статус** | radius 9999, статусный фон/бордер (амбер для HITL с дот-анимацией, mono для tech) | «Ждёт подтверждения оператора», «data_run · выборка 500» |

Все интерактивные — видимый focus-ring (наследие LUDA WCAG); hover/active из `--brand-hover/press`.

### 6.5. Спиннеры и «язык ожидания» (уникальный дифференциатор — из брендкита)

Каждый лоадер СЕМАНТИЧЕН, не универсальный спиннер:

| Лоадер | Анимация | Где применять |
|---|---|---|
| **Кольцо** | `ab-spin` 1.1s, градиент-дуга, 20/32/60px | кнопки, инлайн-загрузка (форма ответа неизвестна) |
| **Волны** | 5 полос `ab-wave`, индиго-градиент | **только пульт прогонов** — идёт оркестрация |
| **Эстафета** | орбита `ab-orbit` с 3 точками | `handoff` между ролями |
| **Сканирование** | визор-скан `ab-scan` | долгое ожидание >3с (аудитор проверяет, `data_run` гоняет выборку) |
| **Скелетон** | `ab-shimmer` 1.6s | когда форма ответа ИЗВЕСТНА (карточка навыка, строка доски) |

**Правило:** скелетон — когда знаем форму; спиннер — когда нет; специальные (волны/эстафета/скан) — привязаны к своей механике, не использовать где попало.

### 6.6. Прогресс-бары

- **Волны прогона:** сегментированный бар «волна 3/5», подпись mono `analyst·data_query`; заполненные сегменты — `--brand`, текущий — пульс, будущие — `--surface`.
- Линейный (детерминированный %) — для `data_run`/загрузок с известным объёмом.

### 6.7. Маскот Эйп — состояния = статусы прогона

Маскот «Эйп» — оператор среды (корпус-купол + визор + маячок конверта). **Один визор = одно внимание за раз.** Маячок = статус конверта.

| Состояние | Визор/маячок | Смысл в UI |
|---|---|---|
| **Готов** (idle) | спокойные глаза, зелёный маячок | простой, ждёт задачу |
| **Думает** (wave running) | дот-анимация в визоре | идёт прогон/волна |
| **Ждёт вас** (HITL) | амбер-корпус, восклицание | нужна апрув оператора |
| **Стоп** (вне конверта) | красный, крест-глаза | нарушение автономии/конверта |
| **Закрыт** (DoD ✓) | зелёный, галочка | аудитор подтвердил, прогон закрыт |

**Чего НЕ делаем с маскотом:** нет рта, рук, пружинящих анимаций; не растягивать непропорционально. Один носитель эмоции — визор.

### 6.8. Чипы, карточки, доска (структура — из LUDA)

- **Семафор-чип** навыка: точка-цвет + подпись `mode/egress/cite` (permission-scoping видимо — находка #1). read=нейтр, write=индиго, action=амбер (HITL), external=амбер-бордер.
- **Карточка навыка/роли/семьи** (палитра канвы): стекло 16px, заголовок Inter 600, id mono, семафор-чипы безопасности.
- **Строка доски** прогона: агент·семья·роль·навык·статус (маскот-иконка состояния), провенанс mono.

| Слой | Источник | Что берём |
|---|---|---|
| **Идентичность бренда** | брендкит ABOP | палитра (индиго-фиолет dark-first), маскот Эйп, лого-конверт, мотив-кит ожидания, glassmorphism |
| **Структура и компоненты** | **LUDA MIRA v3** | сетка, Card/Badge/Button/Input/чипы, вкладки-маршрут, `⌘K`, канва сборки, паспорт агента, Пульт HITL, оптимистичные действия+undo |
| **Дисциплина** | **LUDA MIRA v3** | один семафор-источник, WCAG AA, buildless (React UMD+Babel), токены как единственный источник цвета |
| **Permission-scoping в UI** (#1) | DeepSeek + канва СВОД | видимые `mode/egress/cite` на навыке/узле, слайдер прав |
| **Real-time canvas прогона** (#2) | OpenClaw + брендкит | живые волны/эстафеты/скан на пульте |
| **HITL-пульт** (#3) | Magentic-UI + LUDA | очередь dry_run→approve как экран |
| **Streaming + preview-pane** (#4) | Hermes | стрим шагов + side-by-side предпросмотр (рецепты/артефакты) |

**Разрешение напряжения LUDA↔ABOP:** ABOP = собственный бренд (dark индиго/Эйп), но **на скелете LUDA** — переиспользуем структуру/компоненты/дисциплину, перекрашиваем в бренд ABOP, семафор сохраняем (в бренд-оттенках). Дизайнер не рисует с нуля: берёт компоненты MIRA v3 и одевает в брендкит ABOP.
