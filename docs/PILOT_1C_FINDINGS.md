# Пилот «Аудитор данных в 1С»: карточки находок, объяснение, слепая разметка

_2026-09-26. Блок 4 по порядку владельца (1 → 2 → 4 → 5 → 3). Веб `5.129.192.63:8091`, экран «Обзор» → блок «Находки 1С · журнал пилота»._

## Что сделано

1. **Доменный журнал находок** (Обзор, под журналом прогонов): колонки `УЧАСТОК → УЧАСТОК | ТИП РАСХОЖДЕНИЯ | СУММА | СТАТУС ПРОВЕРКИ | КЛАСС | ДЕЙСТВИЕ`. Источник — `GET /api/findings` (последние прогоны ролей `auditor-1c` / `investigator-1c`, ABAC по семье, повторы одной находки в разных прогонах схлопнуты до свежего).
2. **Карточка находки** (клик по строке, из окна результата «Карточки находок ▸», из HITL-превью): цепочка документов `Реализация → Счёт-фактура → Оплата` чипами, **красное пунктирное звено = разрыв**, клик по звену открывает документ в веб-клиенте 1С (`ABOP_1C_WEB_URL`, по умолчанию `http://201.51.5.24:8092/audit/`, ссылка вида `#e1cib/data/Документ.<Тип>?ref=<uuid>`).
3. **Слой объяснения** в четыре блока: *Что не сходится* (описание из движка) · *Откуда* (документ, проводка, доказательство + кнопка «Открыть документ в 1С») · *Чем грозит* (норма из `нормы_rag` или экспертного справочника `demo/audit1c/norms/*.md`, ссылка на статью, кнопка «Норма: … ↗» → `GET /api/audit1c/norms/{файл}`) · *Что проверить* (строка `**Что проверить:**` из справочника). Отдельный блок **«Последствия и корректировки · перекрёстные нормы»** — уточнённые декларации по НДС/прибыли, элиминация ВГО, объединение карточек, подсказка проверить условия договора с контрагентом (замечания эксперта владельца от 15.09).
4. **Слепая разметка эксперта в интерфейсе**: «✓ Подтверждаю / ✗ Ложная / ? Не уверен», флаг «вручную бы не нашли», комментарий → `POST /api/runs/{run}/findings/{id}/label` (таблица `finding_labels`, PG, аудит `finding.label`); `DELETE …/label` снимает. Метрики пилота считаются автоматически (`findings.pilot_metrics`): **точность** = подтверждено / (подтверждено + ложных), порог ≥ 80 %; **межучастковые** = доля подтверждённых находок со стыком участков, порог ≥ 50 %; **«вручную бы не нашли»** ≥ 3; **размечено N / M**.

## Где считаются факты

- Движок `cli/ape.py: audit1c_run_checks` (проверки A/B/C/D) теперь кладёт в каждую находку `сумма` (СуммаДокумента) и `цепочка` (звенья с `есть / РАЗРЫВ / ДУБЛЬ / н/д / ПРОВЕРИТЬ` и документами по basis-ссылкам). LLM в детекции не участвует.
- `server/findings.py` — нормализация в карточку: `CHECK_META` (участки, тип, файл нормы, шаблон цепочки для старых прогонов без `цепочка`, последствия), `norm_excerpt` (парсинг md эксперта), `card_from_finding` / `card_from_investigation` (расследования от симптома `invest1c-trace`), `pilot_metrics`.
- `server/finding_store.py` — разметка (PG + память).

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/runs/{run_id}/findings` | карточки прогона + метрики |
| POST | `/api/runs/{run_id}/findings/{id}/label` | `{decision: confirmed\|rejected\|unsure, manual_miss, comment}` |
| DELETE | `/api/runs/{run_id}/findings/{id}/label` | снять разметку |
| GET | `/api/findings?limit=&runs=&agent_id=` | журнал пилота + метрики |
| GET | `/api/audit1c/norms/{file}.md` | текст нормы |

## Не сделано / дальше

- Десктоп-чат показывает находки текстом; карточки с цепочкой пока только в вебе.
- Ссылка на документ 1С открывает веб-клиент учебной базы; у заказчика подставить свой адрес через `ABOP_1C_WEB_URL`.
- Норма подбирается по типу проверки (экспертный справочник), не по каждому документу; граф норм (кросс-цитирование) — следующий шаг (см. [[reglament-conformance-slava]]).
