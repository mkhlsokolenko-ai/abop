# ABAC: настройка доступа по отделам — руководство администратора

> Шаг «Отделов агентов» (ADR-079…085). Дополнение к «Руководство администратора» §5.3
> «Доступ к данным: ABAC по отделу». Здесь — как настроить правильно, что ломается чаще
> всего, и как проверить, что настройка работает.

## 1. Три уровня доступа, каждый за своё отвечает

| уровень | что проверяет | где живёт |
|---|---|---|
| **RBAC** (роль) | что человек *умеет делать* в системе: manager > analyst > viewer | Keycloak realm-роль |
| **ABAC** (отдел) | чьи *данные* видит: очередь, агенты, находки, доски своего отдела | Keycloak claim `department` |
| **Конверт** (граф агента) | что агент *имеет право делать*: навыки, HITL, egress | `autonomy_max` контракта |

Ошибка = настроить один уровень и надеяться, что он закроет остальные. RBAC без ABAC:
аналитик видит чужие данные. ABAC без конверта: агент отдела выходит наружу без HITL.

## 2. Как настроить отдел за 5 шагов

### 2.1 Создайте отдел в Keycloak

```
Keycloak → Realm abop → Users → новый пользователь
  → Attributes: department = <идентификатор семьи>
```

`department` — **единственный claim, который проверяет ABAC**. Значение должно совпадать
с `id` семьи из ростера (`families_store`). Например: `finance`, `audit`, `management`.

### 2.2 Убедитесь, что роль в ростере семьи существует

```
cli/ape.py → AGENT_FAMILIES[<семья>]["members"] → роль → [навыки]
```

Аудитор назначения (ADR-079) сверяет граф каждого агента с ростом этой роли. Роль,
которой нет в ростере, даёт warn «роль не объявлена» — это сигнал добавить её в код или
карточку семьи, а не игнорировать.

### 2.3 Дайте семье доступ к системам (ABAC по данным)

```
Админка → Системы → выбрать систему → scope: добавить <идентификатор семьи>
```

Каждая сущность Data Plane привязана к системе (рецепт → `system_id`). Если системе
нет семьи в scope — навык, читающий эту сущность, получит ⛔ «доступ к данным запрещён
ABAC» и будет пропущен (живой цикл 15.11: caught первым же прогоном).

**Что проверить:** для каждого навыка агентов отдела — все сущности из его `inputs`
доступны семье. Иначе план собирается, но навыки пропускаются молча.

### 2.4 Зарегистрируйте клиентские системы

Когда подключаете клиента (реестр «Клиенты»), система клиента автоматически регистрируется
в реестре систем с `scope: ["audit", "finance"]`. Если забыли — рецепты клиента не попадут
в ABAC и данные будут заблокированы (та же ошибка «вне scope»).

### 2.5 Включите динамическую автономию (опционально, manager+)

```
POST /api/departments/{fid}/autonomy  {"включить": true}
```

После включения ИКА отдела определяет уровень: ИКА ≥ 90 → повышенная (внутренние шаги
без HITL), < 70 → суженная (каждый шаг с подтверждением). Необратимое всегда HITL.

## 3. Что ломается чаще всего

| симптом | причина | как чинить |
|---|---|---|
| «⛔ доступ к данным запрещён ABAC» | система рецепта не в реестре или вне scope семьи | добавьте систему в реестр или расширьте scope |
| агент в отделе, но сверщик невидим | роль в другой семье (ABAC department ≠ family) | перенесите роль в нужную семью (ADR-085) |
| ИКА «не покрыто» | нет прогонов или решений по находкам | прогоните 2–3 задачи, подтвердите находки |
| «роль не объявлена в ростере» | роль есть у агента, но нет в карточке семьи | добавьте роль в `AGENT_FAMILIES` или карточку семьи |
| NCR «формат» — выход не структурирован | навык в детерминированном прогоне отдаёт прозу | подключите schema-binding (шаблон есть, binding в runner) |

## 4. Как проверить, что настройка работает

```bash
# 1. ABAC системы: какие системы видит семья
GET /api/access?department=<отдел>
→ allowed / denied списки

# 2. Аудит назначения: все агенты отдела на месте?
GET /api/agents/assignment-audit
→ только расхождения; ok-агенты не перечисляются

# 3. ИКА отдела: данные собрались?
GET /api/families/<отдел>/ika
→ ика + покрытие + слагаемые + почему_пусто

# 4. ABAC конкретной задачи: прогон выполнен?
GET /api/departments/<отдел>/tasks/<tid>
→ DoD статусы подзадач
```

## 5. Матрица: отдел → семьи → системы → данные

Сопоставление, которое надо держать в голове:

```
Отдел (department) → Семья (family) → Системы (scope) → Сущности (рецепты)
      ↓                        ↓                  ↓                ↓
  JWT claim              ростер ролей      ABAC access      Data Plane
  отдел = семья          аудитор проверяет   can_reach_      рецепты читают
                         граф vs роль        system         данные клиента
```

Каждая стрелка — потенциальная точка отказа. Пройдите цепочку сверху вниз при
настройке нового отдела — это быстрее, чем дебажить «почему пусто» в прогоне.
