## Принципы ранжирования
- **Срочность демо** подняла отчёты/вложения/governance-гейт в Tier 0.
- **Дешёвые высокоэффективные** фиксы (#3, #4) — вперёд: инфра есть, труд минимальный.
- **Цепочки агентов (#5)** — самый ценный продуктовый скачок, но L + архитектура → сразу после демо.
- **Tier 2** — продаёт *концепцию* инвестору, к демо физически не нужно.
- **Tier 3** — важный долг, делается кусками между фичами.

## Сквозной принцип владельца
Везде, где объясняем/предлагаем — **реальные данные и реальные интеграции, не хардкод**. Все правки пользователя в любом месте → **Postgres, не localStorage** (мультиюзерность, переживает перенакат).

## Новый вектор: tool-calling под единым ID (идея владельца 2026-09-24)
Доступ агента к системам под сквозным ID = по факту **tool calling**; расширяем набор инструментов расчётами и графиками, агент вызывает их сам. Философия ABOP сохраняется: **код считает истину, LLM объясняет** (калькулятор-tool повышает надёжность — LLM плох в арифметике).

Срезы по возрастанию риска (разделять!):
1. **Графики через спеку** — ✅ СДЕЛАНО, задеплоено. `server/charts.py`: декларативная спека → inline-SVG (bar/line/pie, без matplotlib; рендерится в браузере и в PDF). Числа из результата (детерминированно), `auto_specs`: находки по классам, расхождения ₽, задачи по приоритету. `{{charts}}` во всех кейс-шаблонах. Проверено визуально.
2. **Whitelisted-расчёты** — ✅ СДЕЛАНО, задеплоено. `server/compute.py` + `POST /api/compute`: фиксированный набор `stats/group_by/top/reconcile` (не произвольный код, без exec), читает только через `data_query` (ABAC на слое данных). Каждый расчёт возвращает данные + chart-спеку (→ график). Проверено на реальных 1С-данных (doc1c: 37 док, НДС по контрагентам, распределение по типам); `op=eval` отклоняется. LLM выбирает операцию+параметры, не пишет код.
3. **Песочница Python** — ❌ sandbox-субпроцесс (без сети/ФС, лимиты) для произвольного pandas/numpy. ⚠️ НЕ `exec()` в процессе API — с Identity Map это RCE под кредами юзера.

Governance: compute/charts = `mode=compute, egress=internal`, автономия A1–A2, HITL не нужен. Конечная точка — **единый реестр tools с RBAC на MCP-шлюзе** (сходится с идеей [agent-rbac-mcp-gateway]): системы = внешние tools, расчёты/графики = внутренние, всё под Identity Map. Старт — детерминированные узлы графа, эволюция к LLM-driven tool-calls позже.

## Освежение эфемерных источников (2026-09-24)
`data_query` читает canonical store, не гоняет рецепт вживую. Тяжёлые postgres/csv (audit) не трогаются. Best-effort.
