# Лимиты прогона: где что задаётся

Четыре уровня, от общего к точному. Каждый следующий перекрывает предыдущий, применённые значения
видны в результате прогона (`run_metrics.limits`).

| Уровень | Где задаётся | Кто может | На что влияет |
|---|---|---|---|
| код и окружение | `.env` сервера, умолчания в `server/runner.py` | администратор сервера | базовые значения, если ничего не настроено |
| среда | **Настройки → Прогон** | manager и выше | все прогоны всех агентов |
| навык | **карточка навыка → лимит ответа / шагов инструментов** | admin | любой агент, где стоит этот навык |
| прогон | **окно «Новый прогон» → бюджет прогона** | тот, кто запускает | только этот запуск |

## Что можно настроить

Настройки → Прогон, одиннадцать полей:

| Поле | Что значит | Границы |
|---|---|---|
| лимит ответа навыка со схемой | сколько токенов навык может потратить на структурный ответ | 200…32000 |
| лимит ответа рассуждающего навыка | то же для письма, плана, пояснительной записки | 200…32000 |
| лимит ответа навыка с подробной схемой | потолок для навыков со сложным шаблоном извлечения | 200…32000 |
| шагов инструментов до ответа | сколько раз навык может сходить за данными прежде чем отвечать; ноль — не ходит | 0…8 |
| параллельных навыков | сколько навыков идут в модель одновременно | 1…12 |
| повторов при сбое модели | ретраи при перегрузе или таймауте | 0…5 |
| строк данных на сущность | сколько записей тянем из Data Plane для точного счёта | 50…50000 |
| записей в примере для модели | сколько строк уходит в промпт на больших наборах | 1…200 |
| до скольких записей показываем целиком | порог, ниже которого модель видит всю выборку, а не пример | 1…2000 |
| знаков методики навыка | сколько текста методики попадает в системное сообщение | 500…40000 |
| знаков данных в промпте | потолок блока данных | 500…60000 |

Пустое поле возвращает значение к умолчанию. Значение вне границ не отвергается молча, а подрезается
до границы: опечатка в поле иначе ломала бы прогоны, пока кто-нибудь не догадается заглянуть в
настройки. Напротив каждого поля видно, задано оно вручную или взято по умолчанию, и какое умолчание.

## Лимит и бюджет — разные вещи

**Лимит** ограничивает ОДИН вызов: длину ответа навыка, число шагов инструментов, размер выборки. Он
влияет на качество: слишком маленький лимит обрывает нарратив на полуслове.

**Бюджет** ограничивает ВЕСЬ прогон: токены, рубли, секунды. Он влияет на расход: после превышения
новые навыки не запускаются, и в результате видно, какие остались не запущены. Расход одного вызова
известен только после ответа модели, поэтому последний навык может выйти за рамки — превышение
показывается честно, а не подгоняется.

Бюджет задаётся в окне «Новый прогон», лимиты — в настройках среды и на навыке.

## Почему это вынесено из окружения

Раньше всё перечисленное жило в переменных окружения сервера (`ABOP_RUN_MAX_TOKENS`,
`ABOP_TOOL_STEPS`, `ABOP_RUN_LLM_CONCURRENCY` и прочие). Изменить их означало перенакат контейнера, а
в интерфейсе лимит ответа навыка показывался числом только для чтения: откуда оно взялось и где его
менять, было не видно. Переменные окружения остались как умолчания — настройка их перекрывает.

## Где посмотреть применённое

- результат прогона → `run_metrics.limits` (в том числе `source`: по умолчанию или настройка);
- `GET /api/admin/run-limits` — действующие значения, умолчания, границы и что изменено;
- `POST /api/admin/run-limits` — правка (manager и выше), пустое значение сбрасывает поле.
