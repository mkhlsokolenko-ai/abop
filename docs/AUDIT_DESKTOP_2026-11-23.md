# Аудит десктопа ABOP против документации — 23.11.2026

Повод: подозрение владельца, что в десктопе «куча нерабочих хвостов». Проверялось механически и
вживую, а не чтением кода: за неделю до этого четыре отказа (`_re` на сервере, `_err` в сайдкаре,
чип методолога без данных, потерянная кнопка рейла) прошли мимо всех существующих сторожей.

## Как проверял

| Способ | Что видит | Чего не видит |
|---|---|---|
| Стык адресов: интерфейс → сайдкар → сервер | запрос, которому некуда идти | логику обработчика |
| ESLint `no-undef` и `no-unused-vars` на 21 файле JS | имя без определения; объявленное без вызывающих | ветки, где имя определено, но неверно |
| Живой прогон 16 разделов (браузер через рабочий сайдкар, данные прода) | падение при открытии, упавшие запросы, карты «не загрузился» | действия-записи; поведение внутри Electron |
| Детектор кнопок без обработчиков | кнопки-пустышки | то, куда зовёт обработчик |
| Документы: названия и адреса против кода и реестра маршрутов | задокументированное, чего нет | смысл |
| Реестр маршрутов против текста тестов | маршруты без тестов | тесты, зовущие функцию напрямую |

Скрипты: `_deck_tmp/audit_endpoints.py`, `audit_live.py`, `audit_buttons.py`, `audit_docs.py`,
конфиг ESLint в `_deck_tmp/jsaudit/` — каталог вне git, при повторе аудита поставить заново
(`npm install eslint@9 globals`).

## Сводка

**В порядке:** все 16 разделов открываются и отрисовываются без ошибок JS и карт «не загрузился»;
все 247 кнопок шаблонов подключены; 197 из 199 запросов интерфейса ведут на существующий маршрут
сайдкара, все 100 вызовов сайдкара к серверу — на существующий маршрут сервера.

**Найдено:** 2 падения, 2 нерабочих действия, 1 молчаливый отказ, 28 неиспользуемых имён,
17 маршрутов сайдкара без вызывающих, 5 расхождений в документации, 174 маршрута сервера без тестов.

Хвосты сидят не там, где раздел «не открывается», а в трёх местах: ветки, которые не выполняются
на данных текущего пользователя; обработчики, зовущие несуществующее; и код, переживший свою фичу.

## 1. Падения

### 1.1 Пульт отдела падает, когда у отдела есть находки

`desktop/ui/modules/agents/panel.js:690` — `база ${esc(org || "—")}`. Имя `org` нигде не определено;
строкой выше (670) для этого вычисляется `орг`. Карточку рисует `потокБлок()` →
`группыПульт.map(группаПультСтрокой)` — для каждой нерешённой группы находок отдела.

У отдела без находок ветка не выполняется, поэтому на текущем пользователе пульт выглядит
здоровым. У финансового отдела 284 находки с доказательствами — там первый экран падает с
`ReferenceError` при отрисовке. Доказано статически (ESLint и чтение); вживую не воспроизводилось —
нужен пользователь отдела с находками.

### 1.2 «Прогоны» падают, когда у отдела задан лимит бюджета

`desktop/ui/modules/runs/panel.js:508` — `${сто > лим ? " — превышен" : ""}`. Имя `лим` не
определено. Ветка выполняется, только если у отдела задан `лимит_руб`; сейчас лимита нет, ветка
молчит. Лимит бюджета (релиз 1.0.46) ни разу не проверялся с заданным значением.

## 2. Нерабочие действия

### 2.1 Окно «Заявки методолога»: «Применить» и пересчёт

`agents/panel.js:816` зовёт `POST /api/methodology/{отдел}/apply`, `:827` — `GET /api/methodology/patrol`.
Интерфейс ходит в сайдкар, а у сайдкара нет маршрутов `/api/methodology/*` — только
`/api/modules/<модуль>/…`. Оба действия возвращают 404 с момента появления (20.11).

На сервере маршруты есть (`POST /api/methodology/{fid}/apply`, `GET /api/methodology/patrol`).
Не хватает прокси в сайдкаре, а это релиз.

## 3. Молчаливый отказ

### 3.1 «Решения»: ошибки загрузки не показываются

`decisions/panel.js:28,37` — `ошибкаНаходок` и `ошибкаПолей` присваиваются в `catch` (строки 87 и 93)
и нигде не читаются. При сбое `/findings` или `/fields` раздел показывает пустой список без
объяснения. То же семейство, что потеря текста в чате, закрытая 23.11.

## 4. Мёртвый код — 28 имён

Функции без вызовов:

## 5. Маршруты сайдкара, которых ядро не зовёт — 17 из 153

- **Дубли и наследие:** `POST /api/modules/agents/jobs/{}/cancel` (дубль маршрута runs — «Отменить»
  на «Прогонах» ходит через runs), `GET agents/recipes`, `GET agents/skills`, `POST agents/run`,
  `POST chat/threads/{}/send` (отправка без стрима), `GET runs/metrics/{}`, `GET runs/summary/{}`.
- **Никем не подключено:** `GET decisions/quality`, `GET cabinet/sources`.
- **Скрытые разделы** (в рейле нет по решению 05.10, открываются только через `Ctrl+K`): «Находки»,
  «Источники», «Операции», «Безопасность», «Распознать». Модули живы и работают — «Находки» и
  «Источники» убраны из маршрута, но ни пользователю, ни README про это не сказано.
- **Для панелей вертикалей** (не ядро): `/api/panel-data/{}`, `/api/panel-action/{}`,
  `verticals/{id}/activate|baseline|install|zero-scan`.

## 7. Тесты

- **174 из 279 маршрутов сервера не упомянуты ни в одном тесте**, в том числе все 8 маршрутов
  `/api/departments` и 7 `/api/methodology`. Мерить надо по упоминанию пути: функцию могут
  тестировать напрямую.
- **Сторожа интерфейса строковые.** Они проверяют, что в файле есть нужный текст, и за неделю
  пропустили четыре отказа. ESLint с `no-undef` в проекте нет; сегодня он нашёл два падения
  из п. 1 за один прогон.

## 8. На полях

- «Сверка расхождений» отрисовывает около 286 тысяч знаков — тяжёлый экран.
- В живом прогоне один разовый 502 (`agents/families/ika`) в скрытом разделе «Что происходит в отделе».
- Чип «методолог» и кнопки пульта в браузерной проверке остаются без обработчиков, в Electron
  работают. Значит, пульт нельзя проверить вне приложения — и окно заявок из п. 2.1 вживую
  не проверено.
- Явных `TODO` в коде десктопа нет — хвосты никак не помечены.

## Что не проверял

- Действия-записи (`POST`, `PUT`, `DELETE`) вживую не выполнял: боевые данные. Для них проверена
  только существование маршрута по цепочке.
- Веб-версию, поведение внутри Electron и логику обработчиков сервера вне пути чтения.
