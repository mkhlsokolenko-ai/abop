# ABOP Desktop (APE Desktop) — тонкий клиент ABOP

Текущая версия — в `package.json` и `sidecar/config.py` (они обязаны совпадать). История релизов —
`docs/RELEASE_DISCIPLINE.md`, тег ставит владелец (см. «Дисциплина релизов» ниже). Что в десктопе работает,
а что нет, — `docs/AUDIT_DESKTOP_2026-11-23.md`.

Десктоп-приложение (скачал → установил) поверх ABOP Web API. **Электрон = тонкое окно**,
**Python-сайдкар = прокси к ABOP `/api/*`** (локальный FastAPI, один origin с UI). Всё общение окна с
сайдкаром — по HTTP на `127.0.0.1`, поэтому **окно можно заменить** (Electron → Tauri/pywebview) не трогая сайдкар.
Точка входа простого пользователя — **чат**: запрос → подбор агента → прогон → карточка прогона с находками,
доставкой и подтверждением внешних действий (HITL).

## Архитектура (слои)

```
┌─────────────────────────────────────────────┐
│ Electron shell (electron/main.js)            │  спавнит сайдкар, рендерит ui/
│  └─ BrowserWindow → ui/index.html            │
├─────────────────────────────────────────────┤
│ UI (модульный фронт, ui/)                    │
│  core/app.js  — загрузчик модулей + API      │  тема в core/theme.css (свапается)
│  modules/<id>/panel.js — панель фичи          │
├───────────────── HTTP 127.0.0.1 ─────────────┤
│ Python sidecar (sidecar/) — FastAPI движок   │
│  app.py — ядро: auth + реестр модулей        │
│  registry.py — авто-обнаружение modules/*    │
│  auth.py — вход (Keycloak / loopback-PKCE)    │
│  abop_client.py — вызовы ABOP /api/* (JWT)    │
│  db.py — локальный SQLite (треды/сообщения)   │
│  modules/<id>/module.py — MANIFEST + router  │
└─────────────────────────────────────────────┘
         │ /api/chat · /runs · /agents/match · /hitl · /runs/{id}/report (JWT)
         ▼  ABOP Web API (:8091) → self-host Qwen3-30B (vLLM) · Data Plane · шина → коннектор → системы
```

**Модульность (главное требование):** новая фича = новый модуль, ядро не трогаем.
- **Backend-модуль:** папка `sidecar/modules/<id>/` с `module.py`, где есть `MANIFEST` (id/title/icon/ui/order)
  и `router` (FastAPI). Реестр монтирует его на `/api/modules/<id>`.
- **Frontend-модуль:** `ui/modules/<ui>/panel.js` с `export async function mount(root, ctx)`.
  Ядро берёт список из `/api/modules` и динамически импортирует панель.
- **Тема** — `ui/core/theme.css` (переменные) и `ui/core/abop.css` (словарь дизайнера: оболочка и экраны
  по мокапам). Дизайн меняется без правки логики.

## Модули сейчас (`sidecar/modules/*` ↔ `ui/modules/*`)

Названия — как в рейле (`MANIFEST.title` сайдкара). Что попадает в рейл, решают роль и активная
вертикаль; остальное открывается палитрой команд (`Ctrl+K`).

- **Чат** (`chat`) — рабочая среда: треды с историей (локальный SQLite), ответ модели стримом,
  подбор агента по команде `/work`, прогон в треде с карточкой результата, очередь подтверждений
  (HITL) с превью, вложения и распознавание, «сделать регулярной» (триггер по расписанию).
- **Клиенты** (`clients`) — реестр обслуживаемых компаний: заведение клиента, подключение источника,
  вычитка базы.
- **Решения** (`decisions`) — очередь того, что ждёт слова человека: внешние действия, реестр
  находок, очередь первички. Срез «мой отдел» включён у не-администратора.
- **Агенты** (`agents`) — на первом экране пульт отдела: ИКА и его слагаемые, полоса здоровья, поток
  находок, бюджет и лимит, «Запустить» по тексту, заявки методолога, карточка отдела; ниже — каталог
  агентов и конструктор. Через этот же модуль чат берёт очередь подтверждений и общую доску.
- **Прогоны** (`runs`) — журнал прогонов с ценой и токенами, идущий прогон с отменой, отчёт на печать.
- **Вертикали** (`verticals`) — карточки поставок, включение представления, установка, нулевой прогон,
  база.
- **Кабинет** (`cabinet`) — профиль, расход и квота, каналы связи, личная база.
- **Сверка** — экран вертикали: панель приезжает бандлом с сервера, сайдкар отдаёт ей данные через
  `/api/panel-data/` и выполняет действия через `/api/panel-action/`.

Служебные экраны данных: **Находки** (`findings`), **Граф** (`graphlens`), **Операции** (`opslens`),
**Присмотр** (`watch`), **Распознать** (`ocr`), **Источники** (`connectors`), **Безопасность**
(`security`), **Лента контроля** (`control`). Пять из них убраны из маршрута намеренно (решение
05.10): Находки, Операции, Распознать, Источники, Безопасность — они работают, но открыть их можно
только палитрой.

## Дисциплина релизов (docs/RELEASE_DISCIPLINE.md)

- Правка `desktop/sidecar` или `desktop/electron` → поднять `version` в `desktop/package.json` **и**
  `APP_VERSION` в `desktop/sidecar/config.py` в том же коммите: это доезжает до человека только
  переустановкой.
- Правка `desktop/ui` версию **не** требует: интерфейс приезжает с сервера «Путём А».
- Релиз собирает `desktop-release.yml` по тегу `desktop-vX.Y.Z` — только Windows. macOS собирает
  ручной запуск того же workflow с `mac=true` и `publish=true` в пределах двух часов после релиза.
  **Тег ставит владелец**, не ассистент.
- CI job `desktop-guard`: сайдкар или Electron менялись после тега, а версия не поднята → ошибка;
  версия поднята, тега нет → предупреждение.
- Каждому релизу — запись в `docs/RELEASE_DISCIPLINE.md`: сторож проверяет, что номер версии там есть.


## Запуск (dev)
Требуется: **Node 18+** (Electron) и **Python 3.10+**.
```bash
cd desktop
py -m pip install -r sidecar/requirements.txt   # движок: fastapi, uvicorn, pydantic
npm install                                      # electron, electron-builder
npm start                                        # Electron сам поднимет сайдкар и окно
```
Сайдкар можно гонять и отдельно (для отладки без окна):
```bash
cd desktop && APE_SIDECAR_PORT=8799 py -m sidecar.app
# затем открыть http://127.0.0.1:8799/api/health , /api/modules
```
Данные приложения (токены, треды, кэш интерфейса): `~/.abop-desktop/` (переопределяется `ABOP_DESKTOP_HOME`).

## Сборка инсталлятора (Windows) — Python пользователю НЕ нужен
Два шага: сначала бинарь сайдкара (PyInstaller), потом инсталлятор (electron-builder).
```bash
cd desktop
py -m pip install pyinstaller
py -m PyInstaller --noconfirm --clean build-sidecar.spec   # → dist/ape-sidecar/ (onedir + _internal)
CSC_IDENTITY_AUTO_DISCOVERY=false npm run dist             # → dist/APE Desktop Setup x.y.z.exe (~108 МБ)
```
Как это устроено:
- `build-sidecar.spec` собирает `run_sidecar.py` (→ `sidecar.app:main`) в автономный `ape-sidecar.exe`
  (collect_all uvicorn/fastapi/pydantic + submodules `sidecar.modules`; реестр имеет fallback-список
  модулей — во frozen-сборке `pkgutil` может не перечислить пакеты).
- `package.json → build.extraResources` кладёт `dist/ape-sidecar` в `resources/ape-sidecar`;
  `main.js` в проде (`app.isPackaged`) запускает бинарь оттуда, в dev — `py -m sidecar.app`.

**Гейты сборки (важно на Windows без прав администратора):**
- `signAndEditExecutable: false` + `CSC_IDENTITY_AUTO_DISCOVERY=false` — иначе electron-builder тянет
  `winCodeSign`, распаковка которого содержит mac-симлинки и падает («Cannot create symbolic link»)
  без Developer Mode/админа. Мы не подписываем сборку.
- Инсталлятор **без подписи** → при первом запуске Windows SmartScreen покажет предупреждение
  («Подробнее → Выполнить в любом случае»). Для тихой установки позже добавить code-signing сертификат.

## Сборка под macOS (DMG) — только на macOS-раннере

DMG нельзя собрать с Windows: образ делается инструментами macOS, а сайдкар — нативный бинарь
PyInstaller, у которого кросс-сборки нет вовсе. Поэтому маки собирает CI, по раннеру на архитектуру:
`macos-14` → **arm64** (Apple Silicon), `macos-15-intel` → **x64** (Intel: образ `macos-13`
снят с обслуживания 04.12.2025, а сам Intel на раннерах GitHub доживает до осени 2027). Локально на Mac — то же самое
руками:

```bash
cd desktop
python -m pip install -r sidecar/requirements.txt pyinstaller
python -m PyInstaller --noconfirm --clean build-sidecar.spec   # → dist/ape-sidecar/
npm ci && npm run dist:mac                                      # → dist/ABOP-Desktop-<версия>-mac-<арка>.dmg
```

**Подпись — ad-hoc, и это не формальность.** На Apple Silicon ядро отказывается исполнять Mach-O
без подписи: совсем неподписанное приложение не «ругается Gatekeeper'ом», а не открывается с
«повреждено». Developer ID у нас нет, поэтому `build/afterPack.js` подписывает бандл ad-hoc
(`codesign --sign -`) между упаковкой `.app` и сборкой DMG и тут же проверяет печать. Что это
значит для пользователя:

- при первом запуске Gatekeeper скажет «разработчик не может быть проверен» → **правой кнопкой по
  приложению → «Открыть»** (или «Системные настройки → Конфиденциальность и безопасность → Всё
  равно открыть»). Двойной клик в первый раз не поможет — это поведение самой macOS;
- **авто-обновления на Mac нет**: `electron-updater` проверяет подпись скачанного бандла и ad-hoc
  не принимает, поэтому в `main.js` ветка `darwin` выключена явно — баннер, который падает на
  кнопке «Установить», хуже отсутствия баннера. Обновление = скачать новый DMG;
- и то, и другое снимается покупкой Apple Developer ID ($99/год): появится сертификат — убрать
  ветку `darwin` в `setupUpdater` и выдать CI `CSC_LINK`/`CSC_KEY_PASSWORD`, остальное уже готово.

**Чем Mac-сборка отличается в поведении:**

| | Windows | macOS |
|---|---|---|
| Трей | `icon.ico` | `icon.png` 18px (`.ico` macOS не декодирует — значок был бы невидим) |
| Авто-обновление | есть (electron-updater) | нет (нужен Developer ID) |
| Хоткей «разобрать выделенное» | забирает выделение через SendKeys | SendKeys нет: берётся текущий буфер обмена |

Иконка для macOS — тот же `build/icon.png`, но поднятый до **1024×1024**: electron-builder сам
соберёт из него `.icns`, а меньше 512 не принимает. Задавать `mac.icon` путём бесполезно — к пути
без расширения `.icns` builder дописывает `.icns`, не находит файл и молча откатывается на
`buildResources/icon.png`; именно так упал первый прогон. Текущий файл — апскейл 256→1024:
векторного исходника у иконки нет, поэтому на крупных размерах она мягче, чем могла бы быть.
Появится вектор — заменить файл, менять конфиг не нужно.

## Авто-доставка обновлений (без ручной переустановки)

Гибрид, чтобы не переставлять приложение на каждое изменение:

- **Бэкенд** (шлюз/роутинг/стриминг/модель) — деплой на сервер, клиентам реинсталл **не нужен**.
- **UI** — **«Путь А»**: сайдкар сам тянет свежий бандл с ABOP (`/desktop-ui-bundle`) в свой кэш и
  отдаёт его окну с `127.0.0.1/ui`; при офлайне — вшитый в сборку фолбэк. Окно сверяет версию при
  старте, раз в десять минут и по возврату фокуса (`GET /api/ui/version`, `POST /api/ui/sync`) и
  показывает полосу «интерфейс обновился» с кнопкой «Обновить окно». Молча окно не перезагружается:
  в чате может лежать набранный текст. `APE_UI_URL=<url>` по-прежнему задаёт хост интерфейса вручную
  (для разработки).
- **Сайдкар + оболочка** — **electron-updater** (тихий авто-апдейт с GitHub Releases) на Windows.
  На macOS авто-обновления нет: подпись ad-hoc, updater её не принимает (см. «Сборка под macOS»).

**CI (`.github/workflows/desktop-release.yml`):** пуш тега `desktop-vX.Y.Z` → раннер `windows-latest`
собирает сайдкар (PyInstaller) и установщик и **публикует в GitHub Releases** (`GITHUB_TOKEN`);
Windows-клиенты подхватывают апдейт сами. macOS — отдельным ручным запуском того же workflow
(`mac=true`, `publish=true`) в пределах двух часов после релиза: позже electron-builder отказывается
дополнять опубликованный релиз, и сторож workflow это ловит. Маки обновляются скачиванием DMG.

Проверить изменения сборки, **не выпуская релиз**: Actions → desktop-release → Run workflow с
`publish = false` (или `gh workflow run desktop-release.yml -f publish=false`) — те же шаги, но
результат уходит в артефакты и канал обновления у живых клиентов не трогается. Релиз вручную
(локально): `set GH_TOKEN=... && npm run publish`. Сборка без code-sign → SmartScreen предупредит
при первой установке (для тихой — сертификат позже).

## Нет связи с ABOP (1.0.10)

Сервер и локальный движок приложения различаются: сайдкар может работать, когда ABOP недоступен.
`GET /api/health` сайдкара отдаёт `abop: true|false`, `abop_error` и `abop_url`; UI пингует его раз в 20 секунд
и при потере связи показывает в шапке красную плашку «Нет связи с ABOP — запуск агентов недоступен, история чата
на месте» с кнопкой «Проверить». Любая сетевая ошибка запроса поднимает плашку сразу, не дожидаясь пинга.
Когда связь возвращается — тост «Связь восстановлена» и перезагрузка открытых модулей.

## Сторожа (что ловит поломки до прода)

- `python -m pytest -q` из корня репо — весь набор, около двух минут. Строковые сторожа интерфейса
  сидят в нём же: после правок `desktop/ui` набор надо гонять целиком, а не только smoke.
- `tests/test_js_undef_guard.py` — в JS десктопа нет имени без определения (ESLint `no-undef`).
  Линтер ставится отдельно от приложения: `npm ci --prefix tools/jslint` из корня репо.
- `tests/test_desktop_ui_sidecar_routes.py` — каждый запрос интерфейса имеет маршрут в сайдкаре.
- `tests/test_undefined_names_guard.py` — то же для Python сервера, сайдкара и скриптов (`ruff`),
  ставится вместе с зависимостями CI.

В CI (`ci.yml`, job `smoke`) гоняется полный набор и эти сторожа. До 24.11.2026 полный набор
жил только на машине разработчика: четыре падения «… is not defined» и окно методолога с 404
дошли до прода при зелёном CI.
