# ABOP Desktop (APE Desktop) — тонкий клиент ABOP

Версия: **1.0.8** (`package.json` и `sidecar/config.py`). Последний собранный релиз — `desktop-v1.0.7`;
тег `desktop-v1.0.8` ставит владелец (см. «Дисциплина релизов» ниже).

Десктоп-приложение (скачал → установил) поверх ABOP Web API. **Электрон = тонкое окно**,
**Python-сайдкар = прокси к ABOP `/api/*`** (локальный FastAPI, один origin с UI). Всё общение окна с
сайдкаром — по HTTP на `127.0.0.1`, поэтому **окно можно заменить** (Electron → Tauri/pywebview) не трогая сайдкар.
Точка входа простого пользователя — **чат**: запрос → подбор агента → прогон → карточка прогона с находками,
доставкой и подтверждением внешних действий (HITL).

## Архитектура (слои)

```
┌─────────────────────────────────────────────┐
│ Electron shell (electron/main.js)            │  спавнит сайдкар, рендерит ui/
│  └─ BrowserWindow → ui/index.html            │
├─────────────────────────────────────────────┤
│ UI (модульный фронт, ui/)                    │
│  core/app.js  — загрузчик модулей + API      │  тема в core/theme.css (свапается)
│  modules/<id>/panel.js — панель фичи          │
├───────────────── HTTP 127.0.0.1 ─────────────┤
│ Python sidecar (sidecar/) — FastAPI движок   │
│  app.py — ядро: auth + реестр модулей        │
│  registry.py — авто-обнаружение modules/*    │
│  auth.py — вход (Keycloak / loopback-PKCE)    │
│  abop_client.py — вызовы ABOP /api/* (JWT)    │
│  db.py — локальный SQLite (треды/сообщения)   │
│  modules/<id>/module.py — MANIFEST + router  │
└─────────────────────────────────────────────┘
         │ /api/chat · /runs · /agents/match · /hitl · /runs/{id}/report (JWT)
         ▼  ABOP Web API (:8091) → self-host Qwen3-30B (vLLM) · Data Plane · шина → коннектор → системы
```

**Модульность (главное требование):** новая фича = новый модуль, ядро не трогаем.
- **Backend-модуль:** папка `sidecar/modules/<id>/` с `module.py`, где есть `MANIFEST` (id/title/icon/ui/order)
  и `router` (FastAPI). Реестр монтирует его на `/api/modules/<id>`.
- **Frontend-модуль:** `ui/modules/<ui>/panel.js` с `export async function mount(root, ctx)`.
  Ядро берёт список из `/api/modules` и динамически импортирует панель.
- **Тема** — только `ui/core/theme.css` (CSS-переменные). Дизайн меняется без правки логики.

## Модули сейчас (`sidecar/modules/*` ↔ `ui/modules/*`)
- **chat** — рабочая среда пользователя: треды + история (локальный SQLite), подбор агента по запросу
  (`/api/agents/match`), прогон в треде с карточкой результата, авто-цепочки навыков по контексту,
  HITL-очередь с превью, вложения/OCR, «сделать регулярной» (крон-триггер).
- **agents** — «Мои» и «Общие» агенты, версии, дедуп, правка «моего» агента → новая версия, удаление с подтверждением.
- **connectors**, **graphlens**, **opslens**, **security** — Data Plane, линзы графа/операций, безопасность.
- **cabinet** — рабочий Кабинет пользователя (источники: ABOP Data Plane, локальные файлы Office, последние файлы).
- **ocr** — распознавание документов (RapidOCR).

## Что нового в 1.0.8 (с 1.0.5)

- **HITL-очередь в чате с превью.** Внешние действия агента ждут решения прямо в чате (не в «Мои агенты»):
  панель «🛡 Требуют вашего подтверждения · N», кнопки «Посмотреть и подтвердить» / «Отклонить», «Подтвердить все…».
- **Карточки прогонов с доставкой.** В карточке — находки, токены, конверт автономии и блок «доставка»:
  каждая строка = канал/система → адресат · «тема» · статус (`ожидает вашего подтверждения` / `отправлено` /
  `черновик (без отправки)` / `доступ закрыт`).
- **Превью команд коннектора.** Для заявок канала `command` (результат навыка по шаблону `template.json → delivery`)
  окно подтверждения показывает поля **Действие** (`redmine · issue.create`), **Куда**, **Навык** (навык · элемент),
  **Тема** и html-превью того, что уйдёт; кнопка «Подтвердить и выполнить в системе».
- **Результат выполнения в карточке.** После «да» команда уходит в шину, коннектор исполняет её, десктоп опрашивает
  заявку (`GET /api/hitl/{id}`, до 90 с) и пишет в карточку «✓ выполнено: http://…/issues/N» (или «✗ ошибка коннектора: …»).
- **Кнопка «Отчёт PDF»** на карточке прогона — отчёт по шаблону (`GET /api/runs/{run_id}/report?template=<id>&format=pdf`),
  файл кладётся в «Загрузки»; тот же шаблон использует OUT-узел канала `pdf`.
- **Авто-цепочки** навыков по контексту треда + HITL-подсказка; «ещё раз» перезапускает цепочку.
- **Мои/Общие агенты**, версии и дедуп в подборе; **Кабинет** — рабочий (вместо «Операций»; «Безопасность» влита в Кабинет).
- Фиксы UX-аудита 25.09 (примитивы `api/humanError/modal/confirm/toast`, кэш модулей, шрифты в бандле),
  версия в шапке = реальная версия .exe, режим вывода агента (структурный/рассуждения).

## Дисциплина релизов (docs/RELEASE_DISCIPLINE.md)

- Любая правка `desktop/sidecar`, `desktop/electron`, `desktop/ui` → поднять `version` в `desktop/package.json`
  **и** `APP_VERSION` в `desktop/sidecar/config.py` в том же коммите.
- Релиз собирает `desktop-release.yml` по тегу `desktop-vX.Y.Z`; **тег ставит владелец**, не ассистент.
- CI job `desktop-guard`: `desktop/` менялся после тега, а версия не поднята → ошибка; версия поднята, тега нет → предупреждение.
- UI приезжает с сервера по «Пути А» (`/desktop-ui-bundle`) без пересборки .exe; сайдкар и Electron — только через релиз.

## Запуск (dev)
Требуется: **Node 18+** (Electron) и **Python 3.10+**.
```bash
cd desktop
py -m pip install -r sidecar/requirements.txt   # движок: fastapi, uvicorn, pydantic
npm install                                      # electron, electron-builder
npm start                                        # Electron сам поднимет сайдкар и окно
```
Сайдкар можно гонять и отдельно (для отладки без окна):
```bash
cd desktop && APE_SIDECAR_PORT=8799 py -m sidecar.app
# затем открыть http://127.0.0.1:8799/api/health , /api/modules
```
Данные приложения (токены, треды): `~/.ape-desktop/` (переопределяется `APE_DESKTOP_HOME`).

## Сборка инсталлятора (Windows) — Python пользователю НЕ нужен
Два шага: сначала бинарь сайдкара (PyInstaller), потом инсталлятор (electron-builder).
```bash
cd desktop
py -m pip install pyinstaller
py -m PyInstaller --noconfirm --clean build-sidecar.spec   # → dist/ape-sidecar/ (onedir + _internal)
CSC_IDENTITY_AUTO_DISCOVERY=false npm run dist             # → dist/APE Desktop Setup x.y.z.exe (~108 МБ)
```
Как это устроено:
- `build-sidecar.spec` собирает `run_sidecar.py` (→ `sidecar.app:main`) в автономный `ape-sidecar.exe`
  (collect_all uvicorn/fastapi/pydantic + submodules `sidecar.modules`; реестр имеет fallback-список
  модулей — во frozen-сборке `pkgutil` может не перечислить пакеты).
- `package.json → build.extraResources` кладёт `dist/ape-sidecar` в `resources/ape-sidecar`;
  `main.js` в проде (`app.isPackaged`) запускает бинарь оттуда, в dev — `py -m sidecar.app`.

**Гейты сборки (важно на Windows без прав администратора):**
- `signAndEditExecutable: false` + `CSC_IDENTITY_AUTO_DISCOVERY=false` — иначе electron-builder тянет
  `winCodeSign`, распаковка которого содержит mac-симлинки и падает («Cannot create symbolic link»)
  без Developer Mode/админа. Мы не подписываем сборку.
- Инсталлятор **без подписи** → при первом запуске Windows SmartScreen покажет предупреждение
  («Подробнее → Выполнить в любом случае»). Для тихой установки позже добавить code-signing сертификат.

## Авто-доставка обновлений (без ручной переустановки)

Гибрид, чтобы не переставлять приложение на каждое изменение:

- **Бэкенд** (шлюз/роутинг/стриминг/модель) — деплой на сервер, клиентам реинсталл **не нужен**.
- **UI** — **удалённый**: если задан `APE_UI_URL`, `main.js` грузит фронт с сервера (правки без релиза),
  с фоллбеком на локальную копию из asar при офлайне. Пусто → локальный UI. Хост UI — GitHub Pages
  или портал (любой URL, отдающий `ui/`).
- **Сайдкар + оболочка** — **electron-updater** (тихий авто-апдейт с GitHub Releases): при запуске
  проверяет версию, докачивает, ставит на перезапуск. Конфиг `build.publish` (github owner/repo) в
  `package.json`; проверка — в `main.js` (`checkUpdates()`, только `app.isPackaged`).

**CI (`.github/workflows/desktop-release.yml`):** пуш тега `desktop-vX.Y.Z` → windows-раннер собирает
сайдкар (PyInstaller) + инсталлятор (electron-builder) и **публикует в GitHub Releases** (`GITHUB_TOKEN`).
Клиенты подхватывают апдейт сами.

Релиз вручную (локально): `set GH_TOKEN=... && npm run publish` (или через CI по тегу).
Первый релиз нужно опубликовать один раз — дальше авто-апдейт от него отсчитывается.
Сборка без code-sign → SmartScreen предупредит при первой установке (для тихой — сертификат позже).

## Нет связи с ABOP (1.0.10)

Сервер и локальный движок приложения различаются: сайдкар может работать, когда ABOP недоступен.
`GET /api/health` сайдкара отдаёт `abop: true|false`, `abop_error` и `abop_url`; UI пингует его раз в 20 секунд
и при потере связи показывает в шапке красную плашку «Нет связи с ABOP — запуск агентов недоступен, история чата
на месте» с кнопкой «Проверить». Любая сетевая ошибка запроса поднимает плашку сразу, не дожидаясь пинга.
Когда связь возвращается — тост «Связь восстановлена» и перезагрузка открытых модулей.
