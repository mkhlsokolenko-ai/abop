# Проверка карточек под требования витрины (feed-checks)

Товар участника уезжает на чужую витрину, и карточка обязана соответствовать её требованиям. Нарушения вычисляет КОД инструментом `feed_checks` — по правилам витрины и справочнику соответствия категорий, детерминированно и воспроизводимо. Твоя роль — прогнать проверки, сгруппировать результат и передать дальше, ничего не выдумывая и ничего не пряча.

## Когда применять
- Перед отправкой партии карточек на витрину: узнать, что развернут, до того как развернули.
- Нужен перечень нарушений по кодам с доказательством по каждой карточке.
- Нужен срез по одной причине (`{"код":"ATTR_MISSING"}`) или по одной карточке (`{"карточка":"SKU-3042"}`).

## Метод (пошагово)
1. **Прогони проверки** инструментом `feed_checks`. Получишь `{всего, карточек_с_нарушениями, по кодам, находки[]}`; каждая находка: `карточка, код, причина, поле, доказательство, чинится`.
2. **Разложи по кодам**: `CATEGORY_UNMAPPED` (нет соответствия категорий), `ATTR_MISSING` (нет обязательного атрибута), `UNIT_MISMATCH` (чужая единица), `MARKING_REQUIRED` (нужна маркировка), `IMAGES_FEW` (мало изображений), `TITLE_TOO_LONG`, `TITLE_FORBIDDEN` (рекламная формулировка).
3. **Раздели по признаку `чинится`**: «из данных» — исправление выводится из самой карточки и справочников; «человеком» — нужен снимок, маркировка или решение по новой категории. Это разные очереди работы, и смешивать их нельзя.
4. **Проверь доказательство** каждой находки: там конкретика — какого атрибута нет, какая единица пришла, сколько изображений при каком минимуме. Находка без доказательства не годится, но движок их проставляет: твоя задача сверить, а не переписать.
5. **Не добавляй нарушений рассуждением.** Если кажется, что карточка плоха, а движок молчит — это задача на новую проверку в коде, а не строка в отчёте.

## Definition of Done
- [ ] `feed_checks` отработал; получен полный перечень нарушений с разбивкой по кодам.
- [ ] У каждого нарушения есть код, поле, доказательство и признак «чинится».
- [ ] Очереди «из данных» и «человеком» разделены и посчитаны.
- [ ] Перечень не дополнялся и не сокращался вручную.
- [ ] Названо, сколько карточек прошло проверки без замечаний.

## Анти-паттерны
- Не «находи» нарушения в обход движка: карточку разворачивает витрина по правилам, а не по мнению модели.
- Не объявляй карточку чистой, если правил для её категории нет, — скажи, что проверять было нечем.
- Не теряй `CATEGORY_UNMAPPED`: это не мелочь, а причина, по которой карточка вообще не доедет.
- Не обещай, что проверено всё: опубликованные требования витрины — не весь её чек-лист.

## Безопасность
- **mode=read** — только чтение фида и правил, ничего не меняется.
- **egress=internal** — проверки идут внутри Data Plane.
- **cite=True** — у каждого нарушения доказательство из данных карточки и правил витрины.
