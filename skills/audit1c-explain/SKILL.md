# Объяснение находок и отчёт (explain)

Ты превращаешь сухой реестр находок в понятное объяснение для человека — так, чтобы бухгалтер или аудитор сразу понял суть, увидел первоисточник, осознал риск и знал следующий шаг. Каждая находка раскрывается по четырём вопросам: **Что не сходится / Откуда / Чем грозит / Что проверить**. Это финальный навык конвейера: результат идёт человеку на подтверждение (HITL) и только потом — во внешние системы.

## Когда применять
- Есть ранжированные находки (`audit1c-rank`) и причины (`audit1c-root-cause`) — нужно оформить объяснение и отчёт.
- Нужен документ для бухгалтера/аудитора/менеджмента с первоисточниками и нормами.
- Перед публикацией отчёта наружу (BookStack/PDF/почта) — подготовить к HITL-подтверждению.

## Метод (пошагово)
1. **По каждой находке раскрой четыре блока**:
   - **Что не сходится** — суть нарушения человеческим языком (не код проверки).
   - **Откуда** — точная ссылка на первоисточник: номер и тип документа, конкретная проводка (Дт/Кт/сумма), ИНН — из `доказательство` находки.
   - **Чем грозит** — норма и последствие: НДС без счёта-фактуры → риск отказа в вычете/доначисления (гл. 21 НК РФ); ВГО без элиминации → искажение консолидированной отчётности (ФСБУ/МСФО); дубль контрагента → задвоение расчётов и искажение сальдо; себестоимость не списана → завышение прибыли (ФСБУ 5/2019).
   - **Что проверить** — конкретное действие бухгалтера (выставить/запросить СФ, привязать платёж, объединить карточки, доначислить проводку).
2. **Соблюдай порядок существенности** из `audit1c-rank`: критичное — первым.
3. **Свяжи с первопричиной**: где применимо, укажи, что находка — симптом процесса из `audit1c-root-cause`, и дай рекомендацию по корню.
4. **Честно раздели установленное и предполагаемое**: находки движка — факты со ссылкой; слабые сопоставления из `audit1c-match-weak` — помечай как гипотезы на проверку.
5. **Подготовь к HITL**: отчёт — черновик на подтверждение человека. Ничего не отправляй во внешние системы (BookStack/почта) без явного одобрения; формируй артефакт и помечай «ожидает подтверждения».

## Definition of Done
- [ ] Каждая находка раскрыта по всем четырём блокам (Что/Откуда/Чем грозит/Что проверить).
- [ ] «Откуда» содержит проверяемую ссылку на документ и проводку (не общий текст).
- [ ] «Чем грозит» ссылается на конкретную норму (НК РФ / ФСБУ), а не на «плохо».
- [ ] Порядок — по существенности; критичное вверху.
- [ ] Установленные факты и слабые гипотезы явно разделены.
- [ ] Отчёт помечен как ожидающий подтверждения человека (HITL); наружу без одобрения ничего не ушло.

## Анти-паттерны
- Не пиши «нарушение по документу X» без раскрытия сути и последствия — это не объяснение.
- Не ссылайся на норму «в общем» — указывай конкретную главу/стандарт применительно к находке.
- Не выдавай слабое сопоставление за факт в отчёте — гипотеза остаётся гипотезой.
- Не отправляй отчёт во внешние системы без HITL-подтверждения — это действие с последствиями.
- Не переставляй находки в произвольном порядке — существенность задаёт последовательность.
- Не придумывай нормы/суммы — только из данных и справочника норм.

## Безопасность
- **mode=write** — формирует и публикует отчёт как артефакт; действия аудируемы, публикация наружу — только после HITL.
- **egress=internal** — сам отчёт остаётся внутри периметра; вывод во внешние системы (BookStack/PDF/почта) — отдельный шаг под подтверждением.
- **cite=True** — под каждым пунктом ссылка на первичный документ/проводку и норму; нет источника → прямо указать пробел, не выдумывать.

## Интеграция
- **Вход**: ранжированные находки (`audit1c-rank`), причины (`audit1c-root-cause`), слабые связи (`audit1c-match-weak`); данные — `doc1c`/`ref1c`.
- **Результат**: объяснительный отчёт (в порядке существенности) как артефакт через `write_file`/`remember`; помечен на HITL-подтверждение.
- **Handoff**: после подтверждения человеком — вывод в BookStack (отчёт-страница) → Gotenberg (красивый PDF) → почта (Mailpit); передавай задачу навыкам/коннекторам вывода.
