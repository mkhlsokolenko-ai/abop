# Первопричинный анализ находок (root-cause)

Ты не пересказываешь список нарушений — ты находишь, ПОЧЕМУ они возникли. Часто десяток находок — это один сбойный процесс: не выставляются счета-фактуры, не привязываются платежи, не ведётся единая карточка контрагента. Аудитор ценит не длину списка, а понимание корня: устранишь причину — исчезнет пачка симптомов.

## Когда применять
- Есть реестр находок из `audit1c-checks` — нужно свести симптомы к причинам.
- Находки повторяются по одному типу документа/контрагенту/участку учёта.
- Перед отчётом — чтобы рекомендации били по причине, а не по каждому симптому.

## Метод (пошагово)
1. **Сгруппируй находки** по общему признаку: тип нарушения (класс+проверка), участок учёта (НДС, расчёты, банк), контрагент/организация, период.
2. **Сформулируй гипотезу процесса-причины** для группы: например, «B1+B2 (реализации и поступления без счетов-фактур) → не регламентирован процесс выставления/получения СФ»; «B3+B4 (оплаты без основания и незакрытые поступления) → платежи не привязываются к первичке».
3. **Подтверди причину данными графа**: причина должна опираться на факты (сколько документов затронуто, у каких контрагентов, в каком периоде), а не на общие слова.
4. **Оцени охват**: одна причина → сколько находок она объясняет. Причина, закрывающая много находок, приоритетнее точечной.
5. **Отдели корень от симптома**: в выводе — причина + перечень порождённых ею находок, а не плоский список. Не сливай разные причины в «плохой учёт».

## Definition of Done
- [ ] Находки сгруппированы; для каждой группы названа гипотеза процесса-причины.
- [ ] Каждая причина подтверждена фактами (охват, контрагенты, период), а не декларацией.
- [ ] Указан охват: сколько находок объясняет каждая причина.
- [ ] Причины и симптомы разделены — нет плоского пересказа реестра.
- [ ] Разные причины не слиты в одну размытую формулировку.

## Анти-паттерны
- Не выдавай список симптомов за анализ причин — это разные вещи.
- Не сваливай всё в «низкое качество учёта» — называй конкретный сломанный процесс.
- Не придумывай причину без опоры на данные — только то, что подтверждается находками/графом.
- Не дроби одну причину на десять — и не склеивай десять разных причин в одну.
- Не игнорируй единичную, но существенную находку ради «красивой» группировки.

## Безопасность
- **mode=read** — анализ поверх готовых находок; данные не изменяются.
- **egress=internal** — внутри периметра.
- **cite=True** — каждая причина обоснована конкретными находками и фактами графа.

## Интеграция
- **Вход**: реестр находок из `audit1c-checks`; граф из `audit1c-graph-build` для подтверждения охвата.
- **Результат**: причины с перечнем порождённых находок и охватом — на доску.
- **Handoff**: → `audit1c-rank` (ранжировать причины/находки по существенности) → `audit1c-explain`.
