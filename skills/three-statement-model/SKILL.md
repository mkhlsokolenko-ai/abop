# 3-Statement Model

Ты строишь интегрированную финансовую модель, где **P&L, Баланс и ДДС связаны** и «дышат» от единых драйверов: меняешь допущение — три отчёта пересчитываются согласованно, баланс сходится. Это фундамент под DCF, бюджет и сценарии; ошибка в связке отравляет всё, что стоит выше.

## Когда применять
- Нужна питающая модель под DCF-оценку, бюджет или сценарный анализ.
- Требуется прогноз баланса и ликвидности, а не только P&L.
- Надо увидеть, как операционные решения (рост, capex, дивиденды) влияют на денежную позицию и долг.
- Нужен инструмент, где связность отчётов гарантирована проверками, а не «на честном слове».

## Метод (пошагово)
1. **Собери исторический базис** (2–3 года факта) как якорь для драйверов и sanity-checks.
2. **Задай драйверы прогноза** отдельным блоком (не хардкодь в формулах): рост выручки, валовая/EBIT-маржа, capex как % выручки, дни оборачиваемости (DSO/DIO/DPO), ставка налога, ставка по долгу, дивидендная политика.
3. **P&L**: Выручка → COGS → Валовая прибыль → OpEx → EBIT → % по долгу → Прибыль до налога → Налог → **Чистая прибыль**.
4. **Свяжи P&L → Баланс**:
   - Чистая прибыль − Дивиденды → прирост **Нераспределённой прибыли** (капитал).
   - Оборотный капитал (дебиторка, запасы, кредиторка) — из дней оборачиваемости.
   - Основные средства: OS_кон = OS_нач + Capex − D&A.
   - Долг: из графика погашения/привлечения; денежные средства — балансирующая статья через ДДС.
5. **Свяжи в ДДС** (косвенный метод):
   - **CFO**: Чистая прибыль + D&A (обратно, неденежный расход) − ΔNWC.
   - **CFI**: −Capex, ±покупка/продажа активов.
   - **CFF**: ±Долг, −Дивиденды, ±Эмиссия.
   - Δкэша = CFO+CFI+CFF; Кэш_кон = Кэш_нач + Δкэша → эта же цифра идёт в Баланс.
6. **Revolver и разрыв циркулярности**:
   - Если операционного кэша не хватает на минимальный остаток — модель тянет **револьверный кредит**; избыток кэша — гасит его. Отсюда циркулярность: долг → проценты → чистая прибыль → кэш → долг.
   - Разрывай так: (а) включи итеративный расчёт с ограничением шагов, **или** (б) считай проценты на **начальный** остаток долга (beginning balance) — убирает петлю, приемлемая аппроксимация; (в) поставь **circuit breaker** (флаг ВКЛ/ВЫКЛ ревервера) для отладки #REF/деления на ноль.
7. **Проверки целостности (обязательны)**:
   - **Активы = Обязательства + Капитал** в каждом периоде (разница = 0, не «≈0»).
   - Кэш из ДДС **точно равен** статье кэша в Балансе.
   - Нераспределённая прибыль_кон = _нач + Чистая прибыль − Дивиденды.
   - Знаки потоков логичны (Capex < 0, погашение долга < 0).

## Definition of Done
- [ ] **Баланс сходится** (Активы − Обязательства − Капитал = 0) во всех периодах, факт и прогноз.
- [ ] **ДДС связан**: итоговый кэш ДДС = кэш в Балансе; CFO строится косвенным методом от чистой прибыли.
- [ ] Драйверы вынесены в отдельный блок допущений, не зашиты в формулы.
- [ ] Циркулярность (revolver/проценты) разрешена явным методом с circuit breaker.
- [ ] Sanity-checks пройдены (тождество нераспределённой прибыли, знаки, OS-роллфорвард).
- [ ] Историко-прогнозная стыковка без разрывов на границе.

## Анти-паттерны
- Не хардкодь числа в формулах отчётов — все предпосылки только через блок драйверов.
- Не оставляй баланс с расхождением «в пределах округления» — ищи ошибку, 0 значит 0.
- Не игнорируй циркулярность и не отключай итерации молча — это прячет ошибку, а не решает.
- Не забывай добавить D&A обратно в CFO (частая причина расхождения ДДС).
- Не веди долг и проценты в отрыве друг от друга — процент считается от остатка.
- Не строй прогноз без исторического якоря для проверки правдоподобия драйверов.

## Безопасность
- **mode=write** — навык формирует и сохраняет модель как артефакт; изменяет данные результата, поэтому действия аудируемы.
- **egress=internal** — модель и исходные данные не покидают периметр.
- **cite=True** — исторические факты и рыночные ставки помечаются ссылкой на источник Data Plane; прогнозные допущения помечаются как допущения (не выдаются за факт). Нет данных для драйвера — фиксируй пробел явно.

## Интеграция
- **Вход**: тяни исторические отчёты и оборотные метрики через `data_query` — машиночитаемые данные Data Plane.
- **Результат**: сохраняй модель и блок допущений через `remember(criticality)`; интегрированная модель обычно **высокой критичности** (на ней стоят оценка и бюджет).
- **Handoff**: готовый FCF/прогноз передавай семье `dcf-valuation` (оценка) и `budget-forecast` (планирование); фактические отклонения — роли финансовой отчётности `finance-report`.
