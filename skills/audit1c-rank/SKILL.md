# Ранжирование находок по существенности (rank-findings)

Ты расставляешь находки по важности так, как это сделал бы главный аудитор: сверху то, что грозит доначислением/штрафом или искажает отчётность существенно, снизу — мелочь. Существенность — не «серьёзность» из движка сама по себе, а её сочетание с суммой влияния, налоговым риском и охватом. Цель — чтобы менеджмент за 30 секунд понял, за что хвататься.

## Когда применять
- Есть находки (`audit1c-checks`) и/или первопричины (`audit1c-root-cause`) — нужен порядок работы.
- Перед отчётом/письмом — вынести критичное наверх.
- Нужно отделить существенное от формального (для приоритизации исправлений).

## Метод (пошагово)
1. **Оцени сумму влияния** каждой находки: сумма документа/проводки, размер незакрытого НДС, объём деб/кредиторки. Бери числа из данных, не прикидывай.
2. **Оцени нормативный/налоговый риск**: разрыв по НДС (нет счёта-фактуры) и ВГО без элиминации — высокий риск (доначисление/искажение консолидации); переходящие/дебиторка — средний; НСИ-дубль — риск задвоения расчётов.
3. **Учти класс и охват**: инварианты (A) и цепочки НДС (B) обычно выше формальных; причина, порождающая много находок (из root-cause), поднимается вверх.
4. **Сформируй ранг**: критично / существенно / умеренно / формально — с явным критерием, почему именно так (сумма + риск + охват), а не «на глаз».
5. **Проверь на существенность (materiality)**: мелкие суммы ниже порога не раздувай до критичных; крупные и нормативные — не прячь вниз.

## Definition of Done
- [ ] У каждой находки/причины есть ранг существенности с обоснованием (сумма + риск + охват).
- [ ] Суммы влияния взяты из данных, а не прикинуты.
- [ ] Налоговый/нормативный риск учтён (НДС, ВГО, деб/кредиторка).
- [ ] Порядок отражает существенность, а не класс сам по себе и не алфавит.
- [ ] Применён порог существенности — формальное не выдаётся за критичное и наоборот.

## Анти-паттерны
- Не ранжируй по одной «серьёзности» из движка, игнорируя сумму и риск.
- Не прикидывай суммы влияния — бери из проводок/документов.
- Не хорони крупную/нормативную находку внизу ради «баланса» списка.
- Не раздувай формальную мелочь до критичной ради длины отчёта.
- Не ранжируй без критерия — «важно/не важно» без обоснования не примут.

## Безопасность
- **mode=read** — приоритизация поверх находок; данные не изменяются.
- **egress=internal** — внутри периметра.
- **cite=True** — ранг обоснован суммами и нормами из данных, а не мнением.

## Интеграция
- **Вход**: находки из `audit1c-checks`, причины из `audit1c-root-cause`; суммы — из `doc1c` через `data_query`.
- **Результат**: ранжированный реестр (критично→формально) с обоснованием — на доску.
- **Handoff**: → `audit1c-explain` (оформить объяснение и отчёт в порядке существенности).
