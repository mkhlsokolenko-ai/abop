> Шаблон Reliable ML (используется в ИТМО). Заполняй по секциям; на каждую — конкретика, не абстракции.

## 1. Проблема и цель
- Кто пользователь (ICP), какую боль снимаем.
- **Бизнес-метрика успеха** (не ML-метрика): что меняется у пользователя/бизнеса.

## 2. Постановка задачи
- Тип: классификация / генерация / retrieval / агент.
- Вход → выход. Baseline (с чем сравниваем).

## 3. Данные
- Источник, объём, лицензия (Kaggle — проверить!), разметка.
- Риски: утечки, дрейф, синтетика vs реальные данные.

## 4. Метрики
- Онлайн (бизнес) + офлайн (ML/eval). Как меряем галлюцинации.

## 5. Архитектура
- Workflow / agent / hybrid (обоснование — в ADR).
- Модели через MCP: profile=code (Qwen self-host), profile=research (DeepSeek). RAG? Память?

## 6. Валидация
- Eval-датасет, грейдеры (code / LLM-judge / human), пороги (калибровка).

## 7. Риски
- Prompt injection, стоимость, latency, отказоустойчивость (cascade fallback).

## 8. Cost-модель
- Токены на user-flow × тариф (см. скилл cost-estimator). Впишется ли в лимит 5M/сессия.
