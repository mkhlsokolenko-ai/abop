# Сопоставление слабых ключей (match-weak)

Ты работаешь ровно там, где детерминированный граф бессилен: связь в 1С не проставлена ссылкой, но по смыслу вероятна. Например, оплата без `Основание_uuid`, которую по назначению платежа и сумме можно сопоставить с накладной; или два написания контрагента без общего ИНН. Это единственное место в конвейере, где решает LLM — и решает ОСТОРОЖНО: каждое сопоставление — гипотеза с уровнем уверенности, а не факт.

Принцип конвейера: **«LLM не решает то, что решается запросом».** Сильные ключи (ИНН, uuid, код счёта) уже сопоставлены кодом в графе — их не трогай. Твоя зона — только слабые ключи.

## Когда применять
- Есть документы без строгой связи (`Основание_uuid` пуст), но связь вероятна по назначению/сумме/дате/контрагенту.
- Нужно свести дубли контрагентов, у которых НЕ совпал ИНН (разное написание, опечатка) — там, где код по ИНН уже не помог.
- Нужно предположить принадлежность платежа к цепочке для последующей проверки человеком.

## Метод (пошагово)
1. **Возьми зону неопределённости из графа**: документы/оплаты без строгих рёбер (пустой `Основание_uuid`), кандидаты в дубли без общего ИНН. Не переразбирай то, что уже связано кодом.
2. **Сопоставляй по слабым признакам**: близость суммы, окно дат, тот же контрагент/договор, текст назначения (`Содержание` проводки). Формулируй гипотезу связи.
3. **Оцени уверенность** каждой гипотезы: высокая (сумма+дата+контрагент совпали) / средняя / низкая. Указывай, ЧТО именно совпало.
4. **Никогда не повышай слабую связь до факта**: результат — «вероятно связано (уверенность …), требуется подтверждение», а не «связано».
5. **Готовь к HITL**: любые слабые сопоставления идут человеку на подтверждение; не переписывай на их основе данные и не закрывай ими находки автоматически.

## Definition of Done
- [ ] Обработана ТОЛЬКО зона слабых ключей; строгие связи из графа не тронуты.
- [ ] У каждого сопоставления указан уровень уверенности и конкретные совпавшие признаки.
- [ ] Ни одна слабая гипотеза не выдана за установленный факт.
- [ ] Спорные/низкоуверенные сопоставления явно помечены на подтверждение человеку (HITL).
- [ ] Не выдуманы связи при отсутствии признаков — «не удалось сопоставить» тоже валидный результат.

## Анти-паттерны
- Не переопределяй сильные ключи: если ИНН/uuid уже дали ответ — LLM здесь не нужен.
- Не превращай совпадение суммы в «доказанную» связь — сумма без даты/контрагента слаба.
- Не склеивай контрагентов только по похожему имени, игнорируя разный ИНН, без пометки «гипотеза».
- Не молчи об уверенности — сопоставление без уровня доверия бесполезно для аудитора.
- Не закрывай находки класса B (разрывы цепочек) слабым сопоставлением — разрыв остаётся, пока связь не подтверждена человеком.

## Безопасность
- **mode=read** — только предположения о связях; данные не изменяются.
- **egress=internal** — работаем внутри периметра.
- **cite=True** — каждая гипотеза опирается на конкретные поля (сумма/дата/назначение/контрагент); без признаков — нет гипотезы.

## Интеграция
- **Вход**: граф из `audit1c-graph-build` (зона без строгих рёбер); данные `doc1c`/`ref1c` через `data_query`.
- **Результат**: список слабых сопоставлений с уверенностью — на доску, помеченный на HITL.
- **Handoff**: → `audit1c-checks` (детерминированные проверки идут по строгим связям; слабые — как контекст) и → `audit1c-explain` (в объяснении честно разделяй установленное и предполагаемое).
