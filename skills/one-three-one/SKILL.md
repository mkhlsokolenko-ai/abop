# One-Three-One

Ты упаковываешь развилку в формат, по которому стейкхолдер **принимает решение**, а не открывает ещё один раунд обсуждения: одна измеримая проблема, ровно три честных варианта с trade-off, одна рекомендация с обоснованием и следующим шагом. Дисциплина мышления, а не презентация.

## Когда применять
- Нужно решение стейкхолдера/руководства по развилке, а не дискуссия.
- Есть несколько путей и надо честно сравнить их, а не протащить любимый.
- Перед комитетом/владельцем: свернуть анализ в одну страницу «проблема → варианты → рекомендация».
- Когда обсуждение ходит по кругу — формат заставляет назвать проблему и выбрать.

## Метод (пошагово)
1. **1 Проблема.** Сформулируй одну проблему чётко и **измеримо**: что не так, в каких цифрах это болит, и — обязательно — **последствие бездействия** (что произойдёт и когда, если ничего не делать). Без метрики и цены бездействия проблема не готова.
2. **3 Варианта.** Ровно три **реальных** варианта решения. Каждый с явными trade-off по единым критериям:
   - **стоимость** (деньги/ресурс),
   - **риск** (что может пойти не так, вероятность/тяжесть),
   - **срок** (когда даст эффект),
   - **эффект** (что изменится в метрике проблемы).
   Варианты должны быть жизнеспособными альтернативами — не «один хороший + два соломенных чучела».
3. **1 Рекомендация.** Выбери один вариант и обоснуй выбор **по тем же критериям** (почему trade-off приемлем именно здесь). Назови, что делает выбор обратимым/необратимым.
4. **Next-step.** Конкретный первый шаг: кто, что, к какому сроку. Решение без next-step — не решение.

## Definition of Done
- [ ] Проблема измерима и содержит последствие бездействия.
- [ ] Ровно 3 варианта, все жизнеспособны (нет соломенных чучел вокруг одного «правильного»).
- [ ] У каждого варианта заполнены все критерии trade-off (стоимость/риск/срок/эффект).
- [ ] Рекомендация обоснована по тем же критериям, не «интуитивно».
- [ ] Есть конкретный next-step: кто, что, срок.

## Анти-паттерны
- Проблема как жалоба без метрики и без цены бездействия.
- 1 хороший вариант + 2 соломенных для видимости выбора.
- Разные критерии для разных вариантов (сравнение несопоставимого).
- Рекомендация не следует из критериев; выбор сделан заранее, анализ подгонкой.
- Нет next-step — решение повисает.

## Безопасность
- **mode=read** — только анализируешь и структурируешь, ничего не пишешь во внешние системы.
- **egress=internal** — работаешь на внутренних данных развилки; наружу ничего не отправляешь.
- **cite=False** — внешние цитаты не требуются; но числа в проблеме и вариантах должны опираться на предоставленные внутренние данные, а допущения помечаться явно.
- Не выводи чувствительные данные за пределы того, что нужно для решения.

## Интеграция
- **Вход:** через `data_query` получи контекст развилки, метрики проблемы и ограничения (бюджет, сроки, риск-аппетит) для честного trade-off.
- **Итог:** зафиксируй решение через `remember(criticality=...)` — выбор варианта и его обратимость определяют criticality (необратимые/дорогие решения — выше).
- **Передача:** используй `handoff` при передаче рекомендации на исполнение — приложи выбранный вариант, обоснование и next-step с ответственным.
