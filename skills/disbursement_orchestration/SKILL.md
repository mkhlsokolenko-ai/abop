# Disbursement Orchestration

Ты готовишь выдачу средств — самый критичный шаг конвейера: движение денег во внешнюю систему (core-banking). `mode=action, egress=external` → **всегда через dry_run + HITL**. Агент не проводит выдачу сам; он готовит её к одобрению и проводит только после approve оператора.

## Когда применять
- Заявка одобрена (limit_policy_enforcement дал `approved`), подписан договор — нужно выдать средства.
- Транш по кредитной линии в рамках уже одобренного лимита.

## Метод (пошагово)
1. **Пред-условия (hard-gates).** Прежде чем готовить выдачу проверь: вердикт `approved` актуален, договор подписан, реквизиты получателя верифицированы, сумма ≤ одобренного лимита, нет новых стоп-факторов/двойной выдачи.
2. **Собери платёжное намерение:** получатель, реквизиты, сумма, валюта, назначение, ссылка на заявку/договор (провенанс).
3. **dry_run.** Сформируй предпросмотр операции без проведения: что и куда уйдёт, какие проверки пройдены, оценка комиссий. Никаких списаний на этом шаге.
4. **HITL-approve.** Передай dry_run оператору: `Разрешить / Отклонить` с причиной. Без approve — стоп. Крупные/пограничные суммы могут требовать второго контроля (по DeploymentContract).
5. **Проведение** только после approve: инициируй операцию в core-banking, дождись подтверждения, зафиксируй `disbursement_id` с обратной ссылкой на заявку и на решение оператора (кто, когда).
6. **Постпроверка и откат.** Сверь проведённую сумму с намерением; при расхождении — стоп и эскалация. Идемпотентность: повтор не должен создать вторую выдачу.

## Definition of Done
- Ни одно списание не прошло без dry_run + HITL-approve (зафиксирован оператор).
- Проведённая операция сверена с намерением; есть disbursement_id и провенанс.
- Защита от двойной выдачи (идемпотентность) работает.

## Анти-паттерны
- Проведение выдачи автономно, без approve оператора.
- Выдача суммы больше одобренного лимита или по неверифицированным реквизитам.
- Отсутствие обратной ссылки на решение и на оператора в аудит-следе.
