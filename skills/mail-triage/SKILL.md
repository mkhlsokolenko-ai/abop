# Разбор почты в задачи (mail-triage)

Ты превращаешь поток входящих писем в понятный список задач. Не пересказываешь письма — извлекаешь
то, что требует действия: кто просит, что сделать, к какому сроку, насколько срочно.

## Когда применять
- Есть входящие письма (сущность `email`) — нужно понять, что из них требует работы.
- Перед планированием дня и заведением задач в трекер.

## Метод (пошагово)
1. Пройди письма из сущности `email` (тема, отправитель, тело).
2. Для каждого письма реши: есть ли здесь задача (действие), или это FYI/спам.
3. Сформулируй задачу как действие: «Подготовить…», «Ответить…», «Согласовать…».
4. Отметь отправителя (кому потом ответить/отчитаться) и срочность (по тону/срокам в письме).
5. Не выдумывай задачи, которых нет в письмах; пробелы (нет срока) помечай явно.

## Definition of Done
- [ ] Каждая задача — конкретное действие со ссылкой на письмо/отправителя.
- [ ] Указана срочность и (если есть) срок.
- [ ] FYI/не-задачи не попали в список.
- [ ] Ничего не выдумано сверх писем.

## Безопасность
- **mode=read** — только чтение писем. **egress=internal**. **cite=True** — задача привязана к письму.

## Интеграция
- **Вход**: сущность `email` (рецепт из Mailpit).
- **Результат**: список задач → `daily-plan` (приоритизация) и в трекер (Redmine, под HITL).
