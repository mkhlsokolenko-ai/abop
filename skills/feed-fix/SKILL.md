# Исправление карточки под витрину (feed-fix)

Проверки уже сказали, что не так. Здесь ты готовишь **кандидата на отправку**: что именно поменять в карточке, чтобы витрина её приняла. Это единственный шаг кейса, где модель уместна, — и ровно поэтому границы у него жёсткие.

## Что можно делать
- **Название**: убрать рекламную формулировку, сократить до лимита категории, сохранив бренд, тип товара и модель.
- **Единицы**: привести значение к единице, которую ждёт витрина, если пересчёт однозначен (мм → см). Неоднозначный пересчёт — не твоя работа.
- **Атрибуты**: заполнить те, что **выводятся из самой карточки** (бренд из поля бренда, габариты из описания, если они там есть буквально).
- **Категория**: при `CATEGORY_UNMAPPED` предложить категорию витрины и указать, на чём основано предложение — совпадение названия категории, типа товара, атрибутов.

## Чего делать нельзя
- **Не придумывать значения атрибутов.** Нет объёма в литрах — пиши «нужны данные поставщика», а не правдоподобное число. Выдуманный атрибут проходит модерацию и возвращается рекламацией.
- **Не менять смысл названия**: модель товара, бренд и тип не переписываются ради лимита.
- **Не «исправлять» маркировку и изображения.** Их нельзя получить из текста — это очередь человека.
- **Не подтверждать категорию как решённую.** Предложение категории — предложение; в справочник его вносит человек.

## Метод (пошагово)
1. Возьми нарушения карточки (`feed_checks` с `{"карточка": "…"}`).
2. Для каждого реши: исправление выводится из данных или нужен человек. Сомневаешься — человек.
3. Собери **кандидата**: исходное значение → предлагаемое → основание. Без основания правка не принимается.
4. Отдельным списком — то, что чинится только человеком, с конкретным запросом («нужен снимок, 3 шт.», «нужна маркировка ЕАС», «нужно решение по категории»).
5. Отдельной строкой — чего не хватает в данных поставщика, чтобы закрыть остальное.

## Definition of Done
- [ ] По каждой карточке есть кандидат на отправку либо явный отказ «чинится только человеком».
- [ ] У каждой правки указано основание (поле данных или правило витрины).
- [ ] Ни одно значение атрибута не придумано: невыводимое помечено как запрос к поставщику.
- [ ] Предложенные категории помечены как предложение, а не как факт.
- [ ] Посчитано, сколько карточек уходит сразу, сколько ждёт человека и сколько —
      данных поставщика. Эти три числа равны длинам трёх списков выше: счётчик,
      расходящийся со своим же перечнем, — это выдуманное число.

## Анти-паттерны
- Не заполняй обязательные атрибуты «типичными» значениями категории — это и есть выдумывание.
- Не выбрасывай из названия модель или бренд, чтобы уложиться в лимит.
- Не предлагай категорию «наугад похожую»: без основания лучше честное «соответствия нет».

## Безопасность
- **mode=create** — готовится кандидат, сама карточка никуда не отправляется.
- **egress=internal** — наружу ничего не уходит; публикация идёт через узел доставки с подтверждением.
- **cite=True** — у каждой правки основание из данных или правил витрины.
