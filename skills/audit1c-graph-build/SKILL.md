# Построение графа связей 1С (graph-build)

Ты превращаешь плоский набор документов в связный граф — так, как эти связи РЕАЛЬНО заданы в 1С: документ-основание, субконто проводок, коды счетов, ИНН. Это Граф-RAG для аудита: по нему детерминированно ходят проверки и строятся объяснения. Ключевой принцип — **связь либо есть в данных (uuid/ИНН/код), либо её нет**; граф не выдумывает рёбра.

## Когда применять
- После `audit1c-extract`, перед проверками — нужна связная модель периода.
- Нужно проследить цепочку (Поступление→СчётФактура→Оплата) или найти её разрыв.
- Нужны индексы для проверок: коды счетов по uuid, ИНН организаций/контрагентов.

## Метод (пошагово)
1. **Построй граф инструментом** `audit1c_graph` — он читает `doc1c`/`ref1c` и возвращает сводку: число документов по типам, рёбра `основание→`, размер плана счетов, число организаций по ИНН, дубли ИНН контрагентов.
2. **Узлы** — документы (по `id`=uuid). **Рёбра `основание→`** — из поля `Основание_uuid` (реальная basis-ссылка 1С): СчётФактура→Поступление/Реализация, Оплата→документ поставки/реализации.
3. **Индекс счетов**: uuid счёта → `Код` (60/62/90.01/…) через справочник `Счета`. Проводки хранят счёт как `{uuid,представление}`; код берётся join'ом по uuid — по нему считаются инварианты.
4. **Индексы ИНН**: множество ИНН наших организаций и карта ИНН→карточки контрагентов (для ВГО и дублей НСИ). Сильные ключи (ИНН, uuid) — детерминированы, здесь догадок нет.
5. **Проверь связность**: рёбер `основание→` должно быть сопоставимо числу цепочечных документов; аномально мало рёбер = проблема извлечения или массовый разрыв цепочек (сигнал для проверок класса B).

## Definition of Done
- [ ] `audit1c_graph` отработал; сводка получена и осмыслена (типы, рёбра, счета, ИНН).
- [ ] Basis-рёбра построены из реальных `Основание_uuid`, а не восстановлены эвристикой.
- [ ] Индекс кодов счетов заполнен (иначе инварианты класса A не посчитать).
- [ ] Индексы ИНН организаций и контрагентов готовы (для классов C/D).
- [ ] Оценена связность: число рёбер согласуется с числом цепочечных документов.

## Анти-паттерны
- Не достраивай «логичные» рёбра по совпадению суммы/даты, если нет ссылки `Основание_uuid` — отсутствие ребра само по себе находка (разрыв цепочки).
- Не сопоставляй счета по названию — только по коду через справочник (названия неоднозначны, коды каноничны).
- Не подменяй сильный ключ (ИНН/uuid) слабым (имя) на этапе графа — нечёткое сопоставление это отдельный навык `audit1c-match-weak`.
- Не игнорируй пустые ссылки — пустой `Основание_uuid` у оплаты значим, не «мусор».

## Безопасность
- **mode=read** — построение графа поверх канонических данных; ничего не изменяется.
- **egress=internal** — работаем внутри Data Plane, наружу ничего не уходит.
- **cite=True** — каждое ребро/связь прослеживается до конкретного поля документа (uuid основания, код счёта, ИНН); граф — доказательная основа находок.

## Интеграция
- **Вход**: сущности `doc1c`/`ref1c`; инструмент `audit1c_graph`.
- **Результат**: сводка графа и индексы; заметку о связности — на доску.
- **Handoff**: → `audit1c-match-weak` (сопоставить слабые ключи там, где нет uuid/ИНН) и далее → `audit1c-checks` (детерминированные проверки по графу).
