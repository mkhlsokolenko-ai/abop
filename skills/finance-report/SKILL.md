# Finance Report

Ты готовишь управленческий отчёт, который **объясняет, а не просто показывает** цифры. Менеджмент должен из него понять: что произошло, почему отклонились от плана, какие драйверы сработали и чего ждать дальше. Не дашборд ради дашборда, а разбор с причинно-следственной логикой и ссылками на источник каждой цифры.

## Когда применять
- Закрыт период (месяц/квартал) — нужен управленческий отчёт по факту.
- Требуется разбор отклонений факт vs план/бюджет с объяснением причин.
- Нужен взгляд по сегментам/направлениям, а не только консолидированный итог.
- Нужен обоснованный краткосрочный outlook на базе фактической динамики.

## Метод (пошагово)
1. **P&L за период** + ключевые KPI: выручка, валовая/EBIT/чистая маржа, EBITDA, KPI юнита (ARPU, CAC, retention — если применимо к бизнесу).
2. **Динамика MoM и YoY**: считай и абсолютное, и процентное изменение. YoY снимает сезонность, MoM ловит свежий тренд — показывай оба.
3. **Variance-анализ vs план (мост отклонений / bridge)**:
   - Разложи отклонение факт−план на компоненты: **эффект объёма** (Δколичество × план-цена), **эффект цены/микса** (Δцена × факт-объём), **эффект затрат** (Δставка расхода). Сумма компонентов = полное отклонение.
   - Каждый компонент привяжи к **драйверу** («выручка −8% из-за оттока 3 крупных клиентов», а не «выручка ниже плана»).
4. **Сегменты**: раскрой P&L/маржу по направлениям, регионам или продуктам; подсвети, кто тянет вверх/вниз консолидированный результат.
5. **Forward outlook на факте**: краткий прогноз остатка года/следующего периода, опираясь на run-rate факта, воронку и известные события. Помечай допущения.

## Definition of Done
- [ ] Каждая цифра имеет **ссылку на источник** в Data Plane (нет чисел «из головы»).
- [ ] Отклонения от плана **объяснены драйверами**, а не констатированы.
- [ ] Мост отклонений (объём/цена/затраты) сходится: сумма компонентов = полное отклонение.
- [ ] Представлены и MoM, и YoY.
- [ ] Разбивка по сегментам с указанием главных драйверов результата.
- [ ] Forward outlook обоснован фактом; допущения помечены.
- [ ] Нет экстраполяции без данных — прогноз опирается на факт/воронку, не на «нарисованный» тренд.

## Анти-паттерны
- Не показывай отклонение без объяснения его причины — «факт ниже плана» без драйвера бесполезно.
- Не давай только MoM или только YoY — один без другого искажает картину (сезонность/тренд).
- Не экстраполируй тренд в outlook без опоры на данные (воронка, контракты, run-rate).
- Не смешивай форматы отчётности между периодами — иначе динамика несопоставима.
- Не прячь плохой сегмент в консолидированном итоге — раскрой источник результата.
- Не выдумывай цифру, если источник недоступен — зафиксируй пробел явно.

## Безопасность
- **mode=write** — навык формирует и публикует отчёт как артефакт; действия аудируемы.
- **egress=internal** — отчёт и данные остаются внутри периметра, наружу не уходят.
- **cite=True** — под каждой цифрой ссылка на первичный источник Data Plane; отклонения обосновываются данными, а не нарративом. Нет источника — прямо укажи пробел, не подставляй оценку.

## Интеграция
- **Вход**: получай фактические данные периода, план/бюджет и сегментные срезы через `data_query` — машиночитаемые данные Data Plane.
- **Результат**: сохраняй отчёт через `remember(criticality)`; управленческая отчётность — обычно **средней/высокой критичности** (основа управленческих решений).
- **Handoff**: выявленные отклонения факт/план передавай семье `budget-forecast` как обратную связь для пересмотра прогноза; при запросе на оценку/модель — `three-statement-model` / `dcf-valuation`.
