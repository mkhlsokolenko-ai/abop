# Детерминированные проверки аудита (checks-run)

Ты запускаешь движок проверок и работаешь с его результатом. Сами находки вычисляет КОД инструментом `audit1c_checks` — по реальным ссылкам 1С (документ-основание, коды счетов, ИНН), детерминированно и воспроизводимо. Это принципиально: **аудиторская находка не должна зависеть от «настроения» модели**. Твоя роль — прогнать проверки, сгруппировать и передать дальше, ничего не выдумывая и ничего не пропуская.

## Когда применять
- После графа (`audit1c-graph-build`) — искать нарушения по связному периоду.
- Нужен полный реестр находок по классам A/B/C/D с доказательствами.
- Нужен срез по одному классу (например, только цепочки B) — инструмент принимает фильтр `класс`.

## Метод (пошагово)
1. **Запусти проверки** инструментом `audit1c_checks` (опц. `{"класс":"A|B|C|D"}`). Получишь `{всего, по классам, находки[]}`; каждая находка: `id, класс, проверка, серьёзность, документ, описание, доказательство`.
2. **Классы**: **A** — инварианты проводок (напр. реализация без списания себестоимости 90.02); **B** — разрывы цепочек по basis-ссылкам (реализация/поступление без счёта-фактуры, оплата без основания, деб/кредиторка); **C** — НСИ (дубль контрагента по ИНН); **D** — нормы (ВГО по совпадению ИНН с организацией холдинга, переходящие операции между периодами).
3. **Проверь доказательство каждой находки**: в `доказательство` — конкретная ссылка (нет документа-основания, коды Дт-проводок, ИНН, даты). Находка без доказательства не годится — но движок их проставляет; твоя задача сверить, а не переписать.
4. **Ничего не добавляй и не убирай на глаз**: если кажется, что нарушение есть, а движок молчит — это сигнал доработать ПРОВЕРКУ (код), а не дописать находку текстом. Наоборот, не отбрасывай находку движка, потому что «наверное ок».
5. **Передай реестр дальше** для поиска первопричины и ранжирования; отметь на доске сводку по классам.

## Definition of Done
- [ ] `audit1c_checks` отработал; получен полный реестр находок с разбивкой по классам.
- [ ] У каждой находки есть класс, серьёзность, привязка к документу и доказательство.
- [ ] Реестр не дополнялся и не сокращался «вручную» — только результат движка.
- [ ] Пробелы в покрытии (нужна новая проверка) зафиксированы как задача на код, а не закрыты текстом.
- [ ] Сводка по классам отмечена на доске.

## Анти-паттерны
- Не «находи» нарушения рассуждением LLM в обход движка — это нарушает принцип детерминизма и невоспроизводимо.
- Не отбрасывай находку кода, посчитав её ложной «на глаз» — если это ложное срабатывание, чини проверку, а не прячь результат.
- Не теряй доказательство — находка без ссылки на первичные данные неаудируема.
- Не смешивай классы: разрыв цепочки (B) и инвариант проводки (A) требуют разных действий.
- Не считай отсутствие находок «успехом периода» без покрытия — сообщи, какие проверки реально отработали.

## Безопасность
- **mode=read** — только вычисление находок по данным; ничего не изменяется.
- **egress=internal** — проверки идут внутри Data Plane.
- **cite=True** — каждая находка несёт доказательство (ссылка на документ/проводку/ИНН); чисел и связей «из головы» нет.

## Интеграция
- **Вход**: граф из `audit1c-graph-build`; инструмент `audit1c_checks` (данные `doc1c`/`ref1c`).
- **Результат**: реестр находок A/B/C/D с доказательствами — на доску.
- **Handoff**: → `audit1c-root-cause` (сгруппировать в первопричины) → `audit1c-rank` (ранжировать по существенности).
