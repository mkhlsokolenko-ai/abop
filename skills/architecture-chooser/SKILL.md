# Architecture Chooser

Ты помогаешь честно выбрать между **workflow** (код управляет шагами) и **agent** (модель сама выбирает траекторию). Дефолт — самое простое, что решает задачу.

## Когда применять
- В начале проектирования, до написания дизайн-дока.
- Когда неясно, нужен ли агент или хватит детерминированного pipeline.
- Когда есть соблазн «сделать агента, потому что модно» — проверить честными критериями.

## Метод / Критерии (проходим все четыре)
1. **Сложность.** Задачу можно полностью описать шагами заранее? → workflow. Открытая, плохо специфицируется? → agent.
2. **Ценность.** Оправдывает ли результат более высокую стоимость и latency агента?
3. **Выполнимость.** Модель вообще справляется с этим типом задач?
4. **Цена ошибки.** Можно ли поймать и откатить ошибку (тесты, ревью)? Если нет — упрощай.

## Решение
- **Один LLM-вызов** — классификация, суммаризация, извлечение. Не усложняй.
- **Workflow** — многошаговый, но детерминированный pipeline (RAG-ответ, генерация-по-шаблону).
- **Agent** — открытая траектория, много инструментов, заранее не знаешь план.
- **Hybrid** — агент внутри, но ключевые переходы под контролем кода.

## Правила
- Если сомневаешься — бери уровень проще. Агент — не престиж, а последнее средство.
- Зафиксируй выбор и обоснование в ADR (см. `adr-writer`).

## Definition of Done
- [ ] Пройдены все четыре критерия (сложность, ценность, выполнимость, цена ошибки).
- [ ] Выбран уровень: один LLM-вызов / workflow / agent / hybrid — с явным обоснованием.
- [ ] Проверено, что более простой уровень действительно не решает задачу (агент — не по инерции).
- [ ] Для agent/hybrid зафиксировано, какие переходы остаются под контролем кода (аудируемость).
- [ ] Выбор и обоснование записаны в ADR (`adr-writer`).

## Анти-паттерны
- Выбрать агента «для престижа», хотя задача полностью описывается шагами → workflow.
- Игнорировать цену ошибки: свободная траектория там, где ошибку нельзя откатить.
- Свободный цикл агента без wired-переходов, когда нужна аудируемость (регулируемый домен).
- Пропустить фиксацию решения в ADR — выбор теряется, нельзя пересмотреть осознанно.
- Усложнять до workflow там, где хватает одного LLM-вызова.

## Безопасность
- `mode=read`, `egress=internal`, `cite=False`.
- Навык только анализирует и выбирает архитектуру (read) — ничего не поднимает и наружу не ходит.
- Выбор архитектуры — вход для гейта конверта: свободная траектория повышает риск, гибрид с wired-переходами его снижает (аудируемость).

## Интеграция
- `data_query`: на входе возьми требования/ограничения задачи и домена (цена ошибки, регуляторика) — критерии считаются по фактам.
- `remember(criticality)`: пометь критичность решения — выбор agent vs workflow влияет на профиль риска конверта.
- `handoff`: при выборе агента передай проектирование в `agent-design-writer`; решение и обоснование — в `adr-writer`.
