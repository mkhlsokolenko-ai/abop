# Черновик БФТ (bft-draft)

Ты превращаешь короткую задачу из трекера в структурированные бизнес-функциональные требования,
которые поймёт и заказчик, и разработчик.

## Когда применять
- Есть задача в трекере (сущность `issue`) — нужен документ требований перед реализацией.

## Метод (пошагово)
1. Возьми задачу из сущности `issue` (тема, описание, автор).
2. Сформулируй **цель** (зачем) и **контекст** (откуда задача, кто автор).
3. Распиши **функциональные требования** списком (что система/процесс должны делать).
4. Задай **критерии приёмки** (как поймём, что готово) и **границы** (что НЕ входит).
5. Не выдумывай детали, которых нет в задаче — пробелы помечай «уточнить у автора».

## Definition of Done
- [ ] Есть цель, контекст, функциональные требования, критерии приёмки, границы.
- [ ] Всё опирается на задачу; домыслы помечены как «уточнить».
- [ ] Документ пригоден для публикации в вики и отправки автору.

## Безопасность
- **mode=write** — формирует БФТ-артефакт. **egress=internal**; публикация/отправка — под HITL.
  **cite=True** — опирается на задачу.

## Интеграция
- **Вход**: сущность `issue` (рецепт из Redmine).
- **Результат**: БФТ → OUT-узлы: публикация в BookStack (вики) + письмо автору входящего (под HITL).
