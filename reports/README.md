# Шаблоны отчётов (PDF/HTML) — `reports/<id>.html`

Отчёт прогона рендерится по шаблону: HTML с плейсхолдерами `{{…}}` + общий `base.css`. Файлы здесь — посев;
в рантайме источник правды — таблица `report_templates` в БД (веб-редактор с превью, `/api/report-templates`).
Правка в UI имеет приоритет над посевом; builtin-шаблон с `editor=seed` обновляется при старте, если файл изменился.

Плейсхолдеры (готовит `web_api._report_context`): `title`, `agent`, `date`, `verdict`, `findings_total`, `investigations_total`,
`by_class`, `charts`, `findings`, `investigations`, `deliveries`, `skills` (структурированные ответы всех навыков по их
шаблонам извлечения — таблицы/списки) и `skill_<sid>` для конкретного навыка (дефисы → подчёркивания:
`{{skill_audit1c_rank}}`, `{{skill_invest1c_verdict}}`). Пустой плейсхолдер рендерится как пусто.

Где используется: `GET /api/runs/{run_id}/report?template=<id>&format=html|pdf` (кнопка «Отчёт PDF» в десктопе),
OUT-узлы каналов pdf/email/bookstack (`report_template_id` узла, иначе авто-выбор по форме результата).
`index.json` — имена и pdf_options по id.

Экспертная разметка пилота (слепые решения по находкам из интерфейса) доступна плейсхолдерами `{{разметка_сводка}}` (точность, межучастковые, «вручную бы не нашли» против порогов) и `{{разметка}}` (находки со статусом «подтверждена/отклонена»). Без разметки оба пустые — секция в отчёте не появляется.

## Бланки под вертикали: раскладка документа

Получатель кредитного заключения, ADR и делового письма читает **разные документы** — с разным
порядком разделов, разными обязательными графами и разной мерой ответственности. Одинаковая
последовательность плейсхолдеров превращала их в один отчёт с другой подписью снизу.

Поэтому у формы есть **раскладка** (`layout` в `index.json`, колонка `layout JSONB` в
`report_templates`), а HTML такой формы — одна строка: `{{blank}}` плюс служебные блоки. Образец —
форма аудита 1С, согласованная с заказчиком: шапка с объёмом работы и методом, затем пункты
карточками с подписанными графами, бейдж существенности, код пункта, оговорка о границах документа.

Правят раскладку в БД (форма и её вид лежат в одной записи) — `reports/index.json` только посев.

### Блоки

| Блок | Что даёт | Поля |
|---|---|---|
| `head` | шапка документа: вид, происхождение, объём работы, метод | `title`, `sub`, `meta[[подпись, ссылка]]`, `ctx[ключи]`, `note` |
| `stamp` | угловой штамп письма (кому, тема, цель) | `rows[[подпись, ссылка]]` |
| `attrs` | таблица реквизитов; пустая графа остаётся со словом «не указано» | `title`, `rows` |
| `verdict` | решение документа: бейдж, значение, основание, условия | `src`, `badge`, `badge_label`, `why`, `meta` |
| `kpi` | показатели плашками | `title`, `rows` |
| `prose` | раздел связным текстом (абзацы сохраняются) | `title`, `src` |
| `list` | перечень | `title`, `src`, `field` |
| `cards` | пункты карточками с подписанными графами (форма аудита) | `src`, `head`, `badge`, `badge_label`, `code`, `group`, `graphs[[подпись, графа]]`, `filter[графа, значение]` |
| `register` | реестр: объявленные колонки в объявленном порядке | `src`, `cols[[подпись, графа]]`, `note` |
| `pre` | исходник как есть (код схемы, фрагмент OpenAPI) | `title`, `src` |
| `sign` | подписи: кто подготовил, кто проверил, кто утверждает | `rows[подписи]` |
| `note` | оговорка: чего документ НЕ заменяет | `text` |
| `ctx` | готовая врезка из контекста отчёта (`charts`, `skills`) | `key` |

### Ссылки на поля

Значения берутся из структурированных ответов навыков прогона (`result.skill_outputs[].structured`) —
из того, что объявлено в `json_schema` шаблона навыка. Выдумать значение бланк не может.

* `заявка.запрошенная_сумма` — путь в структуре; берётся у первого навыка, который поле заполнил;
* `limit_policy_enforcement:вердикт` — только у названного навыка;
* `критичность|ценность|срочность` — альтернативы: одна графа документа у разных навыков группы
  названа по-своему;
* в `cols`/`graphs`/`head`/`badge`/`code` указывается **графа элемента** массива, а не путь в корне.

`badge_label` подписывает бейдж там, где значение само себя не объясняет: «успеваем: нет» вместо
одинокого «НЕТ», которое читается как отказ.

Пустой блок не рендерится: заголовок над пустотой читается как «данных нет», хотя их и не ждали.
Колонка реестра, пустая во всех строках, тоже убирается — у работавшего навыка такой графы нет.
Если ни один раздел с данными не заполнился (форму поставили прогону чужих навыков), документ
собирается общим видом — лист с одними подписями не выдаётся.

`tests/test_report_blanks.py` сверяет каждую ссылку раскладки с `json_schema` навыков формы: графа,
указывающая в несуществующее поле, навсегда осталась бы пустой.

## Оформление: токены, а не литералы (06.10.2026)

`base.css` переписан на токенах. Три правила, вынесенные в `tests/test_report_css_tokens.py`, —
нарушить их незаметно нельзя:

1. **Цвет, кегль, отступ — только через токен из `:root`.** Литерал в правиле означает, что через
   месяц рядом появится второй такой же, но на оттенок другой: так и накопились 35 цветов на 60
   строк и две несовместимые палитры в одном документе.
2. **Один смысл — один токен.** «Критично» в карточке находки, «отказ» в блоке решения, класс A в
   бейдже и столбец A на графике — это `--bad`, а не три разных красных.
3. **Селектор объявляется один раз.** До переписывания `body`, `.tbl`, `.kv`, `.sev` были объявлены
   по два-три раза, и побеждало правило, стоящее ниже в файле, а не замысел.

Шкала кеглей — шесть ступеней (`--t-cap` … `--t-2xl`), отступы — один ряд (`--s-1` … `--s-6`).
Прямые углы: это документ, который подшивают и подписывают, а не карточка приложения.

### Печать

Гарнитура выбирается **из тех, что есть в рендерере PDF**: Noto Sans, Liberation Sans/Serif,
DejaVu Sans/Mono. `Segoe UI` в PDF не существует — он подменялся на Liberation Sans, из-за чего
веб-превью и файл на руках выглядели по-разному.

Поля листа и колонтитул задаёт **не CSS, а рендерер** (`cli/ape.py`: `_PDF_FIELDS`, `_PDF_FOOTER`):
`@page` при печати через CDP не применяется, а номера страниц в Chromium средствами CSS недостижимы.
`printBackground` включён явно — без него заливки шапок таблиц и бейджи существенности не печатаются
вовсе, и белый текст бейджа оказывается на белом листе.

### Как смотреть результат

```bash
python ops/render_report_samples.py --png            # все формы: HTML + картинки
python ops/render_report_samples.py --only credit,audit1c,letter
```

Образцы собираются по `json_schema` навыков формы — данные стенда не нужны. Складываются в
`build/report_samples/`.

### Раскладка редактора проверяется на разрешимость

Раскладку, присланную навыком `report-editor`, мало проверить формально (блоки известные, ссылки
пришпилены, навыки в прогоне есть): пути могут быть выдуманы целиком. Такая раскладка рисует пустые
блоки, бланк считает себя незаполненным, и документ сваливается в запасной путь. Поэтому
`report_compose.unresolved()` проверяет, что ссылки находят поля — и у свежей раскладки, и у взятой
из кэша (кэш хранится по набору навыков, а поля от прогона к прогону разные). Запасной путь
сохраняет рамку документа: шапку, оговорку и подписи.
